# 一.简介

- git是免费开源的<mark style="background: #FF5582A6;">分布式版本控制系统</mark>，处理项目代码，管理代码

## 1.1简单概念

---

- 版本控制：记录文件变化，以便将来查阅特定版本修订情况的系统——<mark style="background: #FF5582A6;">记录版本，回调代码</mark>
![[图片/Pasted image 20260623235711.png]]

- 版本：
	- 软件版本
	- 文件版本：
		- <mark style="background: #BBFABBA6;">对文件命名方式区分不同版本,保存历史版本，保存重要的数据</mark>
			- 示例：
				- 初始版本：`test_v_1`
				- 第二版：`test_v_2`

- 基本功能：
	- 保存管理文件：:主动生成版本号
	  ![[Excalidraw/Git/一.Git概述/1.1简介/一.简介/1.1简单概念/文件管理|文件管理]]
	- <mark style="background: #FFB86CA6;">通过客户端命令操作文件管理</mark>
	- 提供不同版本文件的比对功能

## 1.2集中式 vs 分布式

- 集中式：有一个集中式的服务器，多个程序员从服务器下载代码（最新版），一个人想修改必须登上一个人提交修改，版本统一，权限分配
- 分布式：每个人在自己本地写代码，写出一个版本就推送到集中服务器，自己本地也可以版本控制，自己本地也建立一个仓库

- git默认将所有资源都拉取到本地仓库中，会对资源进行压缩处理
- git是分布式文件管理

## 1.3工作机制

---

![[图片/Pasted image 20260624000752.png]]

- 工作区：磁盘，写到代码存放的位置
- 暂存区：让git知道内容——》将工作区的代码提交到暂存区中
- 本地库：上传到本地库中，一个版本依赖上一个版本，不能只删一个版本，只能删除整个本地库

- 本地库：对一个文件夹进行管理就建一个`.git`

- 版本只能整个版本删除，即使删除也可以删除

- 历史版本可以从本地送到远程库

- 托管中心：
	- 局域网：Gitlab
	- 互联网：Github，Gitee码云（国内）

## 2.8日志读取

---

### 一、git log（提交历史）

**一行的结构**：

```
commit 编号 (HEAD -> 分支)  →  Author: 谁写的  →  Date: 什么时间  →  提交说明
```

**怎么读**：

- **从上到下 = 从新到旧**
- 编号 = 提交身份证，`HEAD -> master` = 当前位置在 master 分支
- 想简洁就用：`git log --oneline`（一行一条，只显示编号+位置+说明）

### 二、git reflog（操作记录）

**一行的结构**：

```
提交编号  HEAD@{n}:  操作类型: 细节
```

**怎么读**：

- **从上到下 = 从新到旧**
- `HEAD@{0}` = 现在，`HEAD@{1}` = 上一步之前，数字越大越旧
- 冒号前是干了什么（commit / checkout / reset / merge...），冒号后是细节

### 三、两个命令对比

|git log|git reflog|
|---|---|---|
|本质|分支上的提交记录|你所有的操作流水|
|会显示丢失的提交吗|❌|✅|
|能否跨分支看|✅ 能|❌ 只看本地当前仓库|
|保留时间|永久|约 90 天自动清理|
|主要用途|看历史、查提交|找回误删/误回退的提交|

### 四、一句话记住

> **log 看"现在有哪些提交"，reflog 看"我做过什么"；前者翻历史，后者救失误。**

救失误的固定套路：

```
git reflog                    # 找到目标编号（如 a1b2c3d）
git reset --hard a1b2c3d      # 恢复过去
```

## 2.10分支

---

- 用户和开发者需要在不同环境操作——》不同分支

- 从主分支从引出一个副本，修改提交合并为新版本
  ![[图片/Pasted image 20260902101541.png]]

- 使用分支可以并行开发，可以提高安全性

- `git branch 分支名`:创建分支
	- 重点：
		- 以主分支为基础，刚创建时指向主分支指向的快照
		  ![[Excalidraw/Git/二.Git/2.10分支/分支创建|分支创建]]
- `git branch -v`:查看分支
- `git checkout 分支名`:切换分支
- `git mege 分支名`:把指定的分支合并大当前分支上
	- 一般只有一个分支更改时，无冲突，
	- 若有冲突，则需要手动将冲突部分更正，然后按照一个文件的形式上传
	- 合并到当前分支上，一般以主分支为当前分支合并

合并冲突问题：
```
冲突
 ├─ 原文件被插入冲突标记（只是工作区临时状态，没提交）
 ├─ 你手动编辑，删标记、定最终内容
 ├─ git add   ← 标记"解决好了"
 └─ git commit ← 生成干净的合并提交 M
```

标志合并流程：
```
git status          # 1. 看暂存区/工作区有没有未提交的改动
git stash           # 2. 如果有无关改动，先暂存起来（收进抽屉）
git merge dev       # 3. 干净状态下开始合并
# ...解决冲突...
git add hello
git commit          # 4. 完成合并
git stash pop       # 5. 合并完，把抽屉里的改动放回来
```

注：
1. 合并问题的处理过程处于特殊的状态/<mark style="background: #BBFABBA6;">临时将冲突文件放在工作区等待修改</mark>，修改后上传提交，<mark style="background: #FF5582A6;">临时的冲突文件不计入版本中</mark>
2. 合并时会将暂存区的所有文件都上传，直接`git commit`，这是强制的

# 三.Github

## 3.1创建别名

---

- github一个网页——》一个仓库
	- 网页很长——》在git中设置一个别名对应，一般以仓库命名

- `git remote -v`:展示所有别名
- `git remote add 别名 网址`:添加别名

## 3.2推送和拉取

---

- `git push 别名 版本`
	- 推送当前分支指向的版本以及历史，<mark style="background: #FFB86CA6;">对比历史，没有的都推送过去</mark>
	- 将github的指针更新到当前分支指向的版本

## 3.4拉取

---

- `git pull 别名/网址 分支`：更新合并，
	- 前提：已经将本地仓库初始化了，或者将仓库复制下来了/`clone`
	- 本质：就是一个合并，与合并的机制相同
		- `git fetch`:将分支所有新的更新拉取到本地仓库
		- `git merge 分支`

- 合并本质:
  ![[Excalidraw/Git/三.团队合作/3.4拉取/拉取本质|拉取本质]]
	- <mark style="background: #FF5582A6;">对于主分支合并后，分支情况还是分支维护，历史还是各自的历史</mark>

注：
1. 若是拉取一个分支只修改对应的一个分支

## 3.5克隆远程仓库

---

- `git clone 网址/别名`:将远程仓库克隆到当前文件夹下
	- 没有前提：
		- 拉取代码
		- 初始化本地仓库
		- 创建别名，原来仓库有的都拿来默认为`org`

## 3.6团队内协作

---

- 先`git clone`下载远程仓库，然后修改文件
- `git push`推送到远程仓库
	- 重点：
		- `git clone/pull`相对宽松，但是`git push`要在远程仓库中管理员将你的账号添加到团队中，才可以提交代码
		- 审核机制：
			- 无审核：直接合并
			- 审核：管理员审核，手动合并

## 3.7跨团队协作

---

- 将团队的远程仓库发送给另一个团队，在网页仓库点击`fork`

- fork是直接复制到自己的仓库中建立一个一样的仓库，可以拉取到本地仓库修改
- 修改以后可以在对应的远程仓库点击`pull request`发送给另一个团队
