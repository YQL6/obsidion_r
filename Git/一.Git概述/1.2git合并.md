# Git 合并 · 简略总结

## 一句话本质

> 分支 = 指针；合并 = 把两条分支历史接起来，两边改动**都保留**，生成新的完整版本。

## 两种形态

|情况|方式|结果|
|---|---|---|
|主分支没动、分支直线延伸|**快进**|指针直接跳，无新提交|
|两边都动了（分叉）|**三方合并**|生成合并提交 D（两个父提交）|

## 三方合并机制

```
找共同祖先 A → 算 A→你 和 A→对方 两份改动 → 叠加成 D
```

- 不是两个最新文件直接比，**祖先当裁判**
- 不是"去掉不同的"——**两边改动都收进 D**
- 只有两边改同一处且不同 → **冲突**，手动改 → `git add` → `git commit`

## 合并结果在哪

- 落在**执行合并时所在的分支**（通常是 main），不新开分支
- 被合并的分支还在，可 `git branch -d` 删掉（内容不丢）

## 和 pull 的关系

```
git pull = git fetch + git merge 远程分支   ← 机制完全一样
```
