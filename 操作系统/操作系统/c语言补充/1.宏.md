## 一、宏的本质：编译前的文本替换

宏由预处理指令 `#define` 定义，**在编译器真正翻译代码之前**，预处理器先把宏"原样替换"成文本。所以宏没有类型、没有作用域、不占内存、没有调用开销——它就是个"找字替换"的编辑器操作。

```
#define MAX 100
int a[MAX];        // 预处理后变成 int a[100];
```

## 二、两类宏

**对象宏（Object-like）**：简单的常量替身

```
#define PI 3.14159
#define NAME "hello"
```

**函数宏（Function-like）**：长得像函数的文本模板

```
#define SQUARE(x) ((x) * (x))
#define MAX(a,b)  ((a) > (b) ? (a) : (b))
```

## 三、函数宏的三大铁律（坑全在这）

**铁律1：参数和整体都要加括号**

```
#define SQUARE(x) x*x          // 错！
SQUARE(1+2)  →  1+2*1+2  = 5   // 不是9！

#define SQUARE(x) ((x)*(x))    // 对！
SQUARE(1+2)  →  ((1+2)*(1+2)) = 9
```

宏是文本替换，**参数会原样塞进表达式**，不加括号运算优先级就乱套。

**铁律2：小心"多次求值"**

```
#define MAX(a,b) ((a)>(b)?(a):(b))
MAX(++x, y)   →  ((++x)>(y)?(++x):(y))
```

看到没——`++x` 被**替换进去了两次**，x被自增了两次！函数不会有这问题（参数先求值一次）。所以宏里**别传带副作用的表达式**。

**铁律3：多语句宏用 do-while 包起来**

```
#define SWAP(a,b) { t=a; a=b; b=t; }   // 有隐患
if (x) SWAP(a,b); else ...             // 分号问题爆炸

#define SWAP(a,b) do { t=a; a=b; b=t; } while(0)   // 标准写法
```

`do { } while(0)` 让宏看起来像一条语句，if-else 不会错乱——这是内核和正规库的统一写法。

## 四、进阶武器：# 和

**`#` 字符串化**：把参数变成字符串

```
#define STR(x) #x
STR(hello)   →  "hello"
```

**`##` 粘贴**：把两个标识符拼成一个

```
#define MAKE(name) var_##name
MAKE(x)      →  var_x
```

这两个在写调试宏、生成器、内核代码里很常用。

**可变参数宏**：C99起

```
#define LOG(fmt, ...) printf("[LOG] " fmt, __VA_ARGS__)
LOG("x=%d", x);
```

**预定义宏**（调试神器）：

```
printf("%s %d", __FILE__, __LINE__);   // 当前文件和行号
printf("%s", __func__);                // 当前函数名
```

## 五、宏和函数、常量怎么选

|方案|类型检查|调用开销|多次求值|适用|
|---|---|---|---|---|
|`#define` 宏|无|无|有风险|必须用宏的场景|
|`const` / `enum`|有|—|无|**常量首选**|
|静态/内联函数|有|无|无|**小函数首选**|

现代C语言的最佳实践：

```
// 常量：用枚举/const，不用宏
enum { MAX_SIZE = 100 };
const double PI = 3.14159;

// 小函数：用 static inline，不用宏
static inline int square(int x) { return x * x; }
```

**宏现在只剩下三类"必须用"的场景**：

1. **要 `__FILE__`/`__LINE__`**（调试宏）；
2. **可变参数**、条件编译（`#ifdef`）、头文件保护（`#pragma once` / `#ifndef`）；
3. **内核式泛型技巧**——比如 Linux 的 `container_of`、`offsetof`、`list_head`，非宏不可。
