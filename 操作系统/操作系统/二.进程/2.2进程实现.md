# 一.操作系统Linux编程

## 1.1进程创建

---

- 创建进程
	- 专门的系统调用创建
		- 谁能创建：系统调用
		- 用户空间想创建一个进程，填写进程信息，交给内核实现

- `fork()`:
	- 克隆父进程，生成子进程
		- 子进程应在父进程上运行
- `execl()`:
	- 替换进程的资源
- `exit()`:
	- 进程退出
	- 函数中的`return 0`和`exit()`效果一样
- `wait()`:
	- 等当前进程任意一个子进程退出
	- 唤醒条件：子进程退出/执行完毕
	- `#include<sys/wait.h>`
	- 父进程有的就是等待子进程完毕进行存在，例如：回收子进程

注：
1. fork是将用户空间完全复制，内核空间公共部分和pid等信息不复制，其他的例如：文件描述符和内存映射表一样复制
2. `execl`:替换和重建复制的进程的相同部分

```c
#include<stdio.h>
#include<unistd.h>

int abc = 100;

void show(){
    printf("========%d=======\n",abc);
}
int main(){
    printf("my pid is %d\n", getpid());

   int pid = fork();
   if(pid < 0){
    printf("error");
   }else if(pid == 0){
    printf("my pid is %d",getpid());
    abc = 2000;
    show();
   }else{
    sleep(1);
    show();
   }
    return 0;
}
```

| 类别                         | 内容                        | 是否共享             |
| -------------------------- | ------------------------- | ---------------- |
| 中断/异常向量表（IDT/向量表）          | 处理中断、异常、系统调用的入口           | ✅ 全局共享           |
| 内核代码（公共操作）                 | 系统调用实现、调度器、内存管理、文件系统、驱动   | ✅ 全局共享           |
| 内核全局数据                     | 进程链表、锁、全局计数器、调度统计         | ✅ 全局共享           |
| 内核堆                        | `kmalloc` 分配的内存（内核自己动态申请） | ✅ 全局共享           |
| 页缓存/缓冲区                    | 文件读写的缓存页                  | ✅ 全局共享（映射内容共享）   |
| 设备映射                       | 硬件寄存器/MMIO 的内核映射（ioremap） | ✅ 全局共享           |
| **进程控制块 PCB（task_struct）** | 进程的档案：PID、状态、优先级、父子关系     | ❌ 每进程独属          |
| **内核栈**                    | 进程进内核态执行系统调用时用的栈          | ❌ 每进程独属          |
| **页表**                     | 进程的内存映射关系                 | ❌ 每进程一份（内容含共享映射） |
| **mm_struct 等**            | 地址空间描述、内存统计               | ❌ 每进程独属          |

## 1.3替换进程

---

- `execl`:替换
	- 另一个程序，<mark style="background: #FFB8EBA6;">重构复制进程</mark>的`0~3G`进程

- `int excel(char* pathname, char* arcg, NULL)`
	- 将执行程序替换到复制进程中
	- 返回值：
		- 成功：不返回
		- 失败：返回-1
	- 参数：
		- 第一个参数：执行文件位置，可以是自己写的程序的，可以是系统的，`.exe`文件
		- 第二个参数：传入mian函数的`arg[]数组`——》很多都是利用这个进行实现命令
		- 第三个参数:arg数组
		- 最后一个参数:NULL
	- 作用：覆盖后面的执行文件的代码或资源
```c
#include<stdio.h>
#include<unistd.h>

int abc = 100;

void show(){
    printf("========%d=======\n",abc);
}
int main(){
    printf("my pid is %d\n", getpid());

   int pid = fork();
   if(pid < 0){
    printf("error");
   }else if(pid == 0){
    printf("my pid is %d\n",getpid());
       int result = execl("/bin/ls","ls","-l","./",NULL);
    abc = 2000;
    show();
   }else{
    sleep(1);
    show();
   }
    return 0;
}
```

- 父进程创建子进程
	- 子进程先退出/mian函数返回：
		- 子进程在`/proc`中仍然存在对一个进程号的文件，里面还有信息——》`pcb块`,但是里面的指针都没有指向对象了，上下文资源没有了
		- <mark style="background: #FFB8EBA6;">只剩下一个空壳了，不会随便销毁，由父进程来进行销毁</mark>

注：
1. 命令其实也是一个进程执行

# 二.核心概念

## 2.1切换进程

---

- 进程都是由`PCB块`管理的 
- 进程最终运行，必须让cpu通过`PCB块`，找到`PC指针`

- 操作系统是一个软件，维护了`PCB块`的集合/容器
	- 调度<mark style="background: #FF5582A6;">合适的</mark>进程，调用里面的`pc`
- os管理策略：
	- 进程要能得到cpu(可以运行）
	- 进程也要放弃cpu
		- 主动放弃：不是资源不够，而是某种特殊情况
			- 操作系统的类型：
				- 批处理：
					- 无法交互，按代码一条一条执行
					- 进入睡眠
					- 一般被动放弃，主动一般是抢占式
				- 分时：
					- 时间片到了
				- 实时：
					- 抢占式，优先级更高的来了，让给优先级高的
		- 被动放弃：资源补全,放弃cpu，等待一个唤醒的存在，获取资源，在返回操作
			- `I/O`:
				- `scanf()`:等待输入
				- `getchar()`:等待输入
