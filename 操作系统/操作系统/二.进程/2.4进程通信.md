- 使用全局变量实现通信,在数据段中

```c
#include<stdio.h>
#include<pthread.h>

int shared_data = 0;

void task01(){
    for(int i = 0 ; i <1000 ; i++){
        shared_data += 1;
    }
    //线程正常退出
    pthread_exit(NULL);
}

void task02(){
    printf("shared_data:%d\n",shared_data);
    pthread_exit(NULL);
}

int main(){
    pthread_t thread1,thread2;

    pthread_create(&thread1,NULL,(void*)task01,NULL);
    pthread_create(&thread2,NULL,(void*)task02,NULL);

    //等待线程结束，避免主线程提前结束
    pthread_join(thread1,NULL);
    printf("task1 exit\n");
    pthread_join(thread2,NULL);
    printf("task2 exit\n");
    return 0;

}
```

- 无名管道：
	- 实际情况：
	  ![[Excalidraw/操作系统/操作系统/二.进程/2.4进程通信/二.通信机制/2.4进程通信/无名管道具体情况|无名管道具体情况]]
	- linux的无名管道:
		- 执行流程
			1. **shell 调用 `pipe()`**  创建管道，得到读端 `fd[0]` 和写端 `fd[1]`。此时这两个文件描述符由 shell 进程持有。
			2. **shell fork 出第一个子进程**（称为 `child1`），用于执行左边的命令 `ls -l`
			3. 在 `child1` 中：
		        - 关闭读端 `fd[0]`（因为 `ls` 只写不读）；
		        - 将写端 `fd[1]` 通过 `dup2(fd[1], STDOUT_FILENO)` 复制到标准输出（文件描述符 1）；
                - 关闭原来的 `fd[1]`（因为已经复制到 stdout 了）；
	            - 执行 `exec("ls", "-l")`，用 `ls` 程序替换子进程的代码。
			4. **shell fork 出第二个子进程**（称为 `child2`），用于执行右边的命令 `grep "^d"`
			    - 在 `child2` 中：
		        - 关闭写端 `fd[1]`（因为 `grep` 只读不写）；
		        - 将读端 `fd[0]` 通过 `dup2(fd[0], STDIN_FILENO)` 复制到标准输入（文件描述符 0）；
		        - 关闭原来的 `fd[0]`；
		        - 执行 `exec("grep", "^d")`。
			5. **shell 关闭自己持有的两个管道端**   shell 不再需要 `fd[0]` 和 `fd[1]`，所以关闭它们，避免资源泄漏。
			6. **shell 等待两个子进程结束**  调用 `wait()` 或类似函数，直到 `child1` 和 `child2` 都退出。
		- `ll | grep 555`
	- 代码示例：通过父子进程实现
```c
#include<stdio.h>
#include<stlib.h>
#include<unistd.h>

int main(){
	int fd[2];//保存返回的文件描述符
	pipe(fd); //创建管道
	
	pid_t pid = fork(); //创建进程，同时大部分都是直接复制，管道的描述符都有
	
	if(pid == 0){ //子进程
		close(fd[0]); //关闭读端
		const char *message = "hello,word";
		write(fd[1],message,sizeof(message));
		exit(0);
	}else{//父进程
		close(fd[1]);//关闭写端
		char buffer[200];
		read(fd[0],buffer,sizeof(buffer));
		printf("Receivd message: %s\n",buffer);
		close(fd[0]);
	}
	return 0;
}
```

# 三.临界区和同步机制

## 3.1临界区

---

- 临界区：
	- 访问临界资源的那部分代码
	- 临界区资源位置：
		- 代码段
- 临界资源：
	- <mark style="background: #FF5582A6;">同一时刻</mark>，只能由一个进程使用的资源，<mark style="background: #FFB86CA6;">需要互斥</mark>
	- 多线程的临界资源位置：
		- 代码段：往往只读，一般不是临界资源，代码是否可以同时访问，看设计，操作系统的代码就可以同时访问
		- 数据段：
			- 全局变量
			- 静态变量
		- 堆段
		- 内核提供的空间
	- 多进程的临界资源位置：
		- 内核提供的内存资源

## 3.2同步，互斥机制

---

- 任务是随机的，多个任务访问一个资源时，可能拿到的资源不同步
	- `i++`别多个进程执行，对同一个资源执行
		- `LDR/STR`机制：将内存数据加载到寄存器中，然后写回内存中——》一个时间片可能执行不完
		- 一个执行时还未写回，另一个又读取，相当于就加了一次

- 同步：
	- 数据顺序，先后关系明确，随机性下怎么保证一定进程间的访问顺序
- 互斥：
	- 一旦资源被某个进程占用，其他进程就不该访问这个资源，进入等待
- 问题：
	- 数据竞争和不一致性——》互斥
	- 数据处理的顺序性——》同步
		- 生产者
		- 消费者
	- 死锁问题

## 3.3互斥实现

---

- 互斥要求：
	- 互斥条件：
		- 任何时候对同一资源访问，<mark style="background: #FF5582A6;">不可以同时多进程进入临界区内</mark>
	- 前进条件：
		- <mark style="background: #FFB86CA6;">不应该由开发者考虑多核状态</mark>，系统能在任何cpu配置下都能正常工作
	- 有限等待条件：
		- 临界区外的进程<mark style="background: #FFB8EBA6;">不应该无限期地等待/阻塞进入临界区</mark>，必有一种机制使其一定时间内进入cpu——》饥饿
	- 无忙等条件：
		- 临界区外的进程等待时，不应占用cpu进行无意义的循环检查
		- 刚开始设计时，其实设计的就是忙等，<mark style="background: #FFF3A3A6;">一般忙等效率反而更高</mark>
	- 避免死锁

- 多核的互斥触发：
  ![[Excalidraw/操作系统/操作系统/二.进程/2.4进程通信/三.临界区核同步机制/3.3互斥实现/互斥触发|互斥触发]]
	- 阻塞：
		- 历史上的阻塞：等待，一直执行查询资源是否可用，可用直接进入
		- 理论上阻塞：放弃cpu
		- 现在阻塞机制：<mark style="background: #FFF3A3A6;">放弃cpu，进入睡眠，等待A进程唤醒B进程——》A告知B资源已经释放</mark>
	- 冲突：
		- 资源被占用，后进入的阻塞
		- 占用资源释放后，告知阻塞态的其他进程

- 怎么保证互斥：
	- 严格轮询法：一直`while`等待
		- 本质：用一个共享变量 `turn` 强制"你一次、我一次"轮流进入临界区
		- 未获得临界资源的进程一直`while`等待
		- 类似代码：
			- 进程0代码：当为0状态会进入临界区
			- 进程1代码：当为1状态会进入临界区
			  ![[图片/Pasted image 20260830204118.png]]
	- 忙等互斥：
		- 屏蔽中断：
			- <mark style="background: #ABF7F7A6;">最差的方案</mark>
				- 系统稳定性风险：可能导致死机，一直被一个任务占用，其他任务无法使用
				- 多处理器系统的无效的风险：多处理器中有多个cpu，可能有两个cpu同时处理一个临界资源，无法确认是否被占用
			- <mark style="background: #FF5582A6;">依靠硬件的中断</mark>——》时间片等触发或者主动释放cpu(靠着自己的良心是否让给别人)
			- <mark style="background: #ABF7F7A6;"> 理论上可以通过屏蔽所有中断来独占cpu</mark>
		- 锁变量：
			- <mark style="background: #FFB8EBA6;">现代较优的方案</mark>
			- 两个状态：
				- 被锁住状态:`lock = 1`
				- 未被锁住状态:`lock = 0`
			- 机制：<mark style="background: #FF5582A6;">本质是一个全局变量</mark>
			  ![[Excalidraw/操作系统/操作系统/二.进程/2.4进程通信/三.临界区核同步机制/3.3互斥实现/锁变量|锁变量]]
				- 检查锁的状态，未被锁住状态——》进入临界区，执行代码
				- 检查锁的状态，被锁住的状态——》进入阻塞队列，等待唤醒
			- 实现：
				- 软件：一个数据结构
				- 硬件
			- 互斥问题：
				- <mark style="background: #FF5582A6;">进入临界区时判断锁信息，然后要更新锁信息，判断和更新期间其他进程进入临界区</mark>
				- 锁变量可能会因为判断和更改锁变量时被钻空子，可以通过硬件和软件一起配合弥补，是依靠原子性实现
			- 硬件和软件互相配合解决危险空隙：
				- 设置原子性操作：`读-写`设置为原子操作
					- <mark style="background: #FFB86CA6;">执行中间不会被读到：</mark>
						- 设置独占缓存行
						- 进行操作
						- 释放缓存行
					- <mark style="background: #FF5582A6;">不会被打断</mark>
				- 硬件上提供原子性操作：
					- c语言完全做不到，只能由汇编做
					- 测试并设置，`TSL指令`
			- 类似命令：
			  ```c
while(flag != 0); //flag!=0,就一直等待锁的释放
flag = 1; //占用操作，设置为1
```

- `peterson解法`:
	- 仅支持两个进程的执行，纯软件层次的实现
	- 优点：
		- 实现了互斥操作：进一个全局变量，只有一个进程可以进入
		- 避免饥饿：一个谦让到另一个，对方执行完后，立即又想执行，重来一遍过程，又谦让回来
		- 避免了`CPU空闲`
	- 唯一缺点：
		- <mark style="background: #FFB86CA6;">没有完成让权等待</mark>，一直忙等
```c
#define FALSE 0      // 不想执行
#define TRUE 1       // 想进入执行
#define N 2          // 假设系统有两个进程

int turn;                 // 记录轮到哪个进程
int interested[N];        // 记录哪个进程有执行意愿

// 进入区
void enter_region(int process) {     // process 为 0 或 1
    int other = 1 - process;         // 另一个进程
    interested[process] = TRUE;      // 标记本进程想进入临界区
    turn = other;                    // 谦让：让对方优先
    while (turn == other && interested[other] == TRUE);
                                     // 对方想进且轮到对方 → 等待
}

// 退出区（必须有！）
void leave_region(int process) {
	//标记本进程已经离开临界区
    interested[process] = FALSE;     // 声明自己已退出
}

// 使用方式
// enter_region(0);
//   临界区代码……
// leave_region(0);
```


- 原语：一组不可分割的操作
	- 原子性：
		- 不同操作系统实现方法不一样
		- <mark style="background: #BBFABBA6;">一个操作执行中，要么完全不执行，要么全部完成，不会停留在某个状态</mark>
		- 特点：
			- 不可分割性：原子操作在执行过程中不会被中断或分割成多个部分执行，一旦执行，必须完成
			- 一致性保证：同步，互斥
			- 可见性
	- 实现原子机制：
		- 硬件：
			- 关中断：正是因为中断，就是由中断引起，关掉后什么都没有了，可能导致独占
				- 实现互斥访问
				- 原子操作，捆绑在一起多个操作
			- 硬件指令：通过硬件设计，得到实现原子命令
				- `TSL指令`:测试和设置
				- `swap指令`:交换指令，将两个值交换，读写封装一个原子操作，同时返回旧值留给判断原来值是是什么，0则空闲，进入

## 4.1同步机制设计

---

- 多任务:
	- 临界资源，划分临界区

	- 同步机制：

		- 忙则等待：临界区有进程访问，其他进程要在外面等待
		- 有限等待：一个进程必须要保证其有限时间内，至少要有机会访问cpu
		- 让权等待：一个进程无法进入临界区，应该让出cpu，不忙等
			- 实现条件：
				- 没成功应该等待——》队列
				- 还有一种是一直问——》`while`，这是忙等

- 解决方案：
	- 软件机制：
		- 错误：
			- 单标记法：
				- 设计一个<mark style="background: #FF5582A6;">共享的整型变量</mark>，使进程0/1共享
					- 程序进入临界区的权限

				- 改进：

## 4.2信号量底层机制

---

- 信号量：
	- 本质：
		- 数据结构  ————  A/某个临界区 ，<mark style="background: #FF5582A6;">两者相对应，绑定</mark>
		- <mark style="background: #FFF3A3A6;">信号量的值就是可以使用资源的剩余数量</mark>
	- 信号量的值：
		- `<0`:此时有进程在等待，<mark style="background: #FFF3A3A6;">绝对值为等待的进程数(逻辑上是先减一再判断)</mark>
		- `=0`:此时资源正好分配完
		- `>0`:还有资源
	- 开放的接口
		- <mark style="background: #ADCCFFA6;">都是原子操作</mark>
		- `PV原语`:
			- `P原语`:消费资源，申请资源  资源不够就进入等待队列，等待唤醒
			- `V原语`:生产资源，释放资源  若有等待的资源唤醒任务
	- 信号量的类型：
		- 整型信号量：
			- `int S = 1 // 表示资源量`
		- 记录型信号量：
			- 一个结构体维护资源和队列，执行资源释放后从自己的队列唤醒任务
			- <mark style="background: #FFB86CA6;">资源数设置为1——》互斥锁</mark>

## 4.4生产者和消费者

	- 信号量2:
		- 使用`P(&sem2)`消耗资源
		- 消耗掉资源数量
		- `sem2 = 0`:已经有的资源

- 经典同步问题是生产者和消费者一个特殊的情况
	- 资源为1的情况——》<mark style="background: #FF5582A6;">因为资源为1，所以实现了互斥问题</mark>
	- 对应通用模型：
		- 生产者
		- 消费者

```c

semaphore empty = n;  //还可以生产n个资源
semaphore full = 0;   //还有0个资源可以使用

void producer(){
	while(true){
		生产一个产品;
		P(&empty);  //消耗空位
		P(mutex);
		将产品放入空闲区;
		V(mutex);
		V(full);  //资源增加
	}

		P(full);

		V(empty);
	}
}
```

## 4.5互斥量

---

- 互斥量——》互斥锁
	- 本质就是信号量，为了和同步区分，改名为互斥锁
	- 将信号量封装为一个互斥锁：
		- 接口:
			- `mutex_lock`
			- `mutex_unlock`
		- 资源一定为1:
			- 为了避免一直为释放锁，内部固定只有两个值——》1/0
	- 实现：
		- `TSL/XCHG原语`

| 指令                 | 作用                 |
| ------------------ | ------------------ |
| TSL (Test-and-Set) | 把内存值读出来,同时写 1,返回旧值 |
| XCHG               | 原子交换两个值(比如寄存器和内存)  |
| CMPXCHG            | 比较再交换,比 TSL 更灵活    |

- 若是没有资源——》进入睡眠队列——》资源耗费大
- 使用自旋锁
	- 进行忙等，等待另一个资源的释放，cpu占用率提高，但是效率提高
	- <mark style="background: #FFB86CA6;">应用空间无使用的接口，操作系统内核代码常用</mark>
	- 没有必须是多核的：
		- 单核：
			- 时间片调出另一个任务，执行释放资源
		- 多核：
			- 可能两个统一临界区的的代码执行，另一个执行完，释放资源

```c
//伪代码

//TSL指令的伪代码

// 自旋锁:锁变量为 0 表示空闲,1 表示被占用
volatile int lock = 0;

void acquire() {
    while (TSL(&lock, 1) == 1)   // 尝试把 lock 置 1,若旧值是 1 说明被占
        ;                        // 忙等(自旋)
}

void release() {
    lock = 0;                    // 置回空闲
}

//XCHG的伪代码

void acquire() {
    int tmp = 1;
    while (xchg(&lock, tmp) == 1)  // 原子交换:把 lock 换成 1,拿到旧值
        ;
}

void release() {
    lock = 0;
}
```

- 互斥锁和自旋锁的优点结合——》`快速用户空间互斥/futex`
	- 先试一下自旋锁，长时间无发获得资源，进入睡眠
	- `linux的底层锁`
		- 核心思想是:绝大多数情况下锁竞争根本不发生,那就不该进内核;只有真正发生竞争时,才通过系统调用让内核帮你"睡觉"和"叫人起床"。

- 过桥问题：同一个方向的行人课连续过桥，当某一个方向有人过桥时，另一个方向的行人必须等待；当某一个方向无人过桥时，另一个方向的行人可以过桥，使用信号量解决

semaphore mutex_B = 1;//方向B,可以同时同行的方向的人数统计互斥

//方向A
void direction_A(){
	while(1){
	/*
	*有限获得公平锁，避免产生死锁问题
	*若是先获得A锁，可能无法获得公平锁，而A方向无法下桥归还互斥锁
	*导致死锁
	*/
		p(mutex_F);
		p(mutex_A);
		if(number_A == 0){
			p(mutex);
		}
		number_A++;
		v(mutex_F);
		v(mutex_A);
		过桥;
		p(mutex_A);
		number_A--;
		if(number_A == 0){
			v(mutex);
		}
		v(mutex_A);
	}
}
