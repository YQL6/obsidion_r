# 一.操作系统

## 1.1操作系统的作用

---

- 操作系统：“管理软/硬件资源、为程序提供服务” 的程序
	- 广义上讲：
		- 控制一个整体，提供服务/**管理计算机所有硬件与软件资源，并为用户和应用程序提供一套高效、安全、便捷的服务与界面的完整软件系统**
	- 狭义上讲：
		- 由程序构成身体
		- 向上提供接口，向下对硬件进行管理
			- 对程序负责，优化程序，优化调度
			- 程序共同运行

- 操作系统：怎么了解操作系统
	- 计算机/硬件
	- 程序（软件）
	- 操作系统<mark style="background: #FF5582A6;">（管理软件的软件）</mark>

- 使用计算机完成一些工作：
	- 硬件准备：cpu，io设备，总线，内存等
	- 具体操作：cpu控制各设备间在总线上交互，然后由显示器输出结果

- 底层实现不好用（汇编）——》操作系统：计算机硬件与应用间的一层软件——》方便调用底层硬件，使用cpu，显示器等
	- <mark style="background: #FF5582A6;">管理硬件</mark>：<mark style="background: #FF5582A6;">cpu管理，内存管理，中端管理，磁盘管理，文件管理</mark>，网络管理，电源管理，多核管理，例如：`print("hello")`，怎么实现的由操作系统调用底层硬件

- 操作系统基础上再进行进一步开发——》应用软件，例如：word等

- 学习操作系统：
	- 操作系统接口层面：应用软件层面——》使用操作系统
		  ![[Excalidraw/重构/操作系统接口|操作系统接口]]
		  例如：编程语言，使用cpu：fork,使用文件:open,read。。。
	- 操作系统内部层面：应用软件层面——》改动操作系统
		  ![[Excalidraw/重构/操作系统内部|操作系统内部]]
		  例如：如何将文件的内容写到磁盘上面
	- 操作系统设计层面：硬件层面——》从硬件设计操作系统，提供接口
		  ![[Excalidraw/重构/操作系统底层|操作系统底层]]
		  例如：从板子开始配一个操作系统

- 启动扇区/bootsect.s代码：
```asm
!================ 第1步：段书签 + 入口声明 ================
.globl begtext, begdata, begbss, endtext, enddata, endbss
.text  begtext:        ! 代码段"开始书签"
.data  begdata:        ! 数据段"开始书签"（空的）
.bss   begbss:         ! 未初始化段"开始书签"（空的）
.text
entry start            ! 告诉链接器：程序入口是 start

!================ 第2步：自己搬家 0x7C00 → 0x90000 ================
start:
    mov ax,#BOOTSEG    ! 0x07c0（BIOS 放我们的地方） 这是引导区代码
    mov ds,ax          ! DS = 0x07c0  源地址
    mov ax,#INITSEG    ! 0x9000（我们要搬去的新家）
    mov es,ax          ! ES = 0x9000  目标地址
    mov cx,#256        ! 搬 256 个字 = 512 字节
    sub si,si          ! 源偏移 = 0
    sub di,di          ! 目标偏移 = 0
    rep movw           ! 重复搬运：0x07c0:0 → 0x9000:0
    jmpi go,INITSEG    ! 远跳转：CS=0x9000，继续执行新家的代码

!================ 第3步：读 setup 模块到 0x90200 ================
go:
    mov ax,cs
    mov ds,ax          ! DS 指向新位置（0x9000）
    mov ax,#SETUPSEG
    mov es,ax          ! ES = 0x9020
    call read_it       ! 调用读盘子程序（内部用 BIOS int 13h）
                       !   把磁盘第2~5扇区的 setup 读到 0x90200

!================ 第4步：屏幕打印 "Loading system ..." ================
    mov ah,#0x03       ! BIOS：先读当前光标位置
    xor bh,bh
    int 0x10
    mov cx,#24         ! 一共24个字符
    mov bp,#msg1       ! 指向字符串数据
    mov bx,#0x0007     ! 0x07 = 黑底白字（显示属性）
    mov ax,#0x1301     ! BIOS：写字符串
    int 0x10

!================ 第5步：读 system 内核主体到 0x10000 ================
    mov ax,#SYSSEG     ! SYSSEG = 0x1000 → 物理 0x10000
    call read_it       ! 调用读盘子程序读入整个内核

!================ 第6步：移交控制权 ================
    jmpi 0,SETUPSEG    ! 跳到 0x9020:0，执行 setup.s
```

- 最终读取的内容：
	- `0x7c000`——》`0x90000`：boot
	- `90200`:setup
	- `10000`:system，暂时存放在这里——》不能直接占用`0`地址，0处一般存放中断程序，读取操作系统和`setup`内容都需要自带中断程序

## 2.3setup

---

- setup:
	- 读取计算机的详细信息：后面操作系统会到这里来读取计算机信息
		- 内存大小：操作系统读取到这1mb（10位只能读到这里）中，由于历史兼容，操作系统设计再里面，后来电脑内存大了，操作系统要分配空间，要有依据
		- 光标位置
		- 显卡详细等
	- 
```asm
! ============ setup.s 全流程（一段代码看全） ============
! 入口：bootsect 读入 setup 后，jmpi 0,SETUPSEG 跳到这里（0x90200）

start:
    ! ---- 第1步：收集硬件参数，存进 0x90000 参数表（留给内核）----
    mov ax,#INITSEG
    mov ds,ax            ! DS = 0x9000，指向参数表

    mov ah,#0x03         ! 取光标位置
    xor bh,bh
    int 0x10
    mov [0],dx           ! → 0x90000

    mov ah,#0x88         ! 取扩展内存大小（KB）
    int 0x15
    mov [2],ax           ! → 0x90002

    ! （还有显卡参数 → 0x9000C、根设备号 → 0x901FC，同理）

    ! ---- 第2步：关中断，准备动系统核心结构 ----
    cli                  ! 切换 GDT/保护模式瞬间不能被中断打断

    ! ---- 第3步：把 system 从 0x10000 搬到物理地址 0 ----
    mov ax,#0x0000
    cld                  ! 方向标志清零：movs 向前搬
do_move:
    mov es,ax            ! 目标段
    add ax,#0x1000
    cmp ax,#0x9000
    jz end_move          ! 源段到 0x9000 就停（别碰参数表）
    mov ds,ax            ! 源段
    sub di,di
    sub si,si
    mov cx,#0x8000       ! 一次搬 0x8000 个字 = 64KB
    rep movsw            ! 从源搬到目标
    jmp do_move
end_move:

    ! ---- 第4步（后面的课）：开A20 → 装IDT/GDT → 置CR0 → 
    !      远跳进保护模式 → 在0地址执行head.s → 进C的main() ----
```

```asm
;进入保护模式
mov ax,#0x0001 
mov cr0,ax ;将cr0最低位置为1，进入保护模式，切换电路
jmpi 0,8 ;跳转电路后，寻址方式发生改变，跳转到0地址
;切换后寻址达到4GB——》32位
```
- 保护模式：进入到32位电路——》寻找更大的空间4GB

## 2.4保护模式

---

- 32位机，寻址地址为4GB

- 本质区别：换另一条电路——》解释模式不一样——》16位的是`cs<<4+ip`

- 切换方法：使用`cr`寄存器
	- ![[图片/Pasted image 20260811011451.png]]
		- `PE = 1`:保护模式
		- `PG = 1`:启动分页

- 保护模式：保护内存安全访问——》通过gdt表，规定一系列的内存划分和访问权限
	- `gdt`:通过硬件形式实现——》快
		- 作用：使用其保存扩展内存的段地址，保存在`0x90000~0x92000`之间，<mark style="background: #FF5582A6;">使用`setup`设置</mark>，操作系统读取使用
		- 释义：
			- `g`:`global`，全局
			- `d:descriptor`,描述
			- `t:table`，表
	- 查找方式：
		- `cs:ip`:`cs`——》选择子，做为在`gdt`寻找数据的下标与那张表
		- `cs`需要在gdt中寻找数据——》64b/8字节/4个字
		- `gdt表中数据——》段/基地址` ,将原`ip`拿出来，继续相加得到新地址
		- 
		  ![[图片/747ec0d67f125f3a43406e997e73c04b.jpg]]

- `lgdt gdt_48`：登记gdt表项
- `lidt idt_48`：登记idt表项——》函数向量表

# 三.计算机历史总览

## 3.1物理基础

---

               

- 1940年的计算机：机电计算机
	- 输入输出：打孔带/指示灯
	- 逻辑门：真空管
	- 存储器：使用延迟线——》不断将数据抛出，右从另一边返回，实现存储
	  ![[图片/Pasted image 20260808230121.png]]
	- 操作系统：无，直接使用指令操作

- 1950年的计算机：电子计算机
	- 逻辑门：晶体管/半导体
	- 存储：磁芯内存，类似DRAM
		- 二维磁性网格上，有磁针，磁针两个方向
		  ![[图片/Pasted image 20260809005432.png]]
	- 丰富的I/O设备
	- 可以执行更多的复杂任务，执行通用计算任务
		- 开始出现出现——》使用卡片对应位置打孔
	- 操作系统开始出现：DOM(DISk operating system)
		- 批量送入卡片（所有内存都归一个程序）——》送入多个程序——》管理——》操作系统
		  ![[图片/Pasted image 20260809010753.png]]
		- 操作系统出现：自动换卡（程序执行完，推出卡）+提供API
		- 提供API：程序可以通过操作系统的接口操控硬件——》输出结果
		- 开始出现文件，设备，任务等对象概念和接口

- 1960年的计算机：
	- 内存：扩大，可以同时保存多个程序——》cpu只有一个
		- 只能运行一个程序，可能有的操作无需cpu
		  ![[Excalidraw/操作系统/操作系统/一.操作系统的概述/1.1导入/1960操作系统|1960操作系统]]
			- 例如:`int 16h`中断读取键盘输入，无送入一直等待
		- 两个程序之间的可能相互影响，例如：指针混乱
			- 使用两个寄存器保存开始地址与程序长度，每一次都检测
		- 改进：<mark style="background: #FF5582A6;">操作系统无条件执行</mark>一段时间打断程序，<mark style="background: #FF5582A6;">交替执行程序</mark>
			- ![[Excalidraw/操作系统/操作系统/一.操作系统的概述/1.1导入/定时中断|定时中断]]
			- <mark style="background: #FF5582A6;">定时进行中断</mark>——》中断向量表指向的程序替换为操作系统的程序
	- 有了进程管理的概念，操作系统开始提供对应的API接口
	- 中断
	- I/O设备

- 1970年的计算机：
	- 与现今计算机无异，分时操作系统
