# 一程序的多文件组织

## 1.1程序组织

---

- 程序：一个程序由多个程序组成
	- 程序文件1：
		- 子程序1
		- ...
		- 子程序n
	- ...
	- 程序文件n:
		- 子程序1
		- ...
		- 子程序n

- 示例：
	- 主程序——》p1
		- 调用子程序出错
		- 改正：
			- 使用`extern subp:far`——》声明子程序为其他文件内的子程序
		- 编译：
			- `masm p1.asm`
			- `link p1+p2`
	- 子程序——》p2
		- 声明自己的标号可外部使用：
			- `public subp`

```asm
;主程序
extrn subp:far
assume cs:code,ss:stack
stack segment
	db 16 dup(0)
stack ends
code segment
main:
	mov ax,stack
	mov ss,ax
	mov sp,16
	mov ax,1000
	call far ptr subp  ;调用子程序
	mov ax,4c00h
	int 21h
code ends
end main

;子程序
public subp
assume cs:code
code segment
subp proc  ;子程序开始
	s:add ax,ax
	retf   ;子程序返回
subp endp  ;程序结束
code ends
end s
```

# 二.子程序另一种写法

## 2.1原写法

```asm
call s
...
s:
	add ax,ax
	ret
```

## 2.2新写法

---

- 类似一种括号的写法
	- `near/far`标签：告知编译器请检查我的返回方式是不是`retf`，若是同文件调用则进入函数方式错误自动改正
	- 效果与直接调用标号一样
	- 基础用法——》标号

```asm
名称 proc
;实现功能,与原写法一样
名称 end
```

```asm
assume cs:code
code segment
main proc    ;子程序开始  ，由于end决定，main子程序为程序开始
start:
	mov ax,10h
	call subp ;调用子程序
	mov ax,4c00h
	int 21h
main endp   ;子程序结束
subp proc [near/far]  ;子程序开始
s:
	add ax,ax
	ret
subp endp   ;子程序结束
code ends
end start  ;程序开始仍为end决定标号
```
