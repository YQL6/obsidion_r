# 一.顺序

## 1.1大致解析顺序

### 1. 解析 HTML，构建 DOM 树

- 浏览器从服务器接收 HTML 文档，开始**逐行解析**。
    
- 解析器识别 HTML 标签，生成**DOM（文档对象模型）树**。
    
- 解析过程中，遇到某些资源会触发**外部请求**，根据资源类型不同，会有不同的阻塞行为。
    

---

### 2. 遇到 CSS（`<link>` 或 `@import`）

- **不阻塞 DOM 解析**，但会**阻塞页面渲染**。
    
- 浏览器会并行下载 CSS 文件，但必须等所有 CSS 加载并解析成 **CSSOM 树** 后，才会进行绘制。
    
- 因为页面最终渲染需要完整的 CSSOM，所以 CSS 被称为**渲染阻塞资源**。
    
- 如果多个 CSS 文件，下载是并行的，但最终都要等最慢的那个。
    

---

### 3. 遇到 JavaScript（`<script>` 标签，不带 async/defer）

- **同步 JS 会阻塞 DOM 解析**。
    
- 当解析到 `<script>` 时，停止解析 HTML，下载并立即执行该脚本，执行完后再继续解析。
    
- 如果脚本在 `<head>` 中且没有 async/defer，会阻塞后续 DOM 的构建，可能导致页面白屏。
    
- JS 的执行会等待**前面的 CSS 加载完毕**（因为 JS 可能读取元素样式，如 `element.style`，所以需要 CSSOM 就绪）。
    

---

### 4. 带有 `async` 或 `defer` 的脚本

- **`async`**：
    
    - 异步下载，下载时**不阻塞 HTML 解析**。
        
    - 下载完成后**立即执行**（此时可能暂停 HTML 解析）。
        
    - 执行顺序无法保证，谁先下载完谁先执行。
        
    - 适用于独立脚本（如统计、广告）。
        
- **`defer`**：
    
    - 异步下载，下载时**不阻塞 HTML 解析**。
        
    - 必须等到**HTML 解析完全完成**后，才按在文档中的顺序执行。
        
    - 在 `DOMContentLoaded` 事件之前执行。
        
    - 适用于需要操作 DOM 且有依赖顺序的脚本。
        

---

### 5. 遇到图片、视频、字体等资源

- 这些资源**不阻塞 DOM 解析，也不阻塞渲染**。
    
- 浏览器会异步加载它们，加载完成后直接替换占位符（如 `<img>` 的 `src`）。
    
- 页面可以预先渲染出布局，图片加载后更新布局或触发重绘。
    

---

### 6. DOM 树和 CSSOM 树准备完毕后的渲染流程

1. **DOM 树**和**CSSOM 树**合并成**渲染树（Render Tree）**。
    
2. 根据渲染树进行**布局（Layout / Reflow）**，计算每个节点的位置和大小。
    
3. **绘制（Paint）**，将像素画到屏幕上。
    
4. 如果有动画或交互，还可能触发**重绘（Repaint）**或**重排（Reflow）**。
    

---

### 7. 关键事件

- **`DOMContentLoaded`**
    
    - 在**DOM 解析完成**，且**所有 `defer` 脚本执行完毕**后触发。
        
    - 此时图片、样式表等可能还未加载完成。
        
    - 适合做初始化交互（如绑定事件）。
        
- **`load`**
    
    - 在页面**所有资源**（包括图片、CSS、JS、iframe 等）全部加载完成后触发。
        
    - 适合获取图片尺寸等操作。
        

---

### 8. 总结优化策略

- **CSS 放 `<head>`**：尽早加载，避免无样式闪烁。
    
- **JS 放 `</body>` 前或使用 `defer`/`async`**：避免阻塞 DOM 解析。
    
- **关键 CSS 内联**：加速首屏渲染。
    
- **图片懒加载**：延迟加载视口外图片。
    
- **预加载、预连接**（`<link rel="preload">`, `preconnect`）提升资源加载速度。
    

理解这些顺序，可以帮助你写出高性能的页面，避免渲染阻塞和闪烁问题。
