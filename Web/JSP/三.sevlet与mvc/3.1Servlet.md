# Servlet接口：
```java
//Servlet对象的初始化，Servlet 对象初始化后才能处理请求，由 Servlet 容器调用 public 
void init(ServletConfig config) throws ServletException; 
//获取Servlet配置信息 
public ServletConfig getServletConfig(); 
//处理客户端的请求，由 Servlet 容器调用 
public void service(ServletRequest req, ServletResponse res)    throws ServletException, IOException; 
//返回有关 Servlet 的信息，比如作者、版本和版权 
public String getServletInfo(); 
//销毁Servlet，由 Servlet 容器调用 
public void destroy();
```
问题：
1. 容器——tmocat
2. <mark style="background: #FF5582A6;">第一次处理请求时，有tomcat创建，紧接着就开始初始化，处理问题</mark>
3. Config的获得实例名的方法是获得tomcat创建的类名，不是用户创建，配置中的名称仅用于其他功能映射类
4. <mark style="background: #FF5582A6;">每一个类的实例仅一个</mark>
5. servlet的配置有.xml来获得，由自己配置
6. 没有servlet处理问题，就会404


问题：
1. 获得实例名称，由tomcat创建的
2. 类由两个名称：
	1. 配置的映射名称，由于仅有类无对应实例，在配置阶段，我们为它起一个名称来作为映射名称使用
	2. tomcat容器为我们自动创建实例，我们不知道名称，可以通过getServletName获得
3. 配置servletcofig由容器创建，servlet获得对应的servletcofig

# Servlet模拟：
```java
package com.web.servlet;  
  
import javax.servlet.*;  
import java.io.IOException;  
import java.util.Enumeration;  
  
public class FirstServlet implements Servlet {  
    private ServletConfig config;  
    public FirstServlet(){  
        System.out.println("Servlet已创建");  
    }  
    @Override  
    public void destroy() {  
        System.out.println("Servlet已销毁");  
    }  
  
    @Override  
    public String getServletInfo() {  
        return "get Info";  
    }  
  
    @Override  
    public void service(ServletRequest servletRequest, ServletResponse servletResponse) throws ServletException, IOException {  
        System.out.println("Servlet已经处理问题了");  
    }  
  
    @Override  
    public ServletConfig getServletConfig() {  
        return config;  
    }  
  
    @Override  
    public void init(ServletConfig servletConfig) throws ServletException {  
        config = servletConfig;  
        Enumeration<String> en = servletConfig.getInitParameterNames();  
        while(en.hasMoreElements()){  
            String name = en.nextElement();  
            String value = servletConfig.getInitParameter(name);  
            System.out.println("初始化参数为：" + name+"="+value);  
        }  
        System.out.println("Servlet已经完成初始化");  
    }  
}
```

# web.xml:

```html
<?xml version="1.0" encoding="UTF-8"?>  
<web-app xmlns="http://xmlns.jcp.org/xml/ns/javaee"  
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"  
         xsi:schemaLocation="http://xmlns.jcp.org/xml/ns/javaee http://xmlns.jcp.org/xml/ns/javaee/web-app_4_0.xsd"  
         version="4.0">  
    <servlet>       
	     <servlet-name>firstServlet</servlet-name>  
		 <servlet-class>com.web.servlet.FirstServlet</servlet-class>  
	    <init-param>           
		         <param-name>Character</param-name>  
	            <param-value>UTF-8</param-value>  
        </init-param>       
        <init-param>            
	        <param-name>second</param-name>  
            <param-value>2</param-value>  
		</init-param>    
	</servlet>    
	<servlet-mapping>        
		 <servlet-name>firstServlet</servlet-name>  
		 <url-pattern>/test</url-pattern>  
    </servlet-mapping>
</web-app>
```
结构：
1. servlet:servlet的基础配置
	1. servlet-name:映射名称，代表具体类
	2. servlet-class:具体类，有映射名称对应
	3. init-parm:初始化的参数，可有多个
2. servelt-mapping：映射关系
	1. servlet-name:映射名称
	2. url-pattern:映射类的处理对象，什么样的url来到这个类让其处理
	3. url-pattern解释：当用户访问 `http://你的应用路径/test` 时，容器会自动调用 `FirstServlet` 这个 Java 类来处理请求，而不是去寻找一个名为 `test` 的静态页面。

## 请求——ServletRequest

接口：
```java
//从请求中获取给定属性名对应的属性值 
Object getAttribute(String attributeName); 
//将给定的属性值以给定的属性名存储在请求中 
void setAttribute(String attributeName, Object attributeVaue); 
//从请求中将给定的属性名移除 
void removeAttribute(String attributeName); 
//获取请求中存储的所有属性名 
Enumeration<String> getAttributeNames(); 
//从请求中获取给定参数名对应的参数值（参数值是单个数据） 
String getParameter(String parameterName); 
//从请求中获取给定参数名对应的参数值（参数值是多个数据） 
String[] getParameterValues(String parameterName); 
//从请求中获取所有的参数名 
Enumeration<String> getParameterNames(); 
//从请求中获取所有的参数名和参数值形成的映射 
Map<String, String[]> getParameterMap(); 
//从请求中获取字符集编码 
String getCharacterEncoding(); 
//设置请求的字符集编码 
void setCharacterEncoding(String charset) throws UnsupportedEncodingException;
 //从请求中获取字符流，该字符流只能读取请求体中的数据信息，与下面的 getInputStream 方法只 能二选一 
 BufferedReader getReader() throws IOException;
  //从请求中获取字节流，该字节流只能读取请求体中的数据信息 
  ServletInputStream getInputStream() throws IOException; 
  //从请求中获取当前Servlet所在的上下文对象 
  ServletContext getServletContext(); 
  //从请求中获取请求转发的对象 
  RequestDispatcher getRequestDispatcher(String path);
```

注：
1. 参数——提交上来的数据
2. **`ServletRequest` 的存储对象是用来在“这一次请求”的处理过程中，临时存放和传递数据的“便签板”**，它随请求开始而创建，随请求结束而销毁，不会影响其他请求，安全且高效。
3. <mark style="background: #FF5582A6;">使用GET方式发送的请求，只能通过getParameter 方法获取；使用POST方式发送的请求，只能使 用流来获取。这是因为使用GET方式发送的请求，参数在URL地址中，解析这些参数的时候将其存 放在一个Map集合中，因此可以直接获取。而POS方式发送的请求，参数在请求体中，这部分内容 只能通过流来读取，然后再进行处理</mark>
4. 参数只能获取一次，要流获取，要么get获取——仅限于自己用接口调用，HttpServlet底层优化，可重复读取

# request与response的形成

注：
1. 表单提交时，浏览器发送的 HTTP 请求会被 Web 容器封装成一个 **`HttpServletRequest` 对象**，同时创建一个 **`HttpServletResponse` 对象**，然后交给目标 Servlet（或 JSP）处理。
2. “若没有表单数据，则 request 为空” —— 这个说法不对。即使没有提交任何表单字段（比如一个空的 GET 请求），HttpServletRequest 对象<mark style="background: #FF5582A6;">仍然会被创建</mark>，它包含了请求行、请求头等信息（如请求 URL、方法、客户端 IP 等）。只是调用 getParameter() 会返回 null，但 request 对象本身不为空。

参数与属性：
1.  **“参数”** 通常是指 **客户端发送到服务器的请求参数（Request Parameters）**。这些参数是<mark style="background: #FF5582A6;"> 键值对形式</mark>，来源于：

- **URL 查询字符串**（GET 请求）：`http://localhost:8080/app?name=张三&age=25`
    
- **请求体**（POST 表单）：`<form method="post"> <input name="name"> ... </form>`
    
- **Cookie 或 Headers**（虽然它们也可以获取，但一般不称为“参数”）。
