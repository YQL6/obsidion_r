# <h1>请求转发的流程</h1>

1. **请求到达**：你的请求通过浏览器“送”到了<mark style="background: #FF5582A6;">服务器的</mark>调度室。
2. **身份识别与资源定位**：调度员（即 `Servlet容器`，如Tomcat）首先检查你的请求（HTTP报文），并<mark style="background: #FF5582A6;">根据请求中的URL地址</mark>，在它的“地址本”上<mark style="background: #FF5582A6;">查找对应的资源</mark>。
3. **路由分发**：调度员根据地址本上的记录，执行以下三种处理方式之一：
    - **找Servlet处理（动态内容）**：如果URL匹配的是一个 <mark style="background: #FF5582A6;">`Servlet` 的路径</mark>，调度员会找到它，并把你的请求信息（打包成 `request` 对象）交给这个 `Servlet` 去处理。`Servlet` 处理完业务后，会告诉调度员接下来该做什么，这就是“页面跳转”。
    - **直接返回静态文件**：如果URL直接指向一个 `.html` 或 `.jsp` 等静态文件，调度员会直接把这个文件作为响应返回给你[](https://cloud.tencent.cn/developer/article/1190432)。
    - **返回“查无此页”**：如果地址本上<mark style="background: #FF5582A6;">没有任何资源能匹配</mark>你的请求URL，调度员会直接返回一个“404 找不到”的响应。

# <h1>servlet工作流程</h1>

无servlet映射的url路径转发：Web服务器自带一个“默认Servlet”来处理未明确映射的请求。对于 `.jsp` 文件，它会自动将其翻译、编译成对应的 `Servlet` 并执行。因此，**直接访问 `.jsp` 文件<mark style="background: #FF5582A6;">本质上</mark>也是一种由服<mark style="background: #FF5582A6;">务器内部隐式 `Servlet` 处理</mark>的动态请求**，而不是完全跳过了 `Servlet` 机制。

# <h1>forward过程</h1>

由上所述，可知页面转发：
1. 指令一：服务器内部转发：`Servlet` 告诉调度员：“接下来这件事也归我们管，你把我的这个 `request` 文件袋和未写完的 `response` 回函，<mark style="background: #FF5582A6;">直接转交给另一个指定的同事</mark>（另一个 `Servlet` 或 JSP）继续处理吧！”。这就是 **请求转发 (Forward)**。
2. 指令二：客户端重定向：`Servlet` 告诉调度员：“跟客户说，我这里已经处理完了，让他去另一个新地址办剩下的手续吧。”。于是，调度员<mark style="background: #FF5582A6;">将新地址写入回函（`response`）</mark>，并附上一个 <mark style="background: #FF5582A6;">302 状态码</mark>，让浏览器按新地址重新发起一个全新的请求。这就是 **重定向 (Redirect)。

# printwrite

printwrite——response获得的输出流包装类：输出的数据最终被写入到 **HTTP 响应体** 中，并通过网络发送给客户端（浏览器）。

过程为：
1. **`HttpServletResponse` 封装了网络连接**  
    Servlet 容器（如 Tomcat）为每个请求创建 `ServletResponse` 对象，它内部持有与客户端之间的 **Socket 输出流**（`OutputStream`）。`response.getWriter()` 返回的 `PrintWriter` 实际上是对这个底层输出流的一个字符流封装。
    
2. **写入过程**
    
    - 调用 `out.print("hello")` 时，数据先进入 `PrintWriter` 的缓冲区。
        
    - 当缓冲区满、手动 `flush()` 或 `close()` 时，数据被刷新到底层的 `OutputStream`。
        
    - 底层 `OutputStream` 将字节数据通过 TCP Socket 连接发送到客户端（浏览器）。
        
3. **最终去向**  
    浏览器接收到完整的 HTTP 响应后，根据 `Content-Type` 头解析响应体内容并显示（如 HTML、JSON、图片等）

注：**`PrintWriter` 输出的内容本质上就是字符串（文本）。**
