	- `client`:发送请求,发送的`URL`转化为`IP`
	- `server`：响应请求,将对应的页面返回给浏览器，浏览器显示页面

## 1.2HTTP协议

---

- `HTTP协议`:超文本传输协议，规定发送内容的格式
	- `client——》server`:传送，<mark style="background: #FF5582A6;">根据格式找到对应文件下资源</mark>
	- `server——》client`:响应

- 大体格式：
	- `http://127.0.01:8080/myweb/servlet01?name=zhang`
		- `http://`:协议
		- `127.0.01:8080/或域名:/8080`:`IP/域名 + 端口`
		- `/myweb/servlset01`:服务器里面的路径——》资源路径
		- `?name=zhang`:传递的参数

## 1.3URL，请求协议，响应协议

---

- 请求协议`URL`:`http://host:端口/文件地址/参数`

- `http请求`:
	- 请求头:
		- 键值对：
			- 主机号
			- 文本编码方式
			- 等
	- 请求行
		- `请求方式`
			- `get`
			- `post`
		- 版本号
		- `URL`:去掉主机和协议
	- 请求正文
		- 请求正文/请求体，仅`post`有，`get`在url中
		- 参数

- 大体的格式
```
//大体格式
请求行
请求头1
请求头2
请求头3
......
请求头n
空格
请求体
```

- 请求格式
```
//请求行格式
Method:请求方法
Requeset URI:网址
HTTP-version:请求的GTTP协议版本
空格
```

- 请求头的部分：

| 请求头                   | 含义                | 示例值                                                      | 说明                            |
| --------------------- | ----------------- | -------------------------------------------------------- | ----------------------------- |
| **Host**              | 目标主机名+端口          | `www.baidu.com`                                          | HTTP/1.1 起**必带**，用于虚拟主机识别     |
| **User-Agent**        | 客户端（浏览器/程序）标识     | `Mozilla/5.0 (Windows NT 10.0)…`                         | 服务端可据此区分浏览器/爬虫/移动端            |
| **Accept**            | 客户端能接受的响应类型       | `text/html,application/json`                             | 内容协商用                         |
| **Accept-Language**   | 客户端接受的语言          | `zh-CN,zh;q=0.9`                                         | 服务端可据此返回对应语言                  |
| **Accept-Encoding**   | 客户端支持的压缩方式        | `gzip, deflate, br`                                      | 服务端据此决定是否压缩响应体                |
| **Connection**        | 连接管理              | `keep-alive` / `close`                                   | 是否复用 TCP 连接                   |
| **Referer**           | 来源页面 URL          | `https://www.baidu.com/`                                 | 防盗链、统计来源；注意拼写是 Referer        |
| **Origin**            | 请求来源（跨域相关）        | `https://www.baidu.com`                                  | CORS 判断用，POST/跨域时常见           |
| **Content-Type**      | 请求体的媒体类型          | `application/x-www-form-urlencoded` / `application/json` | 告诉服务器怎么解析 Body                |
| **Content-Length**    | 请求体字节长度           | `28`                                                     | 无 Body 时不存在                   |
| **Cookie**            | 浏览器携带的 Cookie     | `JSESSIONID=ABC123; name=zhang`                          | 服务端 `request.getCookies()` 读取 |
| **Authorization**     | 认证凭证              | `Bearer eyJhbGci…` / `Basic dXNlcjpwYXNz`                | 常用于 Token/基础认证                |
| **Cache-Control**     | 缓存控制指令            | `no-cache`                                               | 请求侧缓存策略                       |
| **If-Modified-Since** | 条件请求（带上次修改时间）     | `Wed, 21 Oct 2026 07:28:00 GMT`                          | 服务器返回 304 表示未修改               |
| **X-Requested-With**  | 是否为 AJAX 请求（非标准头） | `XMLHttpRequest`                                         | 服务端判断是否异步请求                   |

- 响应信息：
	- 状态行
		- 对于请求的响应大概是什么状态
	- 响应头
		- 键值对
	- 响应正文
		- 返回给浏览器的正文——》浏览页面

- 所有的响应和请求都在`NETWork中`

|响应头|作用|Servlet 写法|
|---|---|---|
|`Location`|配合 302，指定重定向目标|`sendRedirect(url)` 或 `setHeader("Location", url)`|
|`Content-Type`|告诉浏览器正文类型/编码|`response.setContentType(...)`|
|`Content-Length`|正文长度|容器一般自动算|
|`Set-Cookie`|让浏览器保存 Cookie|`response.addCookie(cookie)`|
|`Cache-Control`|缓存策略|`setHeader("Cache-Control","no-cache")`|
|`Refresh`|定时刷新/延迟跳转|`setHeader("Refresh","3;url=...")`|
|`Access-Control-Allow-Origin`|CORS 跨域放行|`setHeader("Access-Control-Allow-Origin","*")`|

# 二.访问流程

## 2.1网址处理

---

- `https://域名/上下文路径/资源`
	- `https`:协议
	- `域名`:`IP地址，到达以后又servlet容器进行资源映射，将主机对应到什么文件夹下面`
	- `上下文路径`:将主机分为多个部分，提供不同内容，然后其做为接口
	- `资源`:
		- 静态资源：交给默认`servlet`处理，返回静态资源
		- `有servlet映射的路径`:交给此`servlet`处理，`servlet容器`创建对应的`servlet`

## 三.Servlet

## 3.1创建

---

- `继承HTTPServlet`
- `继承GenerSErvlet`
- `实现Servlet接口`

- 重写方法：
	- `secive`方法或者直接重写`doget,dopost`
		- `secive调用doget，dopost`
		- `doget/dopost`可以相互调用，共用一个代码

## 3.2生命周期

---

- 声明周期：`servlet`不能单独存在，有`servlet引擎`管理
	- 实例和初始化：
		- 当请求到达若存在对应的`servlet`，创建
		- `init方法`:创建serblet实例
	- 就绪/调用/服务：
		- 当请求到达时若对应的`servlet`已经存在，调用其`serivce
		- `service方法`:调用处理请求
	- 销毁阶段：
		- 容器关闭/应用停止时销毁
		- `dectory方法`:销毁`servlet`
