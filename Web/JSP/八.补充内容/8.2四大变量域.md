# JSP/Servlet 四大变量域（作用域）详解

## 一、什么是"域"？为什么要分域？

**域（Scope）** = 数据能被"多大范围、存活多久"地共享。

JSP/Servlet 经常要跨页面、跨请求、跨用户传数据，所以容器提供了 4 个"公共储物柜"，按范围从小到大排列：

```
page（一页） < request（一次请求） < session（一个用户） < application（所有人）
```

它们都提供同一套 API 存数据：

```
setAttribute("key", value);   // 存
getAttribute("key");          // 取（返回 Object，要强转）
removeAttribute("key");       // 删
```

区别只在：**存进去之后，谁能看见、能活多久**。

## 二、逐域详解

### 1. page 域（页面域）——最小

| 项    | 说明                           |
| ---- | ---------------------------- |
| 底层对象 | `pageContext`                |
| 存活范围 | **当前这一个 JSP 页面**（这次请求翻译执行期间） |
| 创建   | 页面开始处理时                      |
| 销毁   | 页面处理完（响应发出去）就没了              |
| 谁看得见 | 只有当前页面自己                     |
| 典型用途 | 页面内部的临时变量、页面内多个标签间传递         |

```
<%-- 当前页面内共享 --%>
<% pageContext.setAttribute("msg", "你好"); %>
${pageScope.msg}
```

**关键细节**：

- 页面转发到另一个 JSP 后，**page 域数据带不过去**（那是另一个 page）；
- 静态包含 `<%@ include %>` 合并编译后算**同一个页面**，page 域共享；动态包含 `<jsp:include>` 是另一个页面，page 域**不共享**。

### 2. request 域（请求域）——一次请求内共享

|项|说明|
|---|---|
|底层对象|`HttpServletRequest`|
|存活范围|**一次请求**：从浏览器发出请求 → 服务器处理完 → 响应返回|
|创建|请求到达服务器，Tomcat 创建 request 对象时|
|销毁|响应结束后|
|谁看得见|处理这次请求的所有组件（Servlet → **转发**到的 JSP）|
|典型用途|**Servlet 查完数据，转发给 JSP 展示**（MVC 最常用）|

```
// Servlet 里
List<User> list = userService.findAll();
request.setAttribute("userList", list);
request.getRequestDispatcher("list.jsp").forward(request, response);
```

```
<%-- list.jsp 里取 --%>
${requestScope.userList}
```

**关键细节**：

- **转发（forward）共享 request 域**（同一请求）；**重定向（sendRedirect）会丢失**——因为重定向是浏览器再发一次**新请求**，新 request 是空的；
- request 域里放的是**"这一次请求相关的数据"**，比如查询结果、表单校验错误。

### 3. session 域（会话域）——一个用户多次请求间共享

|项|说明|
|---|---|
|底层对象|`HttpSession`|
|存活范围|**同一个浏览器用户**的一整段会话（默认 30 分钟，期间一直活动会续期）|
|创建|第一次访问时（准确说：第一次"需要 session"并调用 `getSession()` 时）创建|
|销毁|超时 / 手动 `invalidate()` / 服务器关闭|
|谁看得见|这个用户的所有页面、所有请求（跨请求共享）|
|典型用途|**登录状态**、购物车、用户信息|

```
// 登录成功
session.setAttribute("user", user);
// 任何页面都能取到
User u = (User) session.getAttribute("user");
// 退出登录
session.invalidate();
```

```
${sessionScope.user.name}
```

**关键细节**：

- session 靠 **JSESSIONID（存 Cookie）**识别"同一个人"；Cookie 被禁用时可 URL 重写；
- 不要往 session 里塞大对象（图片、大集合），它一直占服务器内存直到超时；
- 一个浏览器标签页共享同一个 session（除非无痕/多浏览器）。

### 4. application 域（应用域）——最大，所有人共享

|项|说明|
|---|---|
|底层对象|`ServletContext`（JSP 里叫 `application`）|
|存活范围|**整个 Web 应用**：从服务器启动加载应用 → 应用卸载/服务器关闭|
|创建|应用启动时|
|销毁|应用停止时|
|谁看得见|**所有用户、所有页面、所有请求**|
|典型用途|全局配置、网站总访问计数、全局缓存|

```
// 记录网站总访问次数（所有用户共用一个计数）
Integer count = (Integer) application.getAttribute("count");
application.setAttribute("count", count == null ? 1 : count + 1);
```

```
${applicationScope.count}
```

**关键细节**：

- 所有用户共享 → **并发访问同一份数据**，读写时要注意线程安全（用 `AtomicInteger` 或加锁）；
- 数据存活太久，用完要记得清理，否则是"全局垃圾"；
- `ServletContext` 还能拿全局初始化参数 `context-param`、真实路径 `getRealPath()` 等。

## 三、一张总表（建议抄进笔记）

|域|底层对象|范围|创建时机|销毁时机|典型用途|EL 写法|
|---|---|---|---|---|---|---|
|**page**|pageContext|当前页面|页面开始处理|页面处理完|页面内临时变量|`${pageScope.x}`|
|**request**|HttpServletRequest|一次请求|请求到达|响应结束|Servlet→JSP 传查询结果|`${requestScope.x}`|
|**session**|HttpSession|一个用户|首次需要会话时|超时/invalidate/关服|登录状态、购物车|`${sessionScope.x}`|
|**application**|ServletContext|整个应用|应用启动|应用停止|全局配置、总计数|`${applicationScope.x}`|

## 四、EL 取值的查找顺序（重点）

```
${user}   <%-- 不带前缀，按顺序找 --%>
```

```
page → request → session → application
找到第一个就不找了
```

所以：

- 如果四个域都存了 `user`，`${user}` 取到的是 **page 域**那个；
- 想取指定域的，**加前缀最稳**：`${sessionScope.user}`；
- 你之前笔记里"request 和 session 同 key 时从 request 取"只说对了一半——**page 比 request 还优先**。

在 Java 代码里等价写法：

```
pageContext.findAttribute("user");  // 按 page→request→session→application 找
pageContext.getAttribute("user", PageContext.SESSION_SCOPE); // 指定域取
```

## 五、实战串一遍（帮助记忆）

```
用户访问 index.jsp（page 域放了个临时变量）
  ↓ 点登录
LoginServlet 验证通过
  → session.setAttribute("user", 用户对象)   ← 记住登录状态（session）
  → 查出他的订单列表
  → request.setAttribute("orders", 列表)      ← 只给这次展示用（request）
  → 转发到 orders.jsp（request 域共享，能取到 orders）
  ↓ 订单页里
显示 ${sessionScope.user.name} 和 ${requestScope.orders}
顶部计数器每次访问 +1（application 域，全局共享）
```

## 六、易错点总结

1. **重定向丢 request 域**：转发带得过去，`sendRedirect` 带不过去（两次请求）——所以"登录后跳首页"要用 session 存用户，别用 request。
2. **session 别放重数据**：它活在服务器内存直到超时，放图片/大列表会拖垮内存。
3. **application 有并发问题**：所有用户同时读写，裸 `count++` 会丢更新。
4. **page 域 ≠ 跨页面**：页面一结束就没了，别指望它传给别的页面。
5. **getAttribute 返回 Object**：要强转：`(User) session.getAttribute("user")`。

---

## 七、一句话记忆

> **page 管一页、request 管一次请求、session 管一个人、application 管所有人；范围越大活得越久、越要小心并发和内存。不带前缀的 `${x}` 按 page→request→session→application 找。**
