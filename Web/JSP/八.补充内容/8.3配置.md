**结构是固定的，内容是自由的**。更准确的说法是：Servlet 规范给部署描述符 `web.xml` 规定了**固定的标签结构和顺序**，但里面填的类名、名字、参数值由你决定。而且 Servlet 3.0 之后，这些配置还能用**注解**来写。

## 1. Servlet 的标准配置块（固定骨架）

```
<!-- ① 声明 Servlet：名字 + 类 + 初始化参数 -->
<servlet>
    <servlet-name>HelloServlet</servlet-name>
    <servlet-class>com.example.HelloServlet</servlet-class>

    <!-- 初始化参数：随应用启动时读入，内容由你填 -->
    <init-param>
        <param-name>encoding</param-name>   <!-- 参数名，你定 -->
        <param-value>UTF-8</param-value>    <!-- 参数值，你定 -->
    </init-param>

    <load-on-startup>1</load-on-startup>    <!-- 可选：启动时就加载 -->
</servlet>

<!-- ② 映射：把 URL 交给哪个 Servlet -->
<servlet-mapping>
    <servlet-name>HelloServlet</servlet-name>   <!-- 必须与上面一致 -->
    <url-pattern>/hello</url-pattern>           <!-- URL 规则，你定 -->
</servlet-mapping>
```

## 2. Filter 的标准配置块（固定骨架）

```
<!-- ① 声明过滤器 -->
<filter>
    <filter-name>EncodingFilter</filter-name>
    <filter-class>com.example.EncodingFilter</filter-class>
    <init-param>
        <param-name>charset</param-name>
        <param-value>UTF-8</param-value>
    </init-param>
</filter>

<!-- ② 过滤器映射：拦截哪些请求 -->
<filter-mapping>
    <filter-name>EncodingFilter</filter-name>
    <url-pattern>/*</url-pattern>        <!-- 拦截所有请求；也可用 <servlet-name> 指定某个 Servlet -->
    <dispatcher>REQUEST</dispatcher>     <!-- 可选：REQUEST/FORWARD/INCLUDE/ERROR -->
</filter-mapping>
```

## 3. 为什么说"固定"

- `web.xml` 的根标签和整体结构是 **Servlet 规范定死的**，必须符合某个版本（2.5 / 3.0 / 4.0 / 6.0…）的 XSD schema，标签写错或顺序不对容器会报错。
- **固定的是"骨架/标签"**，例如：`<servlet-name>` 里必须是名字、`<servlet-class>` 里必须是全限定类名。
- **自由的是"内容"**：类名、名字、URL 规则、参数名和值都自己填。
- 每个 Servlet/Filter 的"初始化配置"都长这样一套模板，所以你会觉得"都是固定的内容"——其实是同一套模板反复用。

## 4. 代码里怎么读这些"固定配置"

```
// Servlet 里读自己的初始化参数（通过 ServletConfig）
public class HelloServlet extends HttpServlet {
    public void init() {
        String enc = getServletConfig().getInitParameter("encoding");
        // 或 this.getInitParameter("encoding")
    }
}

// Filter 里读自己的初始化参数（通过 FilterConfig）
public class EncodingFilter implements Filter {
    public void init(FilterConfig fc) {
        String charset = fc.getInitParameter("charset");
    }
}
```

ServletConfig/FilterConfig 就是容器把你 `web.xml` 里写的配置打包好再交给你的。

## 5. Servlet 3.0 之后：注解版（结构同样固定）

上面整段 XML 可以简化为注解，但**属性是固定的**，只是换了写法：

```
@WebServlet(
    name = "HelloServlet",
    urlPatterns = "/hello",
    initParams = @WebInitParam(name = "encoding", value = "UTF-8")
)
public class HelloServlet extends HttpServlet { }

@WebFilter(
    urlPatterns = "/*",
    initParams = @WebInitParam(name = "charset", value = "UTF-8")
)
public class EncodingFilter implements Filter { }
```

`@WebServlet`、`@WebFilter`、`@WebInitParam` 这些注解的属性名就是"固定内容"，你只填值。

## 两个常被忽略的"固定细节"

1. **执行顺序**：多个 `<filter-mapping>` 的**书写顺序**决定过滤器链的执行顺序（规范保证同一 URL 映射按声明顺序执行）。
2. **匹配规则**：`<url-pattern>` 有三种固定写法——精确匹配 `/hello`、目录匹配 `/admin/*`、扩展名匹配 `*.do`（`/` 通配整个应用）。根路径 `/` 只匹配默认 Servlet。

**一句话总结**：Servlet 和 Filter 的配置**骨架固定**（标签/注解属性是规范写死的），但**内容自定义**（类名、URL、参数都自己填）——你写每个新功能时，其实就是在重复填同一套固定模板。
