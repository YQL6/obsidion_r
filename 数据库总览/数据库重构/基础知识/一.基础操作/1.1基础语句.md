## 1.4RDBMS

---

- `RDBMS`:关系型数据库

- 关系型数据库：
	- 把复杂的数据结构变为简单的二元关系形式(表格)
	- 实质：表格，多个表格汇集在一起——》数据库

- 关系型：
	- 一个实体对应一张表
	- 不同实体间存在各种各样的关系，可以通过关系模型联系起来

- `SQL`:
	- 同数据库通信的语言

- 非关系型数据库：
	- 舍去关系型数据库的一些特点，复杂查询，事务性等 ——》 换取高性能优势
	- 常用类型：
		- 键值型数据库，`Redis`，通过`key-value`，可以通过`key`快速查询`value`,常用于缓存
		- 文档型数据库
		- 搜索引擎
		- 列式数据库:`HBase`

- `NOSQL`:非关系型数据库的操作语言

## 1.6关系型数据库设计

---

- 表类似`JAVA中的类`,使用`ORM思想(object relational MApping)`
- 表的一个数据行类似`JAVA类的一个对象`,`列类似JAVA的字段/属性`

- 表与表间的关系:
	- `E-R模型(entity-relationship , 实体-联系)`:实体集，属性，联系集
		- 实体集：表，表的一条记录就是对象
		- 属性：字段/列
	- 关联关系：
		- 一对一关联关系：
			- `A的一条记录对应B的一条记录`,不常用，往常直接可以造成一个表
			- 例子：个人信息(学号，姓名，手机号，联系人)，不常用的个人信息(学号，身份证号，家庭住址等)
		- 一对多关联关系：
			- 常用，一个表的记录对应另一个表多个记录——》主表(一)，从表(多)
			- 示例：部门表，员工表，一个部门对应多个员工
		- 多对多关联关系：
			- 使用一般要建立一个<mark style="background: #ABF7F7A6;">连接表</mark>实现多对多的关系，都对连接表实现一对多(连接表)的关系
			- 示例：学生表，课程表，选课信息表，选课信息表中由于学生信息不同，一个课，多条记录，与课程表一对多，选课信息表由于多个课程，与迅速信息表一对多关系
		- 自我引用
			- 自己引用自己
			- 示例：员工表中有主管信息字段，而主管也是员工

# 二.查询基础语法

## 2.1查询语句

---

- `SELECT ... FROM ...`:
	- 从表中查询什么列
		- 表格名
		- 列名：多个列名之间必须由`,`,否则变为别名了(省略了`as`)
	- 伪表：使用表达式做为列，没有列名字符，由于没有选择筛选以后的列，自己创建的列<mark style="background: #ADCCFFA6;">(查询常数)</mark>——》要与筛选以后列的每行一一对应，<mark style="background: #ABF7F7A6;">每一行都匹配这个常数，做为单独新加的一列</mark>，即有几行，就返回几行的自建列
		- 本质：<mark style="background: #FFF3A3A6;">对每一行都进行常数/表达式匹配</mark>
	  ![[图片/Pasted image 20260913144659.png]]
	- <mark style="background: #FFF3A3A6;">本质：就是在筛选之后的表格中拿出要求的整个列</mark>

- `*`:正则——》所有的内容

```mysql
-- 伪表：相当于没有查询表中的列
select 1+1,2+2 FROM DAO;
```

- 别名：`查询时的结果集列的最上面是列名，将显示的列名更改为别名`,<mark style="background: #FFF3A3A6;">不可以使用别名去做为列名参与条件</mark>
	- 别名的<mark style="background: #D2B3FFA6;">使用</mark>要么不加`""`，要么加`""`,<mark style="background: #ABF7F7A6;">最好加上避免使用表达式时或带空格时冲突</mark>
	- 不要使用单引号，一些数据库语法可能不严谨，有点数据库支持，有的数据库不支持

```mysql
select name "小李" from students;

select name 小李 from students;
```

- 去除重复行：单独查询表中的一个列，可能单独显示这个列可能会有多个重复内容——》去重
	- 使用`distinct`在`select一起表示去重`，有的表在某个列为空，若是空，正常表示便是
	- `select distinct 列名1，列名2... form ...`:以列名1，列名2..为一个组，<mark style="background: #FFB86CA6;">看整体是否重复</mark>

```mysql

select distinct name from students;
```

- 着重号：1的左边的符号，若是表名，数据库名，变量名，列名等<mark style="background: #BBFABBA6;">若是使用关键字命名，使用着重号包裹，视为一个命名</mark>，若是不使用关键字命名，使用着重号，也行，没影响

- `DESCRIBE`:显示表的结构：
	- 列名
	- 类型
	- 是否允许为空
	- 约束
	- 默认值

## 2.2过滤数据

---

- 与查询语句配合使用，<mark style="background: #FF5582A6;">按要求(过滤掉一些行)变为对应的一个表，然后选择对应列</mark>

- `WHERE + 条件`:
	- 将表格中不符合的行过滤掉
	- 一定声明在`from第一个后面`
	- 本质：<mark style="background: #FF5582A6;">对每一行都进行条件判断,符合留下，不符合去掉，只留返回值为1的</mark>
	- 特殊：
		- 若是查找`null`的值，使用`=`一定查不到，有`null`的判断就一定返回`null`，只有返回`1`的才保留,但是可以使用`<=>`

注：
1. 条件使用的字符串比较，<mark style="background: #FF5582A6;">大小写是否敏感</mark>，要看创建数据库时是否设置大小写敏感<mark style="background: #FFB86CA6;">，看比较规则</mark>
2. `windows 下的大小写敏不敏感 不会对单/双引号 产生影响`

## 2.3运算符

---

- 算术运算符：
	- `+`:
		- 加法运算符
		- 计算两个值或表达式的和，只表示加法运算
			- 若有字符串参与，会将字符串变为数值
				- 字符串是一个数：按数值计算
				- <mark style="background: #ABF7F7A6;">字符串不是一个数：按0计算</mark>
			- 若有`null`参与计算：`null`
		- `select A + B`
	- `-`
		- 减法运算符
		- 计算两个值的差
		- `select A - B`
	- `*`:
		- 乘法运算符
		- 计算两个值的乘积
	- `div/ /`:
		- 除法运算发
		- 计算两个值的除，非整除运算
		- 默认除不尽：浮点型
		- 特殊情况：`100 div 0`,默认`null`
	- `% / mod`
		- 取模操作
		- 计算两个数的模数，<mark style="background: #FFB86CA6;">默认符号和被模数的符号相同，去掉符号正常运算</mark>
- 比较运算符
	- 判断结果：
		- `1 : 结果为真`
		- `0 : 结果为假`
		- `null : 结果为null`
	- 纯粹的运算符：
		- `=/!=`
			- 等于/不等于符号，判断是否相同
			- <mark style="background: #ABF7F7A6;">可以数值和字符串比较，字符串默认为0，字符串隐式转换为0</mark>
			- 特殊情况：
				- 都是字符串比较：具体看比较规则是否大小写敏感，若是不敏感大小写比较同` 'aB' = 'Ab'` 是1
				- <mark style="background: #ADCCFFA6;">等号两边有`null`直接结果就是`null`</mark>
		- `<=>`
			- 安全等于，相比可以判断`null`
		- `>= / <= / < / > / <>``
			- 规则大致相同
	- 非纯粹的运算符：
		- `ISNULL() / ISNOTNULL() / IS NOT NULL / IS NULL`
			- 判断是否为`null`
		- `LEAST() / GRLEAST()`:
			- 取参数中的最小/最大，字符串比较是`先比位数，若相同位数按位比较ASCLLE`
		- `列名 Between ...(上界) AND ....(下界)`
			- 区间数，包括边界值
			- 相当于：`上界 >= xxx AND 下界 <= xxx`
		- `in (set) / not in(set)`
			- 列名的某一行是否在一个范围内
			- `select last_name,salary,department_id from emploees where department_id in(10,20,30);`，使用`or`也可以
		- `LIKE 'xxx'`
			- 模糊查询，使用正则表达式，表达时严格位置固定:`a%`以a开头后面随意
			- 特殊符号：
				- `%`:不确定个数的字符，`0~?`
				- `_`:表示一个不确定字符
				- `\`:转义字符
				- `ESCPAPE $/xxxx 自定义转义字符`:`select last_name from xxxx where last_name LIKE '_$_a% ESCAPE $'
		- `字符串/字段 REGEXP '正则表达式'`:
			- 具体规则:[[操作系统/Linux/三.开发拓展/3.3shell编程|3.3shell编程]]
			- 若字符串符合后面的正则表达式，返回1
	- 逻辑运算符：
		- `&& / AND`:
			- 两个条件同时成立才是1，有`null`直接为`null`
			- 数值非0为1，数值0为0
		- `|| / or`
			- 或
		- `NOT`
			- 取反，在`WHERE后面条件判断语句前面`
		- `xor`:
			- 异或，条件一满足则条件二应该不满足——》1
		- `or 和 and 可以一起使用 优先级是and 后or 只要有and就先运算`
	- 位运算符：
		- `&`

## 2.4排序和分页

---

- `ORDER BY`:
	- 排序:
		- 一级排序：
			- 只根据一个数据排序
		- 二级排序：
			- 先按照一个数据排序，<mark style="background: #FFF3A3A6;">若是有相同部分</mark>，再按照另一个数据排序
			- `ORDER BY 一级,二级;`
	- 排序顺序：<mark style="background: #BBFABBA6;">紧跟着要生效的数据</mark>
		- `AES`:默认，升序
		- `DESC`:降序
	- 使用字段：
		- 列名
		- 别名
		- 非查询字段

```mysql
use atguigudb;

-- 没有指定顺序，但是多次查询顺序一致，有一个默认顺序——》添加到数据库的顺序
SELECT * from employees;

-- 实现排序，希望按id排序从高到底——》使用ORDER BY排序
-- 升序操作：ASC(默认)
-- 降序操作：DESC

select * from employees ORDER BY employee_id DESC;

-- 通过年度工资从高到低排序,年度工资使用别名实现

select *,salary * 12 annual_sal from employees ORDER BY annual_sal DESC;

-- 通过dempart_id排序，然后再按照salary升序排序

select employee_id,salary,department_id
from employees
ORDER BY department_id DESC,salary ASC;
```

注：
1. <mark style="background: #ABF7F7A6;">别名可以在`ORDER BY`中实现，但是不能再`WHERE`中实现</mark>，为什么呢——》执行顺序决定：先是`FROM 然后 WHERE 然后 SELECT 然后 ORDER BY `,再执行`WHERE`是无别名

	- 参数:

```mysql
-- 显示第3页，一页20条数据

select employee_id,last_name
from employees
# limit  40, 20;

```

注：
1. <mark style="background: #FFF3A3A6;">计算到后面会有变量，进行动态计算，但是参数不能是计算</mark>

# 三.多表查询

## 3.1查询意义

---

- 一对多关系：
	- 多个实体建立对应的表，多个表之间有对应的关系关联 ——》多表查询联系起来
	- 一个实体的信息与另一个实体间的信息对应，需要一次查询要用到多表查询
	- 每个实体当作一个对象，提取相同信息生成一个表，<mark style="background: #BBFABBA6;">模拟现实关系</mark>

- 多表的好处：
	- 降低`I/O`,若是都存储在一个表中同一个信息，可能一个对象使用一样的信息，冗余——》导致`I/O`次数增多，降低效率
	- 冗余，若是多表直接引用(外键)即可，若是一个表什么都要存储
	- 多线程高并发，一个表被查询时为了安全，会进行锁定，其他无法使用，若是使用多表将其分开，则效率提高

- 普通查询：多次查询，返回数据处理层，耗时，效率低
```sql
use atguigudb;

/*
  SELECT ....
  FROM ...
  WHERE ... AND/OR/OXR/NOT .... 
  ORDER BY ....
  LIMIT .... OFFSET ....
*/

-- 查询Abel所在的城市

SELECT *
From employees
WHERE last_name = 'Abel';

-- 获得部门的ID =80

SELECT *
FROM departments
where department_id = 80;

-- 获得地点的ID = 2500

SELECT *
FROM locations
where Location_id = 2500;
```

## 3.2笛卡尔积

---

- 使用多表查询
```sql
-- 查询过程：employees.employee_id,departments.department_id,locations.location_city
select employee_id,department_name
from employees,departments;
-- 一共查询2889条数据，远远超过两表之和
```

- 机制：
	- 笛卡尔积：
		- 以任意一个表为准，将表中每个表项都与另一个所有表项都匹配连在一起，所有的连在一起，形成一个新表
		- 计算：
			- 表A：`n项`
			- 表B：`m项`
			- 笛卡尔积：`m * n项`
		- 形成了一个新表，但是不应该获得全部匹配的表，<mark style="background: #FFF3A3A6;">应该对连接后的表应该进行条件筛选</mark>

```sql
-- 书写查询条件，挑选出员工表和部门表间表项间有关系的表项 ——》 关系在同一个部门号，部门号使员工能对应到部门
select employee_id,department_name
from employees,departments
WHERE employees.department_id = departments.department_id
;
```

- 多表查询/进行：先笛卡尔积，将两个表联系起来，然后<mark style="background: #ABF7F7A6;">保留有联系</mark>的表项

```sql
-- 报错：连接后，表中有两个相同列名
select employee_id,department_name,department_id
from employees,departments
WHERE employees.department_id = departments.department_id
;

-- 虽然有两个相同的列名，但是可以直接使用*，系统默认改名字
select *
from employees,departments
WHERE employees.department_id = departments.department_id
;
```

- 解决不知道相同列名问题：知名表名`exployees.department_id`,没有冲突的也<mark style="background: #FFB86CA6;">建议添加</mark>，避免查询时在其他表中查询字段

- 可以为表起别名，`别名在from中，最先执行，可以起别名使用`,<mark style="background: #FFB86CA6;">若是起别名以后，使用表必须使用别名</mark>

```sql
use atguigudb;

--  直接写表的名字麻烦，为表起别名
select employee_id,department_name
from employees e,departments d 
WHERE e.department_id = d.department_id
;

-- 表了有了别名，使用有别名的表时，必须使用别名


--  直接写表的名字麻烦，为表起别名
select employee_id,department_name
from employees e,departments d 
WHERE employees.department_id = departments.department_id
;

-- 正确用法
select employee_id,department_name
from employees e,departments d 
WHERE e.department_id = d.department_id
;

select employee_id,department_name
from employees e,departments d 
WHERE e.department_id = d.department_id
ORDER BY e.employee_id DESC
;

```

- 查询Abel所在的城市：多表查询

```sql
-- 多表间通过两个两个间的连接关系，链接起来，将其他不符合的表项剔除
select e.employee_id,d.department_name,l.city
from employees e,departments d, locations l
where e.department_id = d.department_id AND d.location_id = l.location_id;
```

## 3.3连接方式

---

- 等值连接 vs 非等值连接：对于连接条件而言，连接条件是一个值等于另一个连接

```sql
-- 工资等级表和员工表没有直接的关系，不像单位和员工间是主从关系
-- 但是有逻辑关系：一个员工的工资只有可能在一个等级工资的区间，通过逻辑关系筛选出最后的表项

SELECT e.last_name,e.salary,j.grade_level
from employees e, job_grades j 
where e.salary between j.lowest_sal AND highest_sal;
```

- 自连接 vs 非自连接 ： 连接对象而言,自己连自己

```sql
-- 找自己的主管

-- 顶头上司上面没有主管了，所以便通过连接条件null = ?，结果为null，排除
select e1.last_name,e2.last_name manager_name
from employees e1,employees e2
where e1.manager_id = e2.employee_id;
```

- 内连接 vs 外连接
	- 内连接：根据连接条件，把满足条件的表项查出来了，不匹配的表项就没有了，看不到了，例如：顶头上司没有主管了
	- 外连接：即使不满足连接条件，也要显示出来
		- 外连接要有一个基准/主表：不匹配了的表项是以哪一个表为准显示未匹配的表项
		- 实现逻辑：
			- 为<mark style="background: #FFF3A3A6;">基准的表开始取表项</mark>
			- 取出来的表项向另一个表的所有表项进行匹配，若是<mark style="background: #FFF3A3A6;">匹配上了</mark>，输出，多条匹配输出多条
			- 若是<mark style="background: #FFB86CA6;">没有匹配的</mark>，则进行输出这个表项 + 另一个表的表项全为`null`的形式
		- 分类：
			- 左外连接：左表为主表
			- 右外连接：右表为主表
			- 满外连接：左右都为主表
				- 实现逻辑：
					- 输出匹配上的表项
					- 看左表中的表项，若是未匹配上，输出`左表 + 右表(null)`
					- 看右表中的表项，若是未匹配上，输出`左表(null) + 右表`
		- 实现语法：
			- `92 / sql-2`:`+`
			- `99 / sql-3`:
				- `内连接 [INNER] JOIN ... ON ...`：`JOIN连接表，ON跟条件`,有关系的两个表连接，形成一个新表，可以继续参与连接
				- `外连接 LEFT/RIGHT/FULL [OUTER] JSON... ON ...`
				- `满外连接的实现`

```sql
-- sql92语法

-- 找所有员工的主管
-- sql92语法实现外连接使用+

select e1.employee_id,e1.last_name,e2.employee_id,e2.last_name
from employees e1 ,employees e2
where e1.manager_id = e2.employee_id(+);

-- 找所有员工的last_name,department_name,但是有的员工没有部门
-- 使用sql92实现外连接,mysql不支持，可以使用orcal，相当于为另一个表为主表/没有+的表为主表

select employee_id,department_name
from employees e,departments d 
WHERE e.department_id = d.department_id(+)
;
```

```sql

-- sql99语法实现内连接
-- JOIN连接两个表，ON表示两个表的连接条件，可以使用完JOIN ... ON ... 后再使用where继续过滤
select employee_id,department_name
from employees e JOIN departments d 
ON e.department_id = d.department_id
;

ON e.department_id = d.department_id;
```

## 3.4UNION

- `UNION`：
	- 合并查询结果，可以将多条`SELECT语句`结果集合并到一起,去掉重复部分，合并时两个表对应的<mark style="background: #BBFABBA6;">列数</mark>和<mark style="background: #FF5582A6;">属性</mark>必须相同
	- 合并不以列名为准，而是列的顺序和类型为准，<mark style="background: #FF5582A6;">列名一般以第一个表为准</mark>

- `union`：
	- 返回并集，去掉重复
	- 去重——》效率低
- `UNION ALL`:
	- 返回并集，合并后是什么样，返回什么样，重合部分两份
	- 仅合并，仅返回，效率高，<mark style="background: #BBFABBA6;">常用</mark>

注：
1. 若是明知没有重复/无需去重，一定使用`UNION ALL`，提高效率

## 3.599语法新特性

---

- 自然连接:`natural JOIN`:
	- 相当于系统为我们做的等值连接，遍历一个表中的所有字段，看另一个表中是否有同一个字段
		- 有：做为条件，进行等值连接
		- 没有：不做任何事情
	- <mark style="background: #BBFABBA6;">内连接</mark>的基础上

```sql
-- NATURAL JOIN  一个内连接

select employee_id,department_name
from employees e  JOIN departments d 
ON e.department_id = d.department_id
AND e.manager_id = d.manager_id
;

select employee_id,department_name
from employees e NATURAL  JOIN departments d 
;
```

- `USING(字段)`：
	- 默认对字段再两个表中找到，并进行等值连接(单独针对这个字段)
	- 只能对`JOIN配合使用`,替代`ON`表示条件

```sql
-- USING

select last_name,department_name
from employees e LEFT OUTER JOIN departments d 
USING(department_id);


select last_name,department_name
from employees e LEFT OUTER JOIN departments d 
ON e.department_id = d.department_id;
```

## 4.4聚合函数/多行函数

- 单行函数的机制：
	- 使用再`select`后面对每行进行操作，然后对每一行都输出一行数据
	- 输入几行，输出几行
- 多行函数的机制：
	- 将所有的参数都遍历后，<mark style="background: #BBFABBA6;">输出一个汇总行</mark>，与表中数据独立的行，若是强行和表中的列放在一起，<mark style="background: #FFB86CA6;">列随机返回一个数</mark>
	- 若是放在`select`后面，其实是一个<mark style="background: #FFF3A3A6;">错误语法</mark>，只是运行相对宽松没有报错
	- 多行 ——》 单行

- 单行函数和多行函数的本质区别：
	- 单行函数时在`select`时，一遍获得一行行数据的字段，一遍执行单行函数，合并到表中
	- 多行函数一边获得一行行数据，一边计算得到一个单表的一行字段，若是查询的字段 + 多行函数都是唯一的 ——》 正确，反之，报错/随机返回一行字段

- 多行函数:
	- 输入多条数据，一定只能返回一个数值

- 常用的聚合函数:
	- `AVG()`:
		- 返回一组数据的平均数值，适应于数值类型的
		- 字符串求总和，进行默认的转换，结果一定为0
		- 对于有`null`的行<mark style="background: #ADCCFFA6;">不做处理</mark>，不做分母，也不做分子，忽视
		- 可以<mark style="background: #BBFABBA6;">搭配</mark>`IFNULL(xxxx,0)`使用，使所有行都计算，被忽视任何一行
	- `SUM()`:
		- 返回一组数据的总和，适应于数值类型的
		- 字符串同，0
		- 对于有`null`的行<mark style="background: #BBFABBA6;">不做处理</mark>，不做分母，也不做分子，忽视
	- `MAX()`
		- 返回所有参数的最大值
		- 字符串可以进行比大小，日期也可以进行比较
	- `MIN()`:
		- 返回所有参数的最小值
		- 字符串可以比大小，日期也可以进行比较
	- `COUNT()`:
		- 返回指定字段在查询结构中<mark style="background: #FFB86CA6;">出现的个数 —— 》 统计条数</mark>
		- 统计条数 与 字段的具体数值无关，只关心个数，<mark style="background: #ABF7F7A6;">不包括`null`</mark>
		- 查询/循环过程中不断对应<mark style="background: #FFF3A3A6;">字段进行统计</mark>
		- 可以<mark style="background: #FFB86CA6;">搭配</mark>`IFNULL()`使用，使所有行都计算，被忽视任何一行

```sql
-- 表中有多少执行多少行，但是每行都是看null，所以为0
-- 表中多少条随机，可以count(1),count(*),count(任何字段/不可为null的字段)
-- 全部条数统计:具体看使用的存储引擎是什么

select count(null),count(salary)
from employees;

--- 不计算null的，但是计算奖金率这样不对，对于没有的做为分母不可以忽视

select AVG(commission_pct) , SUM(commission_pct) / COUNT(commission_pct),
SUM(commission_pct) / 107
from employees;

-- 优化:若是为null，直接换另一个数来计算

select  AUG(IFNULL(commission,0)),SUM(commission_pct) / COUNT(IFNULL(commission_pct,0))
from employees;

```

注：
1. 存储引擎:`MYISM`三者效率相同,`InnDB`(默认使用最高效率方式进行，字段已经被指定):`count(*) = count(1) > count(字段)`

# 五.分组

## 5.1`group by`

---

- 分组机制：
	- 分组流程：
		- 使用`WHERE`对表格过滤
		- 对进行参与分组的分组列进行计算<mark style="background: #FFB86CA6;">分组键或分组组键</mark>
		- 比较分组键或分组组建，相同的为一组
		- <mark style="background: #BBFABBA6;">对于`null`也可以进行比较</mark>，若是有`null`单独为一组，若是多个列参与分组，也可以比较
	- 聚合函数与分组列一起查询：
		- 聚合函数后要表的列的一个值
			- 列是分组列：<mark style="background: #CACFD9A6;">分组列的值固定(</mark>因为分组已经把相同的放在一起)——》<mark style="background: #FF5582A6;">返回固定值</mark>
			- 列不是分组列：列的值不确定 ——》随机返回一个<mark style="background: #D2B3FFA6;">(mysql机制保证，本质是错误语法)</mark>
	- 未分组的表本质上也是一个大的分组
	- 结论:
		- 结论1：`select的字段，必须出groud by中`
		- 结论2：`groud by 声明在where后面，from后面，order by前面，limit前面`
		- 结论3：`with rollup可以在5.7以后的版本和order by使用`
		- 结论4：<mark style="background: #FFF3A3A6;">一般聚合列都要出现在查询中，表明信息
</mark>
```sql
-- group by使用

-- 查询各个部门平均工资，最高工资 ——》进行分组计算，匹配

select AVG(salary)
from employees
group by department_id;

-- 将分组列department_id和平均工资对应起来，直接查询
-- 使用 聚合函数 + 非分组列 方法是错误的，mysql会默认为将汇总行和一个表的行进行一个拼接，表的列随机返回一个值
-- 分组后这种组合是正确：聚合函数 + 聚合列，这个值是确定的
-- 但是可以利用这种机制 ——》gropu by 分组后，使用的分组列在分组中是同一个值，随即返回值相同

select department_id,AVG(salary)
from employees
group by department_id;

-- 在以部门分组的基础上，在对不同工作进行分组，然后查询工资
-- 两个分组顺序不同，结果相同
-- 相当于最后分组形成一个带有两个标签的分组，各行按自己行的值条件进入不同分组，只是先后顺序不同


select department_id,job_id,AVG(salary)
from employees
-- 优先为第一个分组，然后有按第二个分组,....
group by department_id,job_id;

select department_id,job_id,AVG(salary)
from employees
-- 优先为第一个分组，然后有按第二个分组,....
group by job_id,department_id;


```

- 新特性：
	- `with rollup:`
		- 相当于对分组从左到右开始逐渐减少分组列，形成一个新的分组，进行聚合函数(查询中用什么聚合，相应的其也用什么聚合)
		- 是一个小计，对于分组合并小计，到最后形成一个整表计算
		  ![[图片/Pasted image 20260916103756.png|780]]
```sql
select department_id,job_id,SUM(salary)
from employees
-- 优先为第一个分组，然后有按第二个分组,....
group by job_id,department_id with ROLLUP
;
```

## 5.2`HAVING`

---

- 核心：对分组以后的分组进行过滤
- 面向对象：组
- 要求：
	- 要求1：使用聚合函数，则不能使用`where`过滤，要使用`HAVING`
	- 要求2：`HAVING 必须声明在 GROUP BY 后面`
	- 要求3：若是<mark style="background: #CACFD9A6;">不分组</mark>，就是一个大组，使用聚合函数，任然要使用 `HAVING` ，但是面向的是一个大组，但是<mark style="background: #FFB86CA6;">一般没有意义</mark>，就只有一个组，<mark style="background: #FFF3A3A6;">一般要配合使用</mark>
- `HAVING VS WHERE`:
	- 面向对象不同，执行阶段不同
	- `HAVING 只能对分组后的组，聚合字段和分组字段和与分组字段有对应关系的列进行过滤，若是对非聚合列过滤，则会出问题`
	- `WHERE 优先执行，效率更高，过滤后在进行分组，数据集更小`
- 结论：
	- 结论1：当过滤条件中没有聚合函数时，建议在` WHERE `中，有则放到` HAVING`
	- 结论2：`WHERE 一般效率更高`,例如：` JOIN `中是先对原始表进行筛选，然后关联

```sql
-- HAVING为gorup过滤

-- 查询各个部门中最高工资比10000高的部门信息

-- 一般聚合列都要出现在查询中，表明信息
select department_id,MAX(salary)
from employees
-- 报错，核心问题：执行顺序问题，一定不能把聚合函数放到wherer中
-- where为刚出来的表进行过滤，一切的基础是在where的表进行操作
where MAX(salary)
group by department_id;

select department_id,MAX(salary)
from employees
GROUP BY department_id
-- 使用HAVING专门为分组过滤
HAving MAX(salary) > 10000;

-- 不分组，就是一个整体的大组

select department_id,MAX(salary)
from employees
-- 使用聚合函数，任然要使用HAVING，对整体大组进行过滤
HAving MAX(salary) > 10000;

-- 查询部门是10，20，30，40这四个部门中最高工资比10000高的部门信息

-- 方式1：使用where:执行效率最高
-- 先过滤后在分组数据集更小
select department_id,MAX(salary)
from employees
where department_id IN(10,20,30,40)
group by department_id
HAVING MAX(salary) > 10000;

-- 方式2：HAVING一起使用条件
-- 虽然结果相同，但是HAVING是面向分组的，WHERE是面向from/JOIN出来的表的
select department_id,MAX(salary)
from employees
group by department_id
HAVING MAX(salary) > 10000 AND department_id IN(10,20,30,40);
```

## 5.3格式总结

- `sql92`
```sql
-- sql92语法
select .....
from  ......(外连接使用+)
WHERE 多表连接条件 AND 不包含聚合函数的过滤条件
GROUP BY 分组
HAVING 包含聚合函数的过滤条件
```

- `sql99`:
```sql
select distinct ....
from ...(left/right/inner/full) JOIN .... ON 多表连接条件
(right/left) JOIN ON 多表连接条件
WHERE 不包含聚合函数的过滤条件
GROUP BY ...分组
HAVING 包含聚合函数的过滤条件
ORDER BY... [ASC/DESC]
limit ....,.... /.... offset ....
```

- 执行过程：
	- 形成表格：生成虚拟表，不断变换
		- `from`:
			- 优先查询出表格，然后进行外连接笛卡尔积
			- `on`：通过连接条件对笛卡尔积进行过滤
		- `left/right/inner join`:
			- 进行左/右外连接
		- `WHERE`:
			- 对外连接的表格进行过滤
		- `GROUP BY`:
			- 根据组键进行分组
		- <mark style="background: #ABF7F7A6;">聚合函数计算：</mark>
			- 对每一个都进行聚合函数的操作
		- `HAVING`:
			- 对组进行过滤，常和` GROUP BY` 连用,进行聚合函数使用
	- 查询字段：
		- `select ...`:
			- 限制列，输出对应的列
			- 计算：
				- 聚合函数：引用即可
				- 函数
		- `DISTINCT`:
			- 过滤重复数据
		- `ORDER BY`:
			- 顺序
		- `LIMIT`:
			- 分页

- 本质：查询每一个流程中都是生成虚拟表，然后修改，最终得到一个结果集

## 5.3联系

---

- 基本设计：
	- 先看查询过后的一行是什么 ——》 分组结果
	- 一行有什么字段 ——》 分组补充
	- 参与的表格 ——》 表格 + 连接条件
	- 补充连接方式，看谁身上有所有字眼问题 ——》 什么外连接
	- 筛选条件

```sql
-- 查询公司员工工资最大值，最小值，总和

select MAX(salary),MIN(salary),SUM(salary)
from employees;

-- 查询job_id的员工的工资最大值，最小值，平均值，总和

select job_id,MAX(salary),MIN(salary),AVG(salary),SUM(salary)
from employees
group by job_id
;

-- 选择各个job_id的员工人数

select job_id,Count(1)
from employees
GROUP BY job_id;

-- 查询最高工资和最低工资的差值

select MAX(salary) - MIN(salary)
from employees;

-- 查询各个管理者手下的员工的最低工资，其中最低工资不能低于6000，没有管理者不计入
-- 工资——》列名
-- 员工，管理员 ——》表格 + 连接条件
-- 不低于 6000 ——》 筛选条件
-- 管理员手下——》分组
-- 管理员——》分组列，不计入——》having条件筛选组

select manager_id,MIN(salary)
from employees
WHERE manager_id IS NOT NULL
GROUP BY manager_id
HAVING Min(salary) >= 6000;

-- 查询所有部门的名字，location_id,员工的数量和平均工资，并按平均工资降序
-- 名字等 ——》 列名
-- 部门，员工，地点 ——》 表格 + 连接条件
-- 部门的所有员工，地点 ——》 分组
-- 所有 ——》 外连接 ——》可能导致一些地点的部门明明没有人但是count按条统计时有人，因为，外连接保留了
-- 排序 ——》 降序

select d.department_name,d.location_id,COUNT(1),AVG(salary)
from employees e right join departments d on e.department_id = d.department_id
GROUP BY d.department_id,location_id;

-- 修正：count统计不以*统计，按employee_id统计
select d.department_name,d.location_id,COUNT(employee_id),AVG(salary)
from employees e right join departments d on e.department_id = d.department_id
GROUP BY d.department_id,location_id
HAVING AVG(salary) IS NOT NULL;

-- 查询每个工种，每个部门的部门名，工种名和最低工资

select department_name , job_id
from employees e left JOIN departments d on e.department_id = d.department_id
group by department_name,job_id
union
select department_name , job_id
from employees e right JOIN departments d on e.department_id = d.department_id
group by department_name,job_id;

DESC jobs;
```

# 六.子查询

## 6.1子查询

---

- 子查询：查询结果中有插入另外一个查询，查询中有一个查询，对查询的嵌套

- 使用场景：
	- 往往需要从结果集中获得数据
	- 先获得一个结果，然后进行一个比较

```sql
-- 查询谁的工资比Abel高
-- 第一种方式：逐个进行查询，将第一个查询的结果做为第二个查询的条件
-- 非常慢，需要将第一个的传入第二个
SELECT
  salary
FROM
  employees
WHERE
  last_name = 'Abel';
SELECT
  last_name,
  salary
FROM
  employees
WHERE
  salary > 11000;
-- 第二种方式：自连接解决问题
-- 第一个表做为Abel的表格
-- 使用笛卡尔积方式实现的，可是表大的话，非常耗时
SELECT
  e2.last_name,
  e2.salary
FROM
  employees e1
  JOIN employees e2 ON e2.salary > e1.salary
WHERE
  e1.last_name = 'Abel';
-- 第一种方式:使用子查询
-- 第一种方式的缺点在要先查，然后传入，直接将比较中的数值使用查询结构替换
SELECT
  last_name,
  salary
FROM
  employees
WHERE
  salary > (SELECT salary FROM employees WHERE last_name = 'Abel');
```

- 基本概念：
	- 外查询/主查询：外部的查询，是一种相对的概念
	- 内查询/子查询：嵌套的查询，是一种相对的概念

- 执行时间：
	- 在主查询之前完成
- 注意事项：
	- 子查询要包括在括号内
	- 将子查询放在比较条件的右侧 ——》 一种规范，不美观
	- 单行操作符对应单行子查询，多行操作符对应多行子查询
		- 返回的数据条数不同，使用比较符有不同

- 分类：
	- 单行与多行：
		- 单行子查询：
			- 执行查询以后，返回只有一个数
		- 多行子查询：
			- 执行查询以后，返回有多个数
	- 内查询执行次数：
		- 相关子查询：
			- 子查询需要根据外查询执行的位置，跟着一起动
			- <mark style="background: #FFB86CA6;">外部的查询和内部查询相关</mark>，例如：外部是要看本员工的工资和部门工资相比，每次的外查询都有可能部门不同
		- 非相关子查询：
			- 子查询执行一次返回一个固定的值，一直使用这个值，只用执行一次即可
			- 例如：外部是看本员工工资与公司平均工资比较，公司平均工资不变

## 6.2单行子查询

---

- 内查询返回一个数据，外部使用这一个数据，外部使用这个字段使用对应的比较操作符
- 单行比较操作符：
	- `>/<`
	- `=/!=`
	- `>=/<=`
	- `<>`

- 子查询编写思路：
	- 从外往里写：
		- 按平常写
	- 从里往外写：
		- 先将内部的写完，复制到外部的条件中

```sql
-- 查询工资大于149号员工工资的员工信息
SELECT
  last_name,
  salary
FROM
  employees
WHERE
  salary > (SELECT salary FROM employees WHERE employee_id = 149);
  
-- 返回公司工资最少的员工的last_name,job_id,salary
SELECT
  MIN(salary)
FROM
  employees;
SELECT
  last_name,
  job_id,
  salary
FROM
  employees
WHERE
  salary = (SELECT MIN(salary) FROM employees);
  
-- 查询141号员工或174号员工的manager_id和department_id相同的其他员工
-- 从外向里查找
SELECT
  employee_id,
  last_name,
  manager_id,
  department_id
FROM
  employees
WHERE
  manager_id = (SELECT manager_id FROM employees WHERE employee_id = 141)
  AND department_id = (SELECT department_id FROM employees WHERE employee_id = 141)
  AND employee_id <> 141;


```

- 在`HAVING`中单行子查询

```sql
-- 查询最低工资大于50号部门最低工资的部门id和最低工资

select department_id,MIN(salary)
from employees 
group by department_id
HAVING MIN(salary) > (
                        select MIN(salary)
                        from employees
                        group by department_id
                        HAVING department_id = 50
                        );
```

- 在` case `中使用

```sql
                        
-- 显示员工的employye_id,last_name和location
-- 其中若是员工department_id与location_id为1800的department_id相同，则location为Canada，其余则为"USA"

select department_id
from departments
where location_id = 1800;

select employee_id,last_name,case department_id when (select department_id
                                            from departments
                                            where location_id = 1800) then 'Canada'
                                            else 'USA'  end "location"
  from employees;
```

- 子查询空值问题：
	- 内查询是`null`，返回`null`，使用`null`进行查询

```sql

  -- 空值问题

  from employees

```

## 6.3多行子查询

---

- 多行子查询：
	- 多行子查询操作集：
		- `IN`:等于列表中的任意一个
		- `ANY`:需要和<mark style="background: #FF5582A6;">单行比较操作符一起使用</mark>，和子查询返回的<mark style="background: #FF5582A6;">某一个值进行比较</mark>
		- `ALL`:需要和<mark style="background: #FFF3A3A6;">单行操作符一起使用</mark>，和子查询返回的<mark style="background: #BBFABBA6;">所有值及逆行比较</mark>
		- `SOME`:`ANY的别名`,功能一致
	- 单行返回值使用多行操作符也可以

```sql
-- 返回其他job_id中比job_id为'IT_PROG'部门任一工资低的员工的员工号，姓名,job_id以及salary

select last_name,employee_id,job_id,salary
from employees
WHERE job_id <> 'IT_PROG'
and salary < ANY (
                    SELECT salary
                    from employees
                    WHERE job_id='IT_PROG');

SELECT salary
from employees
WHERE job_id='IT_PROG';


```

- `mysql中不被允许的函数嵌套`:
```sql
-- 比任意一个平均都要最低的

-- 不允许嵌套
select MIN(AVG(salary))
from employees
group by department_id;
```
- 允许的使用`from`套<mark style="background: #FFB86CA6;">用一个查询结果，然后套用聚合函数</mark>：
```sql
-- 比任意一个平均都要最低的

select AVG(salary)
from employees
group by department_id;

-- 对于使用子查询形成一个表格，然后在其之上查询的必须为子查询的表格起一个别名
select MIN(avg)
from (
select AVG(salary) avg
from employees
group by department_id) from_zi;

select department_id
from employees
group by department_id
having AVG(salary) <= (select MIN(avg)
                        from (
                        select AVG(salary) avg
                        from employees
                        group by department_id) from_zi);

```
- 另一种解法：
```sql

-- 比任意一个平均都要最低的
select department_id
from employees
group by department_id
-- 比所有部门都要低，同时自己在里面，可能自己就是最小的，加上等号
HAVING AVG(salary) <= ALL (
                            select AVG(salary)
                            from employees
                            group by department_id);
```

- 多行子查询的问题：
	- 当子查询出现`null`不会使普通的多行子查询出现问题
	- 若是想对多行子查询<mark style="background: #ABF7F7A6;">进行`NOT`反向操作</mark>，<mark style="background: #BBFABBA6;">获得子查询操作的补集时，可能有危险</mark>
		- 若是子查询返回的数据集中有`null`，可能导致`not`操作的返回值都为`null`
		- 在子查询过滤掉`null`

注：
1. `mysql`中不可以对聚合函数进行套用，但是`Oracle`中支持
2. 对于使用`FROM`的子链接，一定要<mark style="background: #FFB86CA6;">注意重命名问题，不要命名冲突</mark>

## 6.4相关子查询

---

- 关联子查询：外查询在循环查询过程，子查询根据外部查询情况进行查询，有条件关联
- <mark style="background: #FFF3A3A6;">执行机制：</mark>
	- 先将子查询中关联到外部的字段或行送进去
	- 子查询对送进来的字段/行进行查询，返回值
	- 外部查询使用返回值做条件

```sql
-- 查询员工中工资大于本部门平均工资的员工的last_name,salary和department_id

-- 需要对外表进行查询的表进行命名，区分外表和子表中的数据
select last_name, salary , department_id
from employees out_e1 
WHERE salary > (
                    select AVG(salary)
                    from employees out_e2
                    WHERE out_e1.department_id = out_e2.department_id);

-- 将子查询设计为有部门和平均工资的一个表格，放到from中

select department_id,AVG(salary) inner_avg
from employees
group by department_id
;

select out_e.last_name,out_e.salary , out_e.department_id
from employees out_e JOIN (
                        select department_id,AVG(salary) avg_inner
                        from employees
                        group by department_id) inner_e
ON out_e.department_id = inner_e.department_id
WHERE out_e.salary > inner_e.avg_inner
;

```

- `ORDER BY` 子查询的使用：即使是表中没有的东西，可以通过关联关系是一行获得对应列的信息，也可以直接传递给`ORDER BY`，直接按这个返回值进行运算，排序
- 避免了多表查询，提高了效率
```sql
-- 查询员工的id,salary,按照department_name排序

select employee_id,salary
from employees e
ORDER BY (
            select department_name
            from departments d
            WHERE d.department_id = e.department_id);
```

- `select位置书写子查询`:
```sql
            
-- select位置书写

select employee_id,(
                        SELECT last_name
                        FROM employees inner_e
                        WHERE inner_e.employee_id = out_e.employee_id)
from employees out_e
;
select employee_id,last_name
from employees;
```

- 子查询位置:
	- `select`
	- `from`
	- `where`
	- `HAVING`
	- 增删改查的位置

## 6.5`EXISTS , NOT EXISTS`

---

- 用于查询子查询中是否有满足符合条件的行,逐行查找过程：
	- 有：返回`true`，同时保留输出这一行，停止向下查找
	- 没有：一直向下查找，直到最后，返回`false`，什么都不输出，这一行被去掉

```sql
-- 查询公司管理者的employee_id,last_name,job_id,department_id信息

-- 方法1：自查询
SELECT DISTINCT mgr.employee_id,mgr.last_name,mgr.job_id,mgr.department_id
from employees e , employees mgr
where e.manager_id = mgr.employee_id;

-- 方法2：自查询

select employee_id,last_name,job_id,department_id
from employees
where employee_id in ( 
                        select DISTINCT manager_id
                        from employees
                        );
                        
-- 使用EXISTS

select employee_id,last_name,job_id,department_id
from employees out_e 
where EXISTS(
                select *
                from employees inner_e 
                where out_e.employee_id = inner_e.manager_id);
```

- `NOT EXISTS`:和`Exists原理相反`,若是不在自查询中，就输出，否则，丢掉

注：
1. 性能：尽量写自查询，自查询 》 子查询

---

- 数据存储过程：

## 8.3操作控制

---

- `commit 和 ROLLBACK`:
	- `commit`:一旦执行后，数据就被永久的保存在数据库中了，数据库不可以回滚/撤销，<mark style="background: #ADCCFFA6;">永久保存到了数据库</mark>，若是想要消除，只能删除
	- `ROLLBACK`:一旦执行，可以回滚到最近的一次` commit` 操作，<mark style="background: #BBFABBA6;">不一定成功</mark>

- `TRUNCATE VS DELETE`:
	- 相同点
		- 都可以实现对表中所有数据的删除，同时保留表结构
	- 不同点：
		- `TRUNCATE`:
			- 一旦执行操作，表中数据全部清除，同时，<mark style="background: #FFF3A3A6;">数据不可以回滚</mark>
		- `DELETE`:
			- 一旦执行，表数据可以全部清楚(可以删除一部分数据，使用` where 过滤`)，同时，<mark style="background: #FF5582A6;">数据可以回滚，也可以不回滚</mark>
		- 背后机制：
			- `TRUNCATE`:
				- 背后是` DDL `：一旦执行操作，此类操作都是不可以回滚的，不受`SET AUTOCOMMIT = FALSE` 控制,<mark style="background: #ADCCFFA6;">被动有一个` commit `，默认执行，这个操作不受其影响</mark>
			- `DELETE`:
				- 背后是` DML` :一旦执行，默认也是不能回滚的，但是操作前可以执行` SET AUTOCOMMIT = FALSE` 就可以回滚，取消主动提交参数
			- `TRUNCATE`不用备份，效率高，速度快，<mark style="background: #ABF7F7A6;">但是容易造成事故，尽量少用</mark>

注：
1. `DDL`的执行要慎重
2. `ALTER DROP 一样不能回滚`

## 8.4阿里巴巴的开发手册规范

---

- 表名，字段名：
	- 小写
	- 禁止数字开头
	- 两个下划线间禁止出现单数字
	- 字段名称制定需慎重，避免后期修改
	- 不同单词，使用下划线分开
	- 禁止使用关键字做为名字
	- 必须有`id,gmt_create,gmt_modified`

		- `gmt_creat,gmt_modified 必须为DATETIME 前者是现在时主动创建 后者是过去分词表示被动更新`
	- 库名尽量和应用名称一致
	- 表的命名最好是遵循`业务名_表作用`

- `MYSQL8新特性`:
	- `DDL`的原子性特点：整条语句要么全部执行，要么任意一部分都不执行

```sql
Create DATABASE test;

use test;

CREATE TABLE book1(
    book_id INT
    , book_name VARCHAR(15)
    );

-- book2没有，但是执行到book2停止时，book1已经执行完了
-- 5.7时没有原子化，不会回滚，还不是原子化操作
-- 8.0进行原子化了，若是有一点不对，不仅停止，还将数据回到操作前
DROP table book1,book2;

show tables;
```

## 10.3浮点类型

---

- 浮点类型：
	- `FLOAT`:
		- 占字节少，范围小，4字节
	- `DOUBLE`:
		- 占字节大，范围大，8字节
	- `REAL`:
		- 默认就是`DOUBLE`，可以通过设置配置更改
	- 存储方式：`符号(S) + 尾数(N) + 阶码(E)` ——》因此符号有没有都对范围没有影响，范围单独使用一个位表示，没有符号就让他值等于0就可以了

- `mysql中不规范的写法`:
	- `float(m,n)`:
		- 表示一共`m`位/`整数位 + 小数位`,小数位占`n位`
		- <mark style="background: #D2B3FFA6;">小数若是超出指定，进行四舍五入</mark>，<mark style="background: #FFF3A3A6;">整数超出，报错</mark>，小数四舍五入后导致整数超出，也会报错
	- `DOUBLE(m,n)`
	- `8.0已经不推荐使用了，数据迁移时其他数据库可能会报错`

- `FLOAT,DOUBLE的误差大，几个小数相加算着是1，但是和定义的1使用等号比 sum(f1) = 1 还是不相等，无限接近`:使用更高精度`DECIMAL`
- `DECIMAL(m,n)`:<mark style="background: #ABF7F7A6;">常使用</mark>
	- 占用`m + 2字节`，<mark style="background: #ADCCFFA6;">以字符串形式存储</mark>
	- 不指定`m,n`，默认是`(10,0)`
	- 小数位置四舍五入，整数部分超出报错

- 位类型：
	- `BIT(M)`:
		- 不指定`M`,默认只能存储1位
		- 输出默认为二进制形式，若是想输出十进制对返回结果进行 `+ 0 默认转为10进制`，若是想用2进制使用`BIN()`，若是使用十六进制`HEX()`

```sql
use mytest1;

CREATE TABLE test01(
f1 bit(10),
f2 bit);

DESC test01;

INSERT INTO test01(f1)
values(10);

-- 报错，2在二进制中是2位
INSERT INTO test01(f2)
values(2);
INSERT INTO test01(f2)
values(1);

-- 默认以二进制输出
select * from test01;

-- 以十进制输出
select f1 + 0 from test01;
-- 以二进制输出
select bin(f1 + 0) from test01;
-- 以十六进制输出
select HEX(f1 + 0) from test01;
```

注：
1. 浮点类型一般就是用`DECIMAL`类型

# 十一.约束

## 11.1约束简介

---

- 约束(consranint)：
	- 广义：对数据的限制/约束
	- 狭义：<mark style="background: #BBFABBA6;">保证数据完整性，精确性，可靠性</mark>
		- 实体完整性：两条无法区分的数据
		- 域的完整性：字段的范围合理，对取值范围进行限制
		- 引用的完整性：一个表的字段表示部门，在另一个部门表中应该有对应部门
		- 用户自定义的完整性：用户名唯一，密码不为空等

- 约束：<mark style="background: #ADCCFFA6;">表级的规定</mark>，是对表的字段的<mark style="background: #ABF7F7A6;">强制限制</mark>

- 约束的分类：
	- 从列的个数来看：
		- 单列约束
		- 多列约束
	- 从作用范围来看：
		- 列级约束：此约束声明到对应<mark style="background: #FFF3A3A6;">字段的后面</mark>
		- 表级约束：此约束在表中的所有的字段都声明完以后，<mark style="background: #FFF3A3A6;">在所有字段后面声明约束</mark>
	- 约束的作用：
		- `not null`:非空约束
		- `unique`:唯一约束
		- `primary key`:主键约束
		- `foregien key`:外键约束
		- `check`:检查约束
		- `default`:默认值约束
- 添加约束方式：
	- `CREATE TABLE 添加约束`
	- `ALTER TABLE 添加/删除约束`

## 11.2非空约束

---

- 查看约束

- 非空约束：
	- `NOT NULL`
	- 针对单个列，<mark style="background: #FFB86CA6;">只能一个一个列的指定</mark>，不能一次性指定多个列
	- 默认<mark style="background: #FFF3A3A6;">所有列</mark>都是可以`null`的
	- 一个表可以有多个列是非空约束
	- 空字符串不是`null`,`0也不是null`

```sql
use atguigudb;

-- 查看约束
-- 在information数据库中查询，是系统自带的一个表格，报错约束信息
-- 有的约束可能不显示

select * from information_schema.table_constraints
where table_name = 'test1';

-- 限制字段不允许为空，没有设置非空约束就可以是空
-- 默认是都可以为null

-- CREATE TABLE是添加非空约束

CREATE DATABASE dbtest13;

use dbtest13;

-- 只能使用列级约束，不能进行一次性组合指定
CREATE TABLE test01(
id INT NOT NULL,
last_name VARCHAR(15) NOT NULL,
email varchar(25) ,
salary DECIMAL(10,2)
);

-- 查看表的结构

DESC test01;

-- 添加值

-- last_name为null，失败
INSERT into test01(id,last_name,email,salary)
values(2,null,2222,23442);
-- 正确写法
INSERT into test01(id,last_name,email,salary)
values(2,'fa',2222,23442);
-- 这一行没有指定添加一些字段的值，有默认值使用默认值，没默认值，使用null
INSERT into test01(id,email)
values(2,2222);

-- 更改数据
-- 报错，即使是更改操作也受限制，无法将限制字段改为空
update test01 
SET last_name = null 
where id = 2;

-- 使用ALTER TABLE添加约束

/*
    两种情况
        1.现有的表格中的email字段中有几行是null值 ，此时不允许修改，表中数据不符合限制
        2.现有表格中的email字段都是not null ，此时可以修改
*/
ALTER TABLE test01 
MODIFY email VARCHAR(25) NOT NULL;

-- 使用ALTER TABLE删除非空约束,本质就是使用重新声明字段覆盖掉就声明

ALTER TABLE test01 
MODIFY email VARCHAR(25)  NULL;
```

## 11.3唯一性约束

- 唯一性约束：
	- `UNIQUE`
	- 被声明的字段，<mark style="background: #ADCCFFA6;">不允许有多个一样的值，但是`null`可以</mark>
	- 多列约束：可以加载多个列上，<mark style="background: #FFB8EBA6;">验证是否一致时按一个组的值验证</mark>
- 表级约束命名：
	- 放到所有字段后进行表级约束声明`CONSTRAINT 命名 约束/约束`
		- 使用命名的：约束的名字是命名的
		- 没有命名：使用字段名

```sql
-- 唯一约束

-- 使用列单独标记
CREATE TABLE test02(
id INT UNIQUE, # 列级约束
last_name VARCHAR(15),
email VARCHAR(25) UNIQUE,
salary DECIMAL(10,2)
);

-- 表级约束
CREATE TABLE test02(
id INT UNIQUE,
last_name VARCHAR(15),
email VARCHAR(25) ,
salary DECIMAL(10,2),
# 表级约束:关键字 命名(约束名_表格_字段) 约束 ——》规范写法，可以不写，自动命名
# 删除需要对应的命名
CONSTRAINT uk_test_02_email UNIQUE(email)
);

-- 查看表结构
DESC test02;

-- 查看表格的约束，非空没有显示，唯一有显示
-- 可以看到约束的名字没有命名时和列名一致，若是有命名，按命名算
select * from information_schema.table_constraints
where table_name = 'test02';

INSErt into test02(id,last_name,email,salary)
VALUES(1,'job','fafa',234);
-- 失败，不能重复的字段重复
INSErt into test02(id,last_name,email,salary)
VALUES(1,'job','fafa',234);

-- 多个null不影响
INSErt into test02(id,last_name,email,salary)
VALUES(2,'job',null ,234);
INSErt into test02(id,last_name,email,salary)
VALUES(1,'job',null,234);

-- update也不能改为重复的

-- 使用ALTER TABLE添加

-- 方式1：按表级约束添加

-- 注意若是表格中的数据冲突，无法添加
ALTER TABLE test02 ADD UNIQUE(last_name);

ALTER TABLE test02 ADD CONSTRAINT uk_test02_sal UNIQUE(salary);

-- 方式2：按列级约束添加
ALTER TABLE test02 MODIFY id INT UNIQUE ;

-- 复合的唯一性约束，多列形成一个组合不能重复
CREATE TABLE USER(
id INT,
`name` VARCHAR(15),
`password` VARCHAR(25),
# 表级约束，只能使用表级约束进行约束，只在一个字段上是针对列，不是针对组合
CONSTRAINT uk_user_name_pwd UNIQUE(`name`,`password`)
);

DESC USER;
```

- 删除唯一性约束：
	- 添加唯一性约束的列，同时会<mark style="background: #FFF3A3A6;">自动添加一个索引——唯一索引</mark>
	- 删除唯一约束<mark style="background: #FFF3A3A6;">只能通过唯一索引方式删除</mark>
	- <mark style="background: #BBFABBA6;">删除是需要指定唯一索引的名字，唯一索引名就是唯一约束名</mark>
	- 若是为指定命名
		- 单列：默认字段名
		- 多列：第一个字段名
		- 命名：指定的命名

- 查询索引名：
```sql
select * from information_schema.table_constraints
where table_name = 'test01';
```

- 删除唯一约束
	- `ALTER TABLE 表名 DROP INDEX/CONSTRAIN 约束名`
```sql
-- 删除唯一性约束

-- 方法1：直接删index

ALTER TABLE USER 
DROP INDEX uk_user_name_pwd;

-- 方法2：直接删constraint

ALTER TABLE USER
ADD CONSTRAINT uk_user_name_pwd UNIQUE(`name`,`password`);

ALTER TABLE USER 
DROP CONSTRAINT uk_user_name_pwd;
```

注：
1. 列属性：非空，默认值不是依赖索引定义的，而是由列定义的，不能使用删除索引方式删除，只能使用新声明覆盖旧声明
2. 约束依赖索引定义的无法使用新声明覆盖，只能使用`ALTER TABLE 表名 DROP INDEX/CONSTRAIN 约束名 `删除

## 11.4主键约束

---

- 主键约束：
	- 一个表需要<mark style="background: #FF5582A6;">一个/一组字段区分一行</mark> ——》 保证实体完整性
	- 用来唯一标识表中一行的记录 ——》主键
	- 特点：唯一性 + 非空
	- 位置：
		- 列级别/表级别
		- `ALTER`
	- <mark style="background: #ABF7F7A6;">一个表格只能有一个主键</mark>
		- 主键约束 ——》主键索引，存储表格数据结构的是`B+树`,其通过主键创建，若是多个不知道按谁创建

- 主键的使用
	- 主键声明：
		- 单列主键
		- 复合主键
	- 主键的命名：
		- 强制命名为`PRIMARY KEY`，无法自己命名
		  ![[图片/Pasted image 20260919192644.png]]
	- 实现：
		- <mark style="background: #FFF3A3A6;">主键约束创建同时创建一个主键索引，底层的`B+`树依靠主键创建</mark>
	- 创建：
		- `CREATE`
			- 列级主键
				- 单列主键
			- 表级主键
				- 单列主键
				- 复合主键
		- `ALTER`:
			- 对应的字段必须没有空且不能重复
			- <mark style="background: #BBFABBA6;">由于主键唯一 ——》 原来的表中必须没有主键，有则删除</mark>

```sql
-- 表中最多只有一个主键约束

-- 使用列定义约束
-- 主键无需命名，只要创建就是用PRIMARY做为名字
CREATE TABLE test03(
# 列级约束
id INT PRIMARY KEY,
# 若是oracle使用主键，使用类型2即可
last_name VARCHAR(15),
salary DECIMAL(10,2),
email VARCHAR(25)
);

-- 查看约束
SELECT * FROM information_schema.table_constraints
where table_name = 'test03';

-- 尝试为主键命名
CREATE TABLE test04(
id INT,
last_name VARCHAR(15),
salary DECIMAL(10,2),
email VARCHAR(25),
# 尝试为主键约束命名
CONSTRAINT pk_test04_id PRIMARY KEY(id)
);

-- 查看约束：主键名依旧不会改变，但是不会报错
SELECT * FROM information_schema.table_constraints
where table_name = 'test04';

-- 主键：非空且唯一

insert into test03(id,last_name,salary,email)
VALUES(1,'小明',123212,'fad');
-- 若是id同，报错，不可重复
insert into test03(id,last_name,salary,email)
VALUES(1,'小明',123212,'fad');
-- 不赋值，默认使用默认值，没有就是null,报错，不可以使用null
insert into test03(last_name,salary,email)
VALUES('小明',123212,'fad');

-- 复合主键约束:只能使用表级约束，对主键进行指定字段

CREATE TABLE user1(
id INT,
`name` VARCHAR(15),
`password` VARCHAR(25),
# 既然没有办法命名，就没有必要在用constraint了
PRIMARY KEY(`name`,`password`)
);

insert into user1
values(1,'小明','123123');
-- 若是复合主键，有一个值为null也不可以，也要满足组合不重复的特点
insert into user1
values(1,null,'123123');

-- 使用ALTER添加主键

-- 不要轻易删除主键，否则依据主键创建的b+树就没有了
-- 删除主键以后，非空性质仍然保存，不必记忆
ALTER TABLE user1
DROP PRIMARY KEY;

ALTER TABLE user1
ADD PRIMARY KEY(id);

DESC user1;
```

## 11.5自增列

---

- 使某个字段自动增加，一般添加到主键/唯一性约束上，<mark style="background: #BBFABBA6;">一个表只能有一个自增列</mark>
- 使用场景：
	- 必须使整型数据
	- 此字段为唯一标识符或顺序值时，可设置自增长
- 不对自增列进行赋值，就自动增加
- 本质：列属性

```sql
-- 自增长列

CREATE TABLE test01(
-- 一般用在主键上，主键必须有值，一般又是顺序值，让主键自增长
id INT PRIMARY KEY AUTO_INCREMENT,
last_name VARCHAR(15)
);

-- 主键为自增长，不必为其赋值
-- 初始第一个值时1，从0加上来
insert into test01(last_name)
values('tom');

-- 若是为其赋值

-- 赋值为0或null,自动使用原来最大的值添加
insert into test01(id,last_name)
values(0,'tom');

-- 若是不用0或null，则按赋值算，同时自动排序，将数值大的放到前面，确保自增长是按最大的来
insert into test01(id,last_name)
values(-10,'tom');


select * from test01;

-- 修改自增列

ALTER TABLE test01 
MODIFY id INT;

-- 增加自增列
ALTER TABLE test01
MODIFY id INT AUTO_INCREMENT;
```

- 特殊机制：自增长的下一个内容和字段无关，即使删除最大，仍然有地方保持着下一个值的内容
  ![[Excalidraw/数据库总览/数据库重构/基础知识/一.基础操作/1.1基础语句/十一.约束/11.5自增列/自增长大小|自增长大小]]
	- `5.7`:
		- 自增长的下一个值放到内存中维护，若是重启，重新到字段中找，然后将最大的放入维护
	- `8.0`:
		- 自增长的下一个值放到日志中维护，不随着重启改变

注：
1. 若是第一次插入时确定了自增列的值，从这个值开始递增
2. 若是指定的值大于自增列维护的值，更新自增列维护的值为`指定的值 + 1`
3. 一个表格中只能加一个自增列，一般是主键加

## 11.6外键

---

- 多个实体间由有各种各样的关系 ——》 使用外键联系起来，<mark style="background: #BBFABBA6;">一般是关联到主键上</mark>
- 关系：
	- 主表：被关联的表
	- 从表：关联的表，被关联的列只能是主表的别关联列的值
- <mark style="background: #ADCCFFA6;">外键约束可以有多个</mark>

- 从表的<mark style="background: #FFF3A3A6;">外键必须关联到主表的主键或唯一约束上</mark>，<mark style="background: #BBFABBA6;">必须唯一</mark>，<mark style="background: #FFF3A3A6;">能够确定是对应哪一条表项的关系</mark>

- <mark style="background: #BBFABBA6;">外键是表级约束</mark>，没有列级约束，<mark style="background: #FF5582A6;">所以外键必须命名</mark>，若是不命名，会自动命名，但是不知道是什么，很难删除外键

- 创建表格时，若是创建外键，需要先创建主表

- <mark style="background: #D2B3FFA6;">若是想要删除主表和从表，想要先删除从表，然后主表，同理，主表的数据被从表依赖时，此表项不可以删除，想要先删除外键对应的表项</mark>

- <mark style="background: #ABF7F7A6;">从表</mark>中创建外键约束的列可以和<mark style="background: #FFF3A3A6;">主表</mark>对应的列名可以不一致，<mark style="background: #ABF7F7A6;">但是类型必须一致</mark>，而且<mark style="background: #FFF3A3A6;">可以创建多个外键</mark>

- <mark style="background: #FFB8EBA6;">当创建外键约束时</mark>，系统默认会在<mark style="background: #FFF3A3A6;">所在列上建立普通的索引</mark>，但是删除外键时，索引不会自动删除，需要手动删除

- 外键关联到主表时，外键的列应该和主表的主键时一致的，主表是主键组，外键也应该是一个组，对应主表，也可以是关联到一个不重复的列上

- 从表和主表同时被限制 
	- 从表：将<mark style="background: #FFB86CA6;">主表的对应的值做为集合</mark>，只能添加对应的值
	- 主表：对应的列不能轻易的动，<mark style="background: #FFF3A3A6;">修改/删除要确定对应子表中没有引用对应行的值</mark>

- 约束等级：
	- `CASCADE`:
		- 主表进行`update/delete`记录时，将从表匹配记录的列<mark style="background: #ADCCFFA6;">同步更改</mark>
	- `SET NULL`:
		- 主表修改时，将从表上匹配记录的列设为`null`,但是注意<mark style="background: #FFF3A3A6;">从表的外键列不能为`not null`</mark>
	- `NO action`:
		- 若是从表中有匹配的记录，则不允许对主表对应的列进行修改操作
	- `Restrict`:默认
		- 同`no action`，都是立即检查外键约束
	- `set default`:
		- 若是主表有修改操作，从表的外键设置为对应的默认值
- 推荐：
	- `on update`:`casade`
	- `on delete`:`set null`

```sql
use atguigudb;

-- 创建主键
create table dept01(
dept_id INT,
dep_name varchar(15)
);

-- 添加唯一约束
ALTER TABLE dept01
ADD UNIQUE(dept_id);

-- 添加主键
ALTER table dept01
ADD PRIMARY KEY(dept_id);

-- 查看主表结构
DESC dept01;

-- 创建从表

create table emp01(
emp_id INT PRIMARY KEY AUTO_INCREMENT,
emp_name varchar(15),
department_id int,

# 表级约束
# 务必进行命名：约束名_从表_主表_外键的列
# 若是连接到的主表的列不是主键一般是唯一性约束，会报错
constraint fk_emp1_dept_id FOREIGN KEY(department_id) references dept01(dept_id)
);

-- 查看表结构
DESC emp01;

-- 查询索引信息
select * from information_schema.table_constraints
where table_name = 'emp01';

-- 为从表赋值
-- 若是主表对应列内没有对应的值，不能添加，只能添加有的值，类似集合
insert into emp01
values(1001,'tom',1001);

-- 为主表赋值
insert into dept01
values(1001,'tom');
insert into dept01
values(101,'tom');

-- 删除主表中被引用的值
-- 不能删除，被引用了
delete from dept01
where dept_id = 1001;
-- 可以删除，没有被引用
delete from dept01
where dept_id = 101;

-- 修改主表数据
-- 不可以修改被关联的列，为被关联的列可以
update dept01
set dep_name = 'toom'
where dept_id = 1001;

-- 使用alter添加外键约束
ALTER TABLE emp01
ADD FOREIGN KEY emp01(department_id) REFERENCES dept01(dept_01);

-- 删除外键

ALTER TABLE emp01
drop FOREIGN KEY fk_emp1_dept_id;

-- 手动删除索引

-- 查看表格中的索引
SHOW INDEX FROM emp01;

-- 删除
-- 索引默认为外键名
Alter TABLE emp01
drop INDEX fk_emp1_dept_id;
```

 - 阿里规范：
	 - 不准使用外键和级联

注：
1. <mark style="background: #CACFD9A6;">自动创建索引的名字和外键一致</mark>
2. 外键消耗资源，各个实体的关系可以不使用外键，通过自觉来解决，可以在逻辑层解决

## 11.6自检查

--- 

- 检查某个字段是否符合某个要求，一般是范围

- `5.7不支持自检查`,`8.0支持`

```sql
use atguigudb;

CREATE TABLE test10(
id INT,
last_name VARCHAR(15),
# 会检查所有修改操作，看是否符合条件
salary DECIMAL(10,2) check(salary > 20000)
);

-- 插入数据
-- 不符合，报错
insert into test10
VALUES(10,'fa',112);

insert into test10
VALUES(10,'fa',112123);


-- 修改数据
-- 报错，修改后不符合条件
update test10
SET salary=1000
where 1;

select * from test10;
```
