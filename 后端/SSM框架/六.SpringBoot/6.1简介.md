# 一.引入

## 1.1导入

---

- `spring 使用范围广，功能全`但是要写配置文件，配置类 ——》 框架整合太过复杂
	- 单体项目：整合文件只写1次
	- 微服务项目：将单体项目拆分为n个项目，整合文件写`n次`
- `springboot`框架出现来解决次问题
	- `spirng`:`spring`家族的产品
	- `boot`:<mark style="background: #FFB86CA6;">快速启动</mark>，不写配置文件就能快速启动
- `springboot`可以让项目写少量甚至不写配置文件就能启动
	- 开箱即用，<mark style="background: #ADCCFFA6;">设置合理的默认值</mark>，但是一些<mark style="background: #ABF7F7A6;">根据需求的配置</mark>仍需要进行适当调整
	- 提供一系列大型项目通用的非功能性出现，例如：嵌入式服务器(`tomcat`)，安全性，指标等
	- <mark style="background: #BBFABBA6;">约定大于配置</mark>，只要根据约定来写，基本不需要进行配置

- 总结：<mark style="background: #FFF3A3A6;">简化开发，简化配置，简化整合，简化部署，简化监控，简化运维</mark>

## 1.2版本控制

---

- 版本要求：
	- `maven`:`3.6.3更高的版本`
	- `tomcat`:`10.0+`
	- `Servlet`:`9.0+`
	- `JDK:17+`

## 1.3快速入门

----

- 开发流程：
	- 创建`maven`工程
	- 添加依赖
		- `springboot`父工程依赖
		- `web启动依赖`
	- 编写启动类：
		- 一个项目被拆分为多个模块，单独测试使用启动类
	- 编写处理器`Controller`
	- 启动项目

- 编写依赖:
	- 模块继承`spring-boot-starter-parent这个依赖`，其的父工程还有父工程，是`spring`,不在继承父项目——》父项目设为空项目
	- 导入启动器的依赖，此依赖不写版本，完全继承父项目的依赖

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <parent>
        <!--指定spring boot的包为父工程即可-->
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-parent</artifactId>
            <version>3.0.5</version>
    </parent>

    <groupId>com.atguigu</groupId>
    <artifactId>springboot-base-quick-01</artifactId>
    <version>1.0-SNAPSHOT</version>

    <dependencies>
        <dependency>
            <!--导入对应的启动器-->
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
        </dependency>
    </dependencies>

</project>
```

注：
1. 启动类/根包下面所处的包下面都默认扫描组件

# 二.详细讲解

## 2.1快速入门细节

---

- `springboot 的父工程依旧是 spring(专门配置了依赖)里面已经配置好许多依赖，不冲突`
	- 导入的内容：
		- 依赖的版本管理
		- `java编程的一些配置：UTF-8`
		- 插件版本配置管理
		- 具体的依赖：
			- 导入具体的启动器，导入，不用写版本，自动使用父工程的依赖管理

- 导入另外的依赖：
	- 启动器：
		- 相当于<mark style="background: #FFB86CA6;">整合包</mark>，`spring-boot-starter-web`将`web`需要的依赖都到导入
		- <mark style="background: #FFB8EBA6;">自动配置</mark>一些`web`的配置，使用默认配置
		- 提供方：
			- `springboot`:[官方文档]([https://docs.spring.io/spring-boot/docs/current/reference/html/using.html#using.build-systems.starters](https://docs.spring.io/spring-boot/docs/current/reference/html/using.html#using.build-systems.starters))
			- 第三方：
				- 自定义
				- `命名....`
		- 本质：
			- 人为按照开发场景对依赖的打包，同时`maven`会对其中的依赖进行传导，获得依赖的依赖
		- 创建启动类
			- 注解`SpringBootApplication`
				- 本身就是一个配置类`SpringBoot ——》加入@Bean，可以写到启动类中`
				- 上面有`@EnableAutoConfiguration`——》 有对应的类就进行<mark style="background: #FFB86CA6;">自动加载其他配置类</mark>
				- `@ComponenScan`自动扫描当前类所在的包及子包的类
			- 启动`run(当前类.class,args)`：
				- 调用`main方法`创建`IOC`容器
				- 启动内置的`Web容器`
	- `springboot`依赖没有的依赖
		- 启动器
			- 第三方
			- 官方
		- 单独的依赖

## 2.2统一默认配置

---

- `springboot`下想进行统一的配置管理——》写到`application.properties/yml`中
	- 所有配置文件都是从这里读取配置，对这个文件夹下的文件进行包含读取
		- 数据库信息
		- 服务器信息
		- ...
	- 配置方式：
		- `springboot`固定的参数配置 ——》 固定的`key`
			- 使用`springboot 固定的key对springboot的组件进行配置`
		- 自定义的`key`
			- 配置文件中配置后，使用`@Value等`进行读取
			- 查看官方文档:[官方文档](https://docs.spring.io/spring-boot/appendix/application-properties/index.html)

- 示例：
```properties
# 官方提供的key进行赋值  
  
server.servlet.context-path=/fads  
  
# 自己定义key进行复制1  
  
name=fasd
```

## 2.3yaml配置

---

- 原`properties复杂`:
```properties
# web文件设置服务端口号 项目路径

# properties
# key=value

# 所有的配置 ——》application ——》 springboot ——》所有配置进行操作 ——》不能重复，按层命名
# key多层命名，写起来很麻烦 ——》 使用yaml文件

server.port=8080
server.servlet.context-path=/myapp
```

- 使用`yaml`
```yaml

# 原properties中多层命名，yml文件为了简单使用多层命名格式
# 自动继承上一层的命名，加上一个Tab即可
# 可读性好
# 书写属性value时要空一格写

server:
  #默认为server.prot
  port: 8080
  #默认继承server.servlet
  servlet:
    #默认继承servet.servlet.context-path
      context-path: /myapp
      
#表示集合
name:   
  - 小明  
  - 小红  
  - 二狗子

#server.port=8080
#server.servlet.context-path=/myapp
```

- `yaml`：
	- 一种层次化的标记语言
	- 有层次：
		- 下一个层次默认继承上一层的属性
		- 回车 + 空格
	- 语法：
		- 缩进表示层级，回车自带空格
		- 集合使用`-`表示
		- `key/value 间使用:+空格表示`
		- 文件后缀:`yml,yaml`
		- 语法严格
	- 读取方法：
		- 使用`@Value`
			- 限制多
				- 不能获得`Bean`
				- 不能获得集合
		- 使用自动批量配置
			- `@ConfigurationProperties`
				- 注解中设置实体类中的公共前缀
				- 若是加上公共前缀后相同，注入

- 读取配置

## 2.4多环境配置

---

- 设计项目,可能需要多个环境，配置环境不同
	- 测试
	- 开发
	- 生成

- 环境修改需要手动更改环境，设计多个环境：
	- 使用配置文件
		- 命名必须为`application-xxx`
		- <mark style="background: #FFF3A3A6;">配置文件中`application`必须存在</mark>，仍然使用这个配置
		- 使用<mark style="background: #ABF7F7A6;">主配置文件中指定使用哪个配置文件</mark>`active属性指定`,指定中不需要写`application.yaml`
	- 作用:
		- 拆分框架
			- `application.yaml`：<mark style="background: #ABF7F7A6;">融合各个框架，可以融合多个框架</mark>，指定属性时使用逗号隔开
			- `application-xxx.yaml`:做为分块的配置，例如数据库，数据源等
		- 配置环境：
			- 配置多个环境
			- 使用哪个环境融合哪个环境

- 读取文件：
```yaml
spring:
  profiles:
    active: druid,test
```

注：
1. 若是多个文件中有同一个`key`，则外部为准，<mark style="background: #FF5582A6;">外部覆盖内部</mark>
2. 项目打成`jar包时`，可以在启动项目时指定融合哪个包`--active=xxx`

## 3.2druid整合

---

- 目前官方已经退出适配`spring3`的`druid`了，直接使用`druid-spring-boot-starter`即可

```java
<dependency>
    <groupId>com.alibaba</groupId>
    <artifactId>druid-spring-boot-3-starter</artifactId>
    <version>1.2.23</version> <!-- 建议使用最新稳定版 -->
</dependency>
```

- 整合流程：
	- 导入依赖
	- 启动类
	- `application.yaml`配置对应的信息
	- 写`controller`
	- 启动测试
	- 解决`springboot3和druid的兼容问题，手动配置`(现在可以了，官方版本完善了)

- 对`druid`进行信息配置：
```yaml
spring:
  datasource:
    # 连接池类型 
    type: com.alibaba.druid.pool.DruidDataSource

    # Druid的其他属性配置 springboot3整合情况下,数据库连接信息必须在Druid属性下!
    druid:
      url: jdbc:mysql://localhost:3306/day01
      username: root
      password: root
      driver-class-name: com.mysql.cj.jdbc.Driver
      # 初始化时建立物理连接的个数
      initial-size: 5
      # 连接池的最小空闲数量
      min-idle: 5
      # 连接池最大连接数量
      max-active: 20
      # 获取连接时最大等待时间，单位毫秒
      max-wait: 60000
      # 申请连接的时候检测，如果空闲时间大于timeBetweenEvictionRunsMillis，执行validationQuery检测连接是否有效。
      test-while-idle: true
      # 既作为检测的间隔时间又作为testWhileIdel执行的依据
      time-between-eviction-runs-millis: 60000
      # 销毁线程时检测当前连接的最后活动时间和当前时间差大于该值时，关闭当前连接(配置连接在池中的最小生存时间)
      min-evictable-idle-time-millis: 30000
      # 用来检测数据库连接是否有效的sql 必须是一个查询语句(oracle中为 select 1 from dual)
      validation-query: select 1
      # 申请连接时会执行validationQuery检测连接是否有效,开启会降低性能,默认为true
      test-on-borrow: false
      # 归还连接时会执行validationQuery检测连接是否有效,开启会降低性能,默认为true
      test-on-return: false
      # 是否缓存preparedStatement, 也就是PSCache,PSCache对支持游标的数据库性能提升巨大，比如说oracle,在mysql下建议关闭。
      pool-prepared-statements: false
      # 要启用PSCache，必须配置大于0，当大于0时，poolPreparedStatements自动触发修改为true。在Druid中，不会存在Oracle下PSCache占用内存过多的问题，可以把这个数值配置大一些，比如说100
      max-pool-prepared-statement-per-connection-size: -1
      # 合并多个DruidDataSource的监控数据
      use-global-data-source-stat: true

logging:
  level:
    root: debug
```

- 兼容`springboot3`:
	- 缺少自动装配的配置文件，需要手动在resources目录下创建META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports，文件内容如下:
```
com.alibaba.druid.spring.boot3.autoconfigure.DruidDataSourceAutoConfigure
```
