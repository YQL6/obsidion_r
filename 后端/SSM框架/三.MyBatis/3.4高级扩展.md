# 一.批量映射优化

## 1.1进行批量对应

---

- 问题：多个映射文件一个一个书写 ——》 麻烦
- 解决：使用批量映射

- 配置文件
```xml
<!-- 注册 Mapper 映射文件 -->
    <!--可以注册多个Mapper映射文件-->
<!--    <mappers>-->
<!--        &lt;!&ndash;映射文件位置指定&ndash;&gt;-->
<!--        <mapper resource="mappers/EmployeeMapper.xml"/>-->
<!--    </mappers>-->
    <!--为了避免多个mapper文件的书写
    提供了mapper批量指定的功能：
        1.要求xml文件和mpaper接口和Mapper的xml文件命名一致
        2.要求最终打包后的位置一致：同时指定最终的地址包
            resource和java都是放到类路径下面，但是是两个包下面：
                com的指定 ——》 java下面的包拿出来
                mappers和config ——》 将resources的包拿出来放到classes下
                xml和mapper不是一个包下
           解决问题：
                1.将xml文件放到java的mapper文件夹下面这样两者是一致的包，可以指定，但是maven架构默认不打包xml文件/非java文件，使用pom文件指定打包的内容
                2.将resources下面创建一个和mapper路径一致的包，这样打包时会将同路径的包放到一起
           注意问题：创建文件夹时：
                com.atguigu.MyBatis:是一个文件夹没有结构，仅是文件夹名字
                com/atguigu/MyBatis:是多个文件夹，有结构，使用/隔开不同结构的文件夹
                com创建后跟着atguigu创建接着创建Mybatis:和第二种效果一致
                -->
    <mappers>
        <!--将com.atguigu.MyBaits.mapper文件夹下的所有文件对应的映射文件都加入-->
        <package name="com.atguigu.MyBaits.mapper"/>
    </mappers>
```

# 二.插件

## 2.1插件机制

---

- `mybatis`提供了可扩展的插件机制，可以用于语句执行过程中进行拦截，并允许自定义程序来拦截或修改`sql语句`
  ![[Excalidraw/后端/SSM框架/三.MyBaits/3.4高级扩展/二.插件/2.1插件机制/插件机制|插件机制]]

- 插件执行时机：

| 对象                 | 作用                       | 常用场景                               |
| ------------------ | ------------------------ | ---------------------------------- |
| `Executor`         | SQL 执行器，负责增删改查事务         | 多租户、修改执行逻辑                         |
| `StatementHandler` | 语句处理器，预编译 SQL、设置参数       | PageHelper 分页、SQL 改写、打印完整 SQL（最常用） |
| `ParameterHandler` | 给 PreparedStatement 设置参数 | 参数加密                               |
| `ResultSetHandler` | 把查询结果封装成 Java 对象         | 结果解密、字段转换                          |

- 本质：
	- 对`mybatis封装的四个对象进行增强封装AOP`
	- <mark style="background: #FF5582A6;">AOP思想</mark>

- 分类：
	- 配置后注解使用：
		- 使用插件前不需要传入参数，直接使用
	- 配置后传入参数
		- 使用插件前需要传入参数，放到`LocalThred`中，方便跨层使用
		- 若是没有传入参数，不生效，若是自己写的可以抛出错误

- 包装顺序：
	- 配置顺序

## 2.2分页插件

---

- 使用插件:
	- 引入第三方的插件
	- 在mybatis中进行插件配置，注册插件
	- 使用插件

- 引入第三方插件：
```xml
      <!-- Java + Spring Boot -->
        <dependency>
            <groupId>com.github.pagehelper</groupId>
            <artifactId>pagehelper-spring-boot-starter</artifactId>
            <version>2.1.0</version>
        </dependency>
```

- 注册插件:
```xml
  <!--在mybatis内部配置吵架呢，可以进行sql语句进行拦截了-->
    <!--插件位置位于typeAliases后面-->
    <plugins>
        <!--使用的是分页插件
            注意不能在sql语法中添加;，否则会直接将limit加到;后面
            -->
        <plugin interceptor="com.github.pagehelper.PageInterceptor">
            <!--插件语法面对的数据库类型
                name:参数名
                value:参数值
            -->
            <property name="helperDialect" value="mysql"/>
        </plugin>
    </plugins>
```

- 使用插件：
```java
import com.atguigu.MyBaits.mapper.EmployeeMapper;
import com.atguigu.MyBaits.pojo.Employee;
import com.github.pagehelper.PageHelper;
import com.github.pagehelper.PageInfo;
import org.apache.ibatis.io.Resources;
import org.apache.ibatis.session.SqlSession;
import org.apache.ibatis.session.SqlSessionFactory;
import org.apache.ibatis.session.SqlSessionFactoryBuilder;
import org.junit.jupiter.api.AfterEach;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;

import java.io.InputStream;
import java.util.ArrayList;
import java.util.List;

public class test {
    SqlSession sqlSession;
    InputStream in ;
    @BeforeEach
    public void before() throws Exception {
        in = Resources.getResourceAsStream("mybatis-config.xml");
        SqlSessionFactory sqlSessionFactory = new SqlSessionFactoryBuilder().build(in);
        sqlSession =  sqlSessionFactory.openSession();
    }
    @Test
    public void test() throws Exception {
        EmployeeMapper mapper = sqlSession.getMapper(EmployeeMapper.class);
        //调用分页插件，参数：第几页，显示数量
        //自动间查询数据封装到pageInfo的分页实体类中，一共多少也，一共多少条等信息
        //对threadlocal中放一个page对象，对紧挨着的查询语句拦截，仅对一个sql生效
        PageHelper.startPage(1, 5);
        List<Employee> list = mapper.queryAllEmployee();
        System.out.println(list);
        PageInfo<Employee> pageInfo = new PageInfo<>(list);
        /*
        * 获取当前页的数据
        * 当前页的数据
        * 总页数
        * 总条数
        * 是否有下一页
        * 容量大小
        * 第几页
        * */
        List<Employee> employees = pageInfo.getList();
        System.out.println("当前页的信息数据" + employees);
        int pages = pageInfo.getPages();
        System.out.println("当前的总页数为" + pages);
        long total = pageInfo.getTotal();
        System.out.println("总条数为:" + total);
        int pageNum = pageInfo.getPageNum();
        System.out.println("当前页数为：" + pageNum);
        int pageSize = pageInfo.getPageSize();
        System.out.println("容量大小为:" + pageSize);
    }
    @AfterEach
    public void after() throws Exception {
        sqlSession.close();
        in.close();
    }
}
```

## 2.3mybatis日志使用

---

- `mybatsi`没有内部日志，可以使用第三方日志，强制要求项目统一日志
	- 通过配置`<setting />`指定日志接口是什么，一般使用`SLF4j`,底层不用担心，框架内部实现了适配器，只需要指定接口，实现一个日志类即可

- 具体实现：
	- 进行配置`SLF4J`接口,有固定接口`logger`
	- 导入对应的依赖
		- `SLF4j`的依赖
		- 一个具体的实现日志的类的依赖
	- 写一个资源文件`xml`配置日志类
		- 配置日志级别,一般名字固定`logback.xml`
		- 只需要把 logback.xml 放到项目的资源目录（src/main/resources）下，Logback 就会在应用<mark style="background: #FFF3A3A6;">启动时自动扫描并加载它</mark>。

- 配置接口
```java
<configuration>
    <settings>
        <!-- 指定使用 SLF4J 作为日志门面 -->
        <setting name="logImpl" value="SLF4J"/>
    </settings>
</configuration>
```
- 导入依赖
```xml
<!-- SLF4J API -->
<dependency>
    <groupId>org.slf4j</groupId>
    <artifactId>slf4j-api</artifactId>
    <version>2.0.9</version>
</dependency>
<!-- Logback 实现 -->
<dependency>
    <groupId>ch.qos.logback</groupId>
    <artifactId>logback-classic</artifactId>
    <version>1.4.14</version>
</dependency>
```
- 配置对应的资源文件`xml`
```xml
<configuration>
    <appender name="STDOUT" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- 将 com.yourpackage.mapper 替换为你的 Mapper 接口所在包 -->
    <logger name="com.yourpackage.mapper" level="TRACE"/>

    <root level="INFO">
        <appender-ref ref="STDOUT"/>
    </root>
</configuration>
```

| MyBatis级别 | 对应方法                           | 说明                              |
| --------- | ------------------------------ | ------------------------------- |
| `TRACE`   | `trace(String s)`              | **最详细**。通常用于输出SQL参数、结果集映射等底层信息。 |
| `DEBUG`   | `debug(String s)`              | **调试级别**。用于输出SQL语句、执行时间等核心调试信息。 |
| `WARN`    | `warn(String s)`               | 警告信息，如使用了已弃用的方法。                |
| `ERROR`   | `error(String s, Throwable e)` | 错误信息，如SQL执行失败。                  |

在MyBatis中，**`DEBUG`级别通常用于输出SQL语句，而`TRACE`级别会输出SQL参数和结果集映射等更详细的信息**

# 四.缓存机制

## 4.1一级缓存

---

- 缓存：
	- 将查询出来的数据进行记录，等待查询相同数据时，从缓存中取，不会从数据库中查询
- 本质：
	- <mark style="background: #FFF3A3A6;">返回一个指针</mark>，不是对缓冲区的数据的复制

- 缓存等级：
	- 一级缓存：
		- `sqlSession级别`:范围为`sqlsession`,同一个`sqlSession`查询的数据会被缓存，在进行查询就会从缓存中取，若是从一个对话获得一个接口的两个`mapper`也会缓存，为统一对话
		- 默认开启
		- 一般只对查询功能有效：连续对一个`sql`操作两次，第二次开始就从缓存中查询了
	- 二级缓存

- 一级缓存失效：
	- <mark style="background: #FFF3A3A6;">不同的</mark>`sqlsession`对应不同的一级缓存
	- 同一个`sqlsession`但是<mark style="background: #BBFABBA6;">查询条件不同</mark>
	- 同一个`sqlsession`两次查询期间执行了<mark style="background: #FFB86CA6;">任意一次增删改操作</mark> ——》 改变了数据库的数据 ——》 数据库数据和缓存数据不同了，<mark style="background: #FFF3A3A6;">结果可能不对</mark>
	- 同一个`sqlsession`两次查询期间<mark style="background: #FF5582A6;">手动清除了缓存</mark>
		- `sqlsession.clearCache`

## 4.2二级缓存

---

- 二级缓存：
	- 手动开启
	- 范围:
		- `sqlSessionFactory级别`,通过一个工厂创建的会话
	- 日志中显示缓存的命中率，缓存数据存放到内层中
	- 本质：
		- 对对象的指针进行返回，而不是数据的复制
	- 开启条件：
		- 全局配置中设置`cacheEnabled="true"`
		- 映射文件中设置标签`<cache />`
			- `eviction属性`:
				- 缓存回收机制
				- 值：
					- `LRU`:最近最少使用机制
					- `FIFO`:先入先出机制
					- ....
			- `flushlnerval`:
				- 刷新间隔，单位`ms`
				- 并设置，<mark style="background: #D2B3FFA6;">默认在调用语句时刷新增删改时</mark>
			- `size`:
				- 引用数目
				- 代表最多的缓存数目
			- `readonly`:
				- 只读
				- `true/false`
					- `true`:
						- 只读缓存，返回给用户的是指针，不能修改对象，否则缓存会改变，效率高，但是可能污染数据
					- `false`:
						- 读写缓存,将数据拷贝一份返回给对象，效率低，但是安全
		- 二级缓存必须在`sqlsession`<mark style="background: #FFF3A3A6;">自动提交且关闭</mark>以后才可以保存到`sqlsession中`
		- 查询的方法转化对应实体类必须实现序列化接口
			- 若是没有实现序列化，在存入缓存时/`close/commit`直接报错，抛出异常

- 失效：
	- 两次查询间进行了增删改
	- `clearcache不会清空二级缓存，只针对sqlsession`

## 4.3三级缓存

---

- 一级缓存和二级缓存都是存放到内存中
- 一级和二级缓存是框架自带的，可以第三方实现缓存，来替代二级缓存，一级缓存无法替代
- 第三方的缓存：
	- 添加依赖：
		- `ehcache`
		- `slf4j的一个具体实现logback`
	- 配置第三方缓存的属性，通过`<cache />配置标签来切换二级缓存为第三方缓存`

## 4.4缓存数据查询顺序

---

- 一级缓存是关闭提交以后才会提交到二级缓存中
- 查询缓存范围：
	- 二级缓存：
		- 可能有其他会话查询的数据
	- 一级缓存
	- 数据库
