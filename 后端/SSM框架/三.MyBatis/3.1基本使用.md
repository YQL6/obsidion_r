# 一.简介

## 1.1引入

---

- 持久层框架/`DAO`：支持自定义`sql`，自己写映射，但是`JDBC`的动作都被封装到底层
	- 基本使用：增删改查
	- 多表映射：优势明显
	- 动态语句
	- 动态扩展
- `Mabits一般使用xml文件配置`

## 1.2优势

---

- 对比原生的`JDBC`:
	- 免除了设置和获得结果集等工作
	- `sql仍需要自己来写`
- `jdbc`:
	- 全都自己写：
		- 数据源配置，创建
		- 获得连接/`ThreadLocal`
		- 获得执行器
		- 执行获得结果集，手动映射实体类
		- ....
- `Hibernate`：
	- 操作简便，开发效率高
	- 封装程度过高，一切`sql`等操作都已经封装好了，自定义空间小
	- 性能低，反射过多
	- 依赖配置严重
- `Mabits`:
	- 封装轻量级，性能较好
	- `SQL和java编码分开`,简单结果映射
	- 省略了一些`jdbc`操作

import com.atguigu.MyBaits.mapper.EmployeeMapper;
import org.apache.ibatis.io.Resources;
import org.apache.ibatis.session.SqlSession;
import org.apache.ibatis.session.SqlSessionFactory;
import org.apache.ibatis.session.SqlSessionFactoryBuilder;
import org.junit.jupiter.api.Test;
import com.atguigu.MyBaits.mapper.EmployeeMapper;
import com.atguigu.MyBaits.pojo.Employee;

import java.io.IOException;
import java.io.InputStream;

public class mabaits {
    @Test
    public void test01() throws Exception {
        /*
        * mybatis使用方法较为繁琐
        * 不像jdbc一样直接创建，而是要通过开放的接口使用
        * 到后面直接交给IOC管理
        * */
        //创建sqlsessionfactroy对象
        //1.读配置文件
        InputStream in = Resources.getResourceAsStream("mybatis-config.xml");
        //2.基于配置文件创建一个sqlsessionfactory对象(重点) ——》 全局唯一
        SqlSessionFactory sqlSessionFactory = new SqlSessionFactoryBuilder().build(in);
        //获得session，开启会话
        //3.获得Sqlsession对象 ——》 每次连接数据库操作的会话
        SqlSession sqlSession = sqlSessionFactory.openSession();

        EmployeeMapper employeeMapper = sqlSession.getMapper(EmployeeMapper.class);
        //5.调用代理对象的方法执行对应sql语句,调用代理对象的方法会自动查找对应的mapper接口方法
        Employee e = employeeMapper.queryEmployeeById(1);
        System.out.println(e);
        //6.关闭sqlsession的连接
        sqlSession.commit();
        sqlSession.close();
        in.close();
    }
}

# 二.使用讲解

## 2.1`ibatis`方式和原理

---

- 最初就是`Apache的一个ibatis项目`后来到谷歌下`mybatis`
	- `ibatis`:
		- `1.x,2.x`
		- 有自己的一套数据库`curd`方法
	- `mybatis`:
		- `3.x`
		- 有自己的一套数据库`curd`方法，是对`ibatis`的封装和优化

- 模拟需求：
  ![[图片/Pasted image 20260927172103.png]]
	- 对学生表进行数据插入
		- 新方式：
			- 创建接口和`mappers文件`
		- 老方式：
			- 使用`StudentMapper.xml`文件即可，不用接口
			- 加一个实体类，然后讲映射配置交给配置文件即可

- 真正底层实现：
  ![[Excalidraw/后端/SSM框架/三.MyBaits/3.1基本使用/二.使用讲解/2.1ibatis方式和原理/ibatis|ibatis]]
- 缺点：`mybatis`针对这些进行优化
	- `key`容易写错
	- 映射困难
- 本质：
	- 就是从全局缓存中找到配置文件中的sql语句，然后执行，进行自动的简单映射

public void test_ibatis() throws Exception {  
    //1.读配置文件  
    InputStream in = Resources.getResourceAsStream("mybatis-config.xml");  
    //2.基于配置文件创建一个sqlsessionfactory对象(重点) ——》 全局唯一  
    SqlSessionFactory sqlSessionFactory = new SqlSessionFactoryBuilder().build(in);  
    //获得session，开启会话  
    //3.获得Sqlsession对象 ——》 每次连接数据库操作的会话

    *selectOne selectList / insert /delete /update 查找对应sql语句的标签，然后执行  
    * 参数1：sql的String，可以直接使用定位获得对应配置文件中的sql,准确定位：namespace.id  
    * 参数2：传入的参数，只能传入一个，要是多个，只能使用map集合映射  
    * 区别：  
    *   1.不需要写接口  
    *   2.直接使用  
    * 缺点：  
    *   1.sql语句标签对应的字符串标识容易错误  
    *   2.参数只能传递一个  
    *   3.返回值不会提示是什么类型，提供的解决方法也较为弱  
    * */    Student s = sqlSession.selectOne("666.kkkk",1);  
    System.out.println(s);  
  
}

        <setting name="logImpl" value="STDOUT_LOGGING"/>

    <typeAliases>
        <package name="com.atguigu.MyBaits.pojo"/>
    </typeAliases>

    <!--
        default配置决定了哪个环境生效

        -->
    <environments default="development">

        <environment id="development">

            <!-- JDBC 事务管理 -->
            <!--使用jdbc的提交和回滚功能（看传入的值是什么)，自动开启事务，自己提交事务(推荐)

                -->
            <dataSource type="POOLED">
                <!--环境配置-->
                <property name="driver" value="com.mysql.cj.jdbc.Driver"/>

## 3.2参数传递

---

- 类型：
	- `#{key}`:
		- 占位符 + 赋值
		- 推荐，不会发生注入，但是不能对关键字等内容进行赋值
	- `${key}`:
		- 单纯的字符串拼接
		- 不推荐，但是能和`#{key}`配合使用

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper
        PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "https://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.atguigu.MyBaits.mapper.EmployeeMapper">

    <select id="queryById" resultType="com.atguigu.MyBaits.pojo.Employee">
        <!--自动映射：注意不能太过偏重命名-->
        <!--取值的两种方式：
            #{key}:占位符 + 赋值 ， emp_id = ? , ? = 赋值——》 推荐使用，可以放置注入攻击
                只能赋值，不能为替代容器名，例如：标签，列名，sql关键字
            ${key}:字符串拼接  ，" emp_id = " + id
                若是需要输入(columnname,columnvalue)时，只用#{key}不可以，列名无法赋值——》配合使用，先${},后#{}
            -->
        select emp_id empid,emp_name empname,emp_salary empsalary from student where emp_id = #{id};
    </select>
</mapper>
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper
        PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "https://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.atguigu.MyBaits.mapper.EmployeeMapper">

    <select id="queryById" resultType="com.atguigu.MyBaits.pojo.Employee">
        <!--自动映射：注意不能太过偏重命名-->
        <!--取值的两种方式：
            #{key}:占位符 + 赋值 ， emp_id = ? , ? = 赋值——》 推荐使用，可以放置注入攻击
                只能赋值，不能为替代容器名，例如：标签，列名，sql关键字
            ${key}:字符串拼接  ，" emp_id = " + id
                若是需要输入(columnname,columnvalue)时，只用#{key}不可以，列名无法赋值——》配合使用，先${},后#{}
            -->
        select emp_id empid,emp_name empname,emp_salary empsalary from student where emp_id = #{id};
    </select>
    <!--场景1：传入单个值类型-->
    <delete id="deleteById">
        <!--当前单个值，可以随便写输入的名称
            一般输入和内容一致
            -->
        delete from t_emp where emp_id = #{id};
    </delete>
    <select id="queryBySalary">
        select emp_id empid,emp_name empname,emp_salary empsalary from t_emp where emp_salary = #{salary};
    </select>
    <!--场景2：传入一个实体对象-->
    <insert id="insertEmp">
        <!--默认使用属性名即可
            使用实体对象的属性名，默认从传入的实体对象中取
            底层使用反射注入，只有一种方法
            -->
        insert into t_emp(emp_name,emp_salary) values(#{empname},#{empsalary} ;
    </insert>
    <!--场景3：传入多个简单的单值类型-->
    <select id="queryByNameAndSalary">
        <!--
            多个值传入，不可以随便取
            按形参取名，不可以
            方案1：推荐
                使用注解指定 @Param注解:指定多个简单参数的，在接口处指定一个参数的名字
                    形参赋值的内容默认赋值给@Param("value")中的value
                    一般在xml，注解中使用
            方案2：
                Mybatis默认机制
                    默认赋值给 arg0,arg1.... 形参传入的值依次赋值
                    默认赋值给 param1,param2.... 这个方式也支持
         -->
        select emp_id empid,emp_name empname,emp_salary empsalary from t_emp
        where emp_name = #{emp_name} and emp_salary = #{emp_salary}
    </select>
    <!--场景4：key直接就是map的key即可-->
    <insert id="inserEmpByMap">
        insert into (emp_name,emp_salary) values(#{emp_name),#{emp_salary});
    </insert>
</mapper>
```

- 接口书写：
```java
package com.atguigu.MyBaits.mapper;  
  
import com.atguigu.MyBaits.pojo.Employee;  
import org.apache.ibatis.annotations.Param;  
  
import java.util.List;  
import java.util.Map;  
  
public interface EmployeeMapper {  
    Employee queryById(Integer id);  
    //根据id删除员工  
    Employee deleteById(Integer id);  
    //根据工资查询  
    List<Employee> queryBySalary(Double salary);  
    //通过实体对象插入数据  
    int insertEmp(Employee employee);  
    //根据员工的姓名和工资查询员工信息  
    List<Employee> queryByNameAndSalary(@Param("emp_name") String name,@Param("emp_salary") Double salary);  
    //插入员工数据，员工数据在map中  
    //注意方法名不能重复，因为id不能重复  
    int insertEmpByMap(Map data);  
}
```

        delete from t_emp weher emp_id = #{id};

    <!--场景2：返回单个简单类型 ——》 如何指定resultTyep的写法
        直接指定返回值的数据类型
        resultType:
            1.类的限定名
            2.别名简称

        具体实现流程：
            mybaits ——》 ibatis ——》 selectOne 单个 | selectList 集合 ——》 selectone调用selectList

| 对比项    | `<id>`       | `<result>`      |
| ------ | ------------ | --------------- |
| 映射动作   | 把列赋给属性       | 把列赋给属性          |
| 语义     | 标识唯一行        | 普通字段            |
| 去重     | 参与           | 不参与             |
| 嵌套映射   | 用于判断同一对象     | 不参与             |
| 缓存 key | 参与           | 不参与             |
| 是否必须   | 简单查询可不写      | 按需写             |
| 推荐     | 主键列都用 `<id>` | 其他列用 `<result>` |

## 3.7自定义映射关系

---

- 常在多表查询时使用

- 映射配置：
```xml
 <!--
        定义映射关系：
            id：使用的标识，别人使用都用标识即可
            type：返回值类型，将数据封装到哪个实体类中
                集合：泛形
                实体类：全限定符|定义标识
                -->
    <resultMap id="teacher_map" type="teacher">
        <!--id表示主键的映射关系-->
        <id column="id" property="id"></id>
        <!-- result表示只是普通的字段而已-->
        <result column="name" property="name"></result>
    </resultMap>
    <select id="queryTeacherById" resultMap="teacher_map">
        <!--
            映射字段间的处理：
                1.起别名，使表的字段和实体类的属性名字相同
                2.开启驼峰式映射
                3.自定义映射：reslutMap：可以多表映射
                                与reslutType二选一
                            reslutType:按照类型对应规则进行映射， 但是只能进行一层结构的映射，即一个表格的映射关系，若是引入第二个表格就无法映射!!!
                                Employees
                                    emp_id
                                    last_name
                                    job_id ——》 关联到 job表格上，
                                        通过它查询job_name ——》 无法映射，只能是一个实体类,无法进行深层次结构映射!!!
        -->
        <!--使用reslutMap就相当于自己进行定义映射关系-->
        select id ,name from teacher where id = #{id};
    </select>
```
