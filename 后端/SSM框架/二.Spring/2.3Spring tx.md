# 一.引入

##  1.1简单介绍

- `Spring tx`:声明式事务

- 编程式事务：手动编写程序管理事务，即编写代码方式直接控制事务的提交和回滚

```java
//编程式事务

try{
	//开启事务：关闭事务的主动提交
	conn.setAutoCommit(false);
	//核心操作
	//业务代码
	//提交事务
	conn.commit();
}catch(Exception e){
	//回滚事务
	conn.rollback();
}finally{
	//关闭连接
	conn.close();
}
```

- 声明式事务：使用`Xml配置`和注解方式进行事务控制，开发者只需要进行<mark style="background: #FFB86CA6;">配置即可</mark>，<mark style="background: #FFF3A3A6;">具体事务由第三方框架支持</mark>，避免开发者直接对事务进行操作

- 第三方框架：
	- `Spring-tx`:
		- 进行书写配置文件(注解,`xml配置`),对方法进行配置，添加事务属性

## 1.2事务管理器和原理

---

- 事务操作几乎都是一样的 ——》 `AOP操作`可以提取写增强方法，写各个地方的增强和配置，自己写事务操作
- `Spring tx`:进行进一步封装，都不用自己写了，对`AOP的进一步封装`，直接指定方法

	- 事务对不同连接数据库的方式的处理不同——》写一个多态，使用声明数据库连接，调用同样的方法，进行的操作不同
	- <mark style="background: #ADCCFFA6;">传入什么数据库连接方式，进行对应的操作</mark>
	- 底层实现：
		- 提供具体的类型的数据库事务实现，选择合适的配置事务处理器
		- 将事务处理器放入`Spring IOC容器中`,然后使用增强类获得事务处理器
	- 操作：
		- 将事务管理器放入`IOC容器中`，使增强类获取事务管理器
		- 指代功能那些方法要添加事务
	- 包：
		- 事务管理器：
			- `spring-tx`
		- 实现数据库事务实现：
			- `Connection`:`Spring-jdbc`
			- `Hibernate/Jpa`:`Spring-orm`
	- 本质：盛放了具体事务实现的代码，然后将其放入增强中，调用它实现事务

# 二.事务实现

## 2.1基本程序搭建

---

- 添加事务步骤：
	1. 选择对应事务管理器实现加入到`IOC容器中`，`Spring声明式事务已经为我们提供了各个管理器实现`，加入到`IOC容器中即可`，选择一个实现的事务管理器`D/H`
	2. 开启事务注解的支持:`@EnableTransactionManagement`
	3. 使用注解指定那些方法需要添加事务即可:
		1. 执行流程：注解调用`Spring`内置的增强类，内置增强类(内部注入了`plat`接口，所以写事务管理器使返回写`plat`)调用事务管理器进行事务方法调用，切入到切入点上(使用的是环绕式)

```
业务方法上的 @Transactional（标记/元数据）
        ↓ 被读取
TransactionInterceptor（增强）          ← 由 @EnableTransactionManagement 自动注册
        ↓ 调用
PlatformTransactionManager（接口/规范）
        ↓ 容器按类型找实现
DataSourceTransactionManager（真正的实现类）
```

```java
//配置类

package com.atguigu.maven.config;

import com.alibaba.druid.pool.DruidDataSource;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.*;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.jdbc.datasource.DataSourceTransactionManager;
import org.springframework.stereotype.Component;
import org.springframework.transaction.TransactionManager;
import org.springframework.transaction.annotation.EnableTransactionManagement;

@Configuration
@PropertySource("classpath:jdbc.properties")
@ComponentScan("com.atguigu.maven")
@EnableTransactionManagement//开启事务注解支持
@EnableAspectJAutoProxy //开启AspectJ的注解支持，与事务注解不冲突
public class Javaconfig {
    //durid连接池
    @Bean
    public DruidDataSource druidDataSource(@Value("${driver}") String driver,@Value("${user}") String user,
                                           @Value("${password}") String password,@Value("${url}") String url) {
        DruidDataSource druidDataSource = new DruidDataSource();
        druidDataSource.setDriverClassName(driver);
        druidDataSource.setUrl(url);
        druidDataSource.setUsername(user);
        druidDataSource.setPassword(password);
        return druidDataSource;
    }
    @Bean
    public JdbcTemplate jdbcTemplate(DruidDataSource druidDataSource) {
        return new JdbcTemplate(druidDataSource);
    }
    /*
    * 1.创建声明式事务的具体实现类进行配置
    * 2.配置具体的增强类，指定方法
    * */
    @Bean
   public PlatformTransactionManager transactionManager(DruidDataSource druidDataSource) {
        return new DataSourceTransactionManager(druidDataSource);
    }
}

```

## 2.2事务属性

---

- 只读模式:
	- 事务中只有查询代码，开启只读模式会提高效率
	- `属性：readOnly`:默认`false`
	- 使用场景：注解加到类上，所有方法都有注解，相当于都有了事务切面，为了覆盖整个注解，可以为只有查询的事务方法添加一个新的注解，覆盖掉类的注解，并且添加只读属性

```java
  /*
    * 只读模式：事务中只有查询语句，设置只读模式可以提高效率
    *   属性：readOnly  默认false
    *   但是只查询可以不添加事务 ，但是有可能添加到类上，各个方法都有事务
    *   单独为只有查询的事务添加一个注解@Transactional(readOnly=true)
    * */
    @Transactional(readOnly = true)
    public void changeInfo() {
        studentDAO.updateAgeById(29,2);
        int i = 1/0;
        System.out.println("-------");
        studentDAO.updateNameById("text2",3);
    }
```

## 2.3事务超时时间设置

---

- 为事务<mark style="background: #FF5582A6;">设定一个时间</mark>，若是<mark style="background: #FFF3A3A6;">超过</mark>则进行<mark style="background: #BBFABBA6;">回滚</mark>操作并且<mark style="background: #FFF3A3A6;">抛出异常</mark>，释放资源

- 属性：`timeout`
	- 默认值为`-1`,代表永远不会超时
	- 可以为其设置一个整数，单位是`s/秒`
	- 超过时间，抛出异常，回滚，释放资源
	- 抛出错误：`TransactionTimedOutException`,可以进行捕获，然后设置处理操作

```java
package com.atguigu.maven.Service;

import com.atguigu.maven.DAO.StudentDAO;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class StudentService {

    @Autowired
    private StudentDAO studentDAO;
    /*
    * 事务直接加在需要的地方，不用写增强类
    *   @Transactional注解直接实现了了事务的增强类的调用
    *       位置：方法/类上
    *           方法：单独这一个方法加上事务
    *           类：类的所有方法加上事务
    * */
    /*
    * 只读模式：事务中只有查询语句，设置只读模式可以提高效率
    *   属性：readOnly  默认false
    *   但是只查询可以不添加事务 ，但是有可能添加到类上，各个方法都有事务
    *   单独为只有查询的事务添加一个注解@Transactional(readOnly=true)
    * 
    *   属性：timeout  默认-1  永远不会超时
    *   设置数字，做为时间，单位s
    *   若超过设置的时间，报错TransactionTimedOutException，可以捕获这个错误进行处理
    * */
    @Transactional(readOnly = false,timeout = 5)
    public void changeInfo() {
        studentDAO.updateAgeById(29,2);

        try {
            Thread.sleep(6000);
        } catch (InterruptedException e) {
            throw new RuntimeException(e);
        }
//        int i = 1/0;
        System.out.println("-------");
        studentDAO.updateNameById("text2",3);
    }
}

```

注：
1. 同样`timeout`可以设置在类上，使全体方法获得这个注解
2. 若是方法上单独注解，<mark style="background: #D2B3FFA6;">就近原则</mark>，覆盖掉类上的标签，所有属性都按最近的标签来

## 2.4事务异常指定问题

---

- 执行的事务最终状态：
	- 成功：
		- 没有任何问题
	- 失败：
		- 任何异常发生不能代表就是`sql执行失败`
		- 必须是对应的异常发生，才发生回滚
			- 异常：
				- `Throwable`
					- `ERROR`
					- `Exception`
						- `RuntimeException`
						- `其他Exception`
- 回滚时机：
	- 事务管理器：
		- 默认运行时异常回滚，其他异常不回滚
		- 一些异常不回滚，会导致前面的语句更改数据，但是后面的语句没有执行，破坏了原子性
	- 使用`rollbackFor属性`指定回滚异常有那些及子类
	- 使用`norollbackFor属性`指定再回滚异常中那些异常不回滚

```java
   @Transactional(readOnly = false,timeout = 5,rollbackFor = Exception.class)
    public void changeInfo() {
        studentDAO.updateAgeById(29,2);

        try {
            Thread.sleep(6000);
        } catch (InterruptedException e) {
            throw new RuntimeException(e);
        }
//        int i = 1/0;
        System.out.println("-------");
        studentDAO.updateNameById("text2",3);
    }
```

## 2.5事务隔离设置

---

- 事务隔离级别：
	- 隔离级别越高，越安全，性能越低
	- 隔离级别：
		- `读未提交/read uncommited`：
			- 事务可以读取未提交的数据，容易脏读，不可重复读和幻读等问题
		- `读已提交/read commited`:
			- 可以避免脏读，不可以避免重复读和幻读问题
			- <mark style="background: #FF5582A6;">推荐</mark>
		- `可重复读/repeatable read`:
			- 可以避免脏读和不可重复读问题，不可以避免幻读问题
		- `串行化/serializable`
			- 最高级别的隔离，完全进制了并发，只允许一个事务执行完毕以后才能执行另一个事务，效率极低，不适合高并发场景

```java
   @Transactional(readOnly = false,timeout = 5,rollbackFor = Exception.class,isolation= Isolation.READ_COMMITTED)
    public void changeInfo() {
        studentDAO.updateAgeById(29,2);

        try {
            Thread.sleep(6000);
        } catch (InterruptedException e) {
            throw new RuntimeException(e);
        }
//        int i = 1/0;
        System.out.println("-------");
        studentDAO.updateNameById("text2",3);
    }
```

## 2.6事务传播行为

---

- 两个事务由各自的事务增强设置，一个事务的设置会不会影响另一个事务设置
  ![[Excalidraw/后端/SSM框架/二.Spring/2.3Spring tx/二.事务的实现/2.6事务传播行为/事务调用间的传播|事务调用间的传播]]
	- 事务传播行为：事务间调用，如何影响子事务
		- 子事务是被调用者，父事务先开启，子事务遇到子事务选择是否共用一个事务
		- 在子事务上设置
			- 属性：`propagation`
				- 加入:`Propagation.REQUIRED`值
				- 不加入:`Propagation.REQUIRED_NEW`值

```java
@Transactional(propagation = Propagation.REQUIRED)
    public void changeAge(){
        studentDAO.updateAgeById(211,1);

    }
    @Transactional
    public void changeName(){
        studentDAO. updateNameById("text2",2);
    }
```
