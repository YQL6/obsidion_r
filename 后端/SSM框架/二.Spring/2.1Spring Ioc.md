## 1.2SpringFramework介绍

---

- `Spring 和 SpringFramework的区别`:
	- `Spring`:`Spring` 全家桶，例如：`Spring Framework,Spring MVC, Spring Cloud`，<mark style="background: #BBFABBA6;">泛指一套技术栈</mark>
	- `SpringFramework`:<mark style="background: #ABF7F7A6;">一个技术栈</mark>，`Spring全家桶`的<mark style="background: #FF5582A6;">基础</mark>
	- 有时将`SpringFramework`称为`Spring`

- `SpringFramework`有很多模块组成，有很多功能，要声明功能导入相应模块即可
	- 功能模块：
		- `Core Container`：
			- 核心容器，<mark style="background: #ABF7F7A6;">管理存储组件</mark>，实例化对象使用`new`,存储用全局变量,不好管理，这些都由`core container`管理
			- 将组件间的<mark style="background: #ADCCFFA6;">关系处理</mark>好以后<mark style="background: #FFF3A3A6;">注入</mark>到代码中
		- `AOP&ASPCETS`:
			- 面向切面编程——》面向对象编程的完善
		- `TX`:
			- 声明式事务，简化事务的书写
		- `Spring MVC`:
			- 提供了面向`Web应用软件`的集成功能

- `Spring6.0`:使用`JDK17`

---

	- 实例化，配置和组装组件(bean)
	- 配置信息/原数据
		- `XML`
		- `java注解`
		- `java代码`
	- 管理需要：

		- 已经了实现的对象

## 3.3注入依赖

- 创建项目：
  ![[Excalidraw/后端/SSM框架/二.Spring/2.1Spring Ioc/三.IOC容器的具体实现/3.3依赖注入/项目架构|项目架构]]

```xml
<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://www.springframework.org/schema/beans http://www.springframework.org/schema/beans/spring-beans.xsd">
    <!--引入两个组件类-->
    <bean id="UserDAO" class="com.atguigu.ioc02.UserDAO"></bean>
    <!--1.单参构造-->
    <bean id="UserService" class="com.atguigu.ioc02.UserService">
        <!--指定构造参数传值-->
        <!--参数说明
            value:直接属性值,String,int,double,float等
            ref:引用其他的bean，写其他bean的id值
            二选一
            -->
        <!--若是ref赋值，可以不考虑先后顺序
            springioc容器是一个高级容器，内部有缓存动作
            先创建对象，在内部进行赋值
            -->
        <constructor-arg ref="UserDAO"></constructor-arg>
    </bean>

    <!--2.创建第二个实例——》多个参数的构造器-->
    <bean id="UserService1" class="com.atguigu.ioc02.UserService">
        <!--方案1：按照构造参数的顺序填写参数-->

        <constructor-arg value="18"></constructor-arg>
        <constructor-arg value="小明"></constructor-arg>
        <constructor-arg value="UserDAO"></constructor-arg>
    </bean>

    <bean id="UserService1" class="com.atguigu.ioc02.UserService">
        <!--方案2：按照构造参数的名字填写参数
            不用考虑参数顺序，直接根据参数名字来赋值
        -->

        <constructor-arg name="age" value="18"></constructor-arg>
        <constructor-arg name="name" value="小明"></constructor-arg>
        <constructor-arg name="userDAO" value="UserDAO"></constructor-arg>
    </bean>

    <bean id="UserService1" class="com.atguigu.ioc02.UserService">
        <!--方案3：按照参数的下角标填写参数
            不用考虑顺序，index=构造参数的下角标，从0开始
            例如：age是第一个参数：index=0，若是填1，则将直接值放入到第二个参数中
        -->

        <constructor-arg index="0" value="18"></constructor-arg>
        <constructor-arg index="1" value="小明"></constructor-arg>
        <constructor-arg index="2" value="UserDAO"></constructor-arg>
    </bean>

    <!--3.set方法注入-->
    <bean id="movieFinder" class="com.atguigu.ioc02.MovieFinder"></bean>
    <bean id="simpleMoviveLister" class="com.atguigu.ioc02.SimpleMovieLister">
        <!--配置set选项： name是set方法的名称，但是不是原名——》去掉set，将第一个字母变为小写
            例如：setMovieFinder——》movieFinder
            -->
        
        <!--小细节：
            set不支持多个参数传入，
            set和构造器可以一起使用，先构造器然后set
            -->
        <property name="movieFinder" ref="movieFinder"></property>
        <property name="movieName" value="action"></property>
    </bean>
</beans>
```

补充：
- `constructor_arg`:表示创建过程参数——》构造器和工厂参数
	- 静态：直接创建，所以直接传入参数
	- 非静态：先创建工厂，然后方法创建
- `property`:后传入赋值，`setter的方法`

## 3.4基于配置的IOC容器的创建

---

- 读取配置文件，创建`IOC容器`
	- 创建容器时可以传入多个配置文件——》将多个配置文件合并一起，然后当作一个使用
	- 配置文件设置和创建容器分开，将文件和容器分开，容器可以指定配置文件
- 获得组件:通过不同方法获取的是一个对象
	- 通过`id`获取
	- 通过`id + .class`获取
	- `通过bean的.class获取`
		- 可能出现较多问题

```java
package com.atguigu.test;

import com.atguigu.ioc03.HappyComponent;
import org.junit.jupiter.api.Test;
import org.springframework.context.ApplicationContext;
import org.springframework.context.support.ClassPathXmlApplicationContext;

public class SpringIocTest {
    public void createIoc(){
        //方式1：直接创建容器并且指定配置文件
        //构造函数(String...配置文件)可以填写一个或多个配置文件
        //ioc，di都是在容器内部实现
        ApplicationContext context = new ClassPathXmlApplicationContext("Spring_ioc_03.xml");
        //若是有多个配置文件，可以写多个参数，做为文件名称

        //方式2：先创建ioc容器对象，在指定配置文件，在刷新
        //源码的配置过程， 创建容器和配置文件分开 ， 往往时配置文件和源码分开
        ClassPathXmlApplicationContext Application = new ClassPathXmlApplicationContext();
        Application.setConfigLocation("Spring_ioc_03.xml");
        Application.refresh();//创建bean和注入过程
    }
    @Test
    public void getBeanFormIoc(){
        //1.创建Ioc容器
        //只有实现类才有一些方法，不能使用接口接
        ClassPathXmlApplicationContext context = new ClassPathXmlApplicationContext();
        context.setConfigLocation("Spring_ioc_03.xml");
        context.refresh();
        //2.读取Ioc容器的组件
        //方案1：直接根据BeanId获取,返回值类型是Object,类的方法无法使用，需要强转
        HappyComponent happy = (HappyComponent) context.getBean("happyContext");

        //方案2：根据beanId'，同时指定bean的类型Class
        HappyComponent happy2 = context.getBean("happyContext", HappyComponent.class);

        //方案3：直接根据类型获取
        /*
        *类型：
        *    类的.class 
        *    接口的.class ——》自动匹配子类
        */ 
        /*
        * 若是只有一个这个类型的实例：直接取出来，成功
        * 多个：报错
        * 配置文件中指定是哪个：取出来
        * */
        HappyComponent happy3 = context.getBean(HappyComponent.class);
        happy3.doWork();
        //比较内存地址
        System.out.println(happy == happy2);//true
        System.out.println(happy2 == happy3);//true
    }
}

```

| `getBean` 重载方法                                   | 查找方式                     | 行为及注意事项                                                                                                                                                |
| ------------------------------------------------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `getBean(String name)`                           | **仅按名称**（Bean 的 id/name） | 返回 Object，需要手动类型转换；若名称不存在则抛 `NoSuchBeanDefinitionException`。                                                                                           |
| `getBean(Class<T> requiredType)`                 | **仅按类型**（包括接口或实现类）       | 查找容器中所有类型兼容的 Bean；  <br>- 恰好一个：返回该 Bean；  <br>- 多个匹配：抛 `NoUniqueBeanDefinitionException`；  <br>- 零个匹配：抛 `NoSuchBeanDefinitionException`。               |
| `getBean(String name, Class<T> requiredType)`    | **名称 + 类型**双重校验          | 先按名称找 Bean，再检查该 Bean 的实际类型是否与 `requiredType` 兼容；  <br>- 名称不存在：抛 `NoSuchBeanDefinitionException`；  <br>- 名称存在但类型不匹配：抛 `BeanNotOfRequiredTypeException`。 |
| `getBean(String name, Object... args)`           | **按名称**，并传构造参数           | 主要针对**原型作用域** Bean（Prototype），每次获取时可用不同构造参数创建新实例；若 Bean 是单例且已存在，则忽略 args。                                                                              |
| `getBean(Class<T> requiredType, Object... args)` | **按类型**，并传构造参数           | 同样适用于原型 Bean，按类型查找唯一候选，并传入构造参数创建实例；若有多个候选类型匹配，则抛异常。                                                                                                    |

注：
1. <mark style="background: #ABF7F7A6;">接口也可以作为类型</mark>：`getBean(接口.class)`，这样它的实现类也可以从`Ioc容器中获得`,<mark style="background: #CACFD9A6;">底层机制是`接口类型/实例 instanceof 各个bean`,只要是可以实现多态即可</mark>，<mark style="background: #ABF7F7A6;">可能出现多个实现类</mark>
2. 继承机制相同，从`IOC获得类`不是严格限定的
3. <mark style="background: #FFF3A3A6;">配置文件中一定是实现类</mark>
4. 从`Spring Ioc容器中出来的一个.class对象都是同一个`
5. <mark style="background: #ABF7F7A6;">获得`Bean`的机制：</mark>`bean instanceof A`，判断所有组件是不是这个`.class`的子类，自身，实现类

## 3.5扩展组件周期和作用域

---

- 周期方法：
	- 按固定时机有容器调用一次的方法
		- 初始化创建:`init`
		- 销毁：`destory`
	- 实例：
	  ![[Excalidraw/后端/SSM框架/二.Spring/2.1Spring Ioc/三.IOC容器的具体实现/3.5扩展组件周期和作用域/周期方法|周期方法]]
	- 业务逻辑不是周期方法，其按需求调用，有代码调用

- 组件类中可以定义方法，当`LOC容器实例化和销毁组件对象的时候进行调用`

- 周期方法的配置：
```xml
<?xml version="1.0" encoding="UTF-8"?>  
<beans xmlns="http://www.springframework.org/schema/beans"

        Spring ioc 容器会在对应的时间节点回调对应的方法

</beans>
```

```java
package com.atguigu.loc04;  
  
public class JavaBean {  
    /*  
    * 方法必须是public，必须是void返回值，必须是无参的  
    * 命名随意  
    * 反射时找无参数和public和void返回值的  
    * */    public void init(){  
        System.out.println("JavaBean init");  
    }  
    public void destroy(){  
        System.out.println("JavaBean destroy");  
    }
```

## 3.6扩展factoryBean使用

---

- 将组件放入`loc`容器
	- 工厂模式
		- 静态
			- `<bean id class factory-method>`
		- 非静态
			- `<bean id class> + <bean id factory-bean factory-method>`
	- 构造器
		- 有参
			- `<bean id class> + <constructor-arg>`
		- 无参
			- `<bean id class>`
	- `factoryBean`:
		- 简化工厂模式，<mark style="background: #ADCCFFA6;">一个接口</mark>,就是一个标准化的工厂,提供`getObject方法`,<mark style="background: #ABF7F7A6;">必须重写自己的实例化逻辑</mark>
		- `<bean id class=类的全限定符`
		- 可以创建复杂类对象的创建
		- 提供的方法:
			- `getObject`:
				- 返回对应的`Bean`
			- `boolean isSington()`
				- 返回`ture`是单例，默认，<mark style="background: #FFB86CA6;">已经默认实现</mark>
				- 重写返回`false`，变为多例
			- `Class<?> getObjectType()`:
				- 返回`getObject()`方法返回的对象类型，若是不知道，返回`null`

- `factoryBean的主要作用`:
	- 代理类
	- 第三方框架的整合：
		- 一个对象创建，需要创建多个类，在`getObject`实现，<mark style="background: #BBFABBA6;">对外直接开放最终类</mark>
	- 复杂对象的实例化

- `factoryBean的实现类`
	- 容器读取配置时，怎么对应类型
		- `读ID时`:找到对应的`ID`，发现是实现了`FactoryBean`,调用`getObject()`
		- `读类型时`:发现时`factoryBean实现类时，调用getobjetType()`
		- 
	- 周期任务：
		- <mark style="background: #CACFD9A6;">实现类本身的周期任务可以使用</mark>
		- 有`getObject()`出<mark style="background: #BBFABBA6;">来的类不会有周期任务</mark>，他是由`getObject()`返回的，没有进行配置
	- `factoryBean的实现类`也会被放入容器中，只是要读取有点特殊：
		- `&id`:读取`factoryBean实现类`

- `FactoryBean vs BeanFactory`:
	- `FactoryBean`:一个组件，一个接口，简化工厂操作
	- `BeanFactory`:一个接口，`IOC容器接口`,实例化`IOC容器`

注：
1. 所有操作都是落到外部的工厂类上——》要是想为实际类赋值，可以通过工厂类的赋值，在工厂类内部赋值给实际类

## 4.3DI注入

---

- 原来/`Xml`的注入方法:
	- 构造器：
		- `constructor-args`
	- `set方法`
		- `property`

- `@Autowired`:
	- 位置：
		- `set方法上`
		- 构造器上
		- <mark style="background: #FFB86CA6;">属性上/成员变量上</mark>
	- 工作原理：
		- 根据类型去`IOC容器`找类型，找到进行装配
			- 找不到，报错：装配失败
			- 多个对象可以装配：
				- 默认将<mark style="background: #ABF7F7A6;">属性名的第一个字母小写</mark>做为`bid查找`:
					- 找到：装配
					- 找不到：报错——》更改属性名与一个`Bean id配置`
				- `@Qualifile`指定`bid`是什么，此注解必须和`@Autowired`<mark style="background: #ABF7F7A6;">一起使用</mark>
					- `@Qualifier(value = "studentServiceImpl")`
					- `value是默认属性`,可以省略
		- 本质：注解进行获得属性的`Type`，根据类型的`class`进行匹配，若是接口，则可能出现多个匹配
	- `required属性`：即使无`Bean`强制执行下去，用到这个时后面会报错

```java
package com.atguigu.maven.ioc_03;

import com.atguigu.maven.ioc_03.Impl.UserServiceImpl;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

import javax.annotation.Resource;
import javax.annotation.Resources;
import javax.xml.namespace.QName;

@Component
public class UserController {
    /*
    * 直接在参数上进行配置
    * 参与配置的组件都要放到IOC容器中
    * 相当于<property userService>
        1.主动去寻找符合类型的组件对象
        *2.设置给当前属性值
    * */
    /*
    * 里面有一个required的属性，默认为ture，可以设置为false，之后可以没有匹配的bean
    * 若是调用方法则找不到对象调用，进行空指针报错
    * 不推荐使用
    * */
    //@Autowired(required = true)
    @Resource(name = "userService")
    private UserServiceImpl userService;

    /*
    * set方法配置的必须要有set方法
    * 配置机制和@Autowired同理
    * */
    public void setUserService(UserServiceImpl userService) {
        this.userService = userService;
    }

    public String show(){
        return userService.show();
    }
}

```

- 扩展注解：
	- `@Resource`:`Java`提供注解，`Spring`提供实现——》`JDK17把它剥离出去了需要重新导入依赖`
		- 依赖：`jakatra.annotation-api`
		- 功能：
			- 实现主动装配+指定`Bean Id`
		- 可以单独使用，配合使用时优先使用`byid`的方式进行注入

- 扩展：

| 作用域标识符               | 常量定义（在 Spring 中）                             | 描述                                                             | 适用场景                     |
| -------------------- | -------------------------------------------- | -------------------------------------------------------------- | ------------------------ |
| `singleton`          | `ConfigurableBeanFactory.SCOPE_SINGLETON`    | 默认作用域。每个 Spring 容器中只有一个 Bean 实例，所有请求共享该实例。                     | 无状态的服务类、工具类、配置类等。        |
| `prototype`          | `ConfigurableBeanFactory.SCOPE_PROTOTYPE`    | 每次请求（注入或 `getBean`）都会创建一个新的 Bean 实例。                           | 有状态的 Bean，每次使用都需要全新实例。   |
| `request`            | `WebApplicationContext.SCOPE_REQUEST`        | 每个 HTTP 请求拥有一个独立的 Bean 实例，请求结束后销毁。                             | Web 应用中与请求相关的数据，如请求参数封装。 |
| `session`            | `WebApplicationContext.SCOPE_SESSION`        | 每个 HTTP Session 拥有一个独立的 Bean 实例，Session 结束后销毁。                 | 用户会话信息，如购物车、登录用户。        |
| `application`        | `WebApplicationContext.SCOPE_APPLICATION`    | 每个 `ServletContext` 拥有一个独立的 Bean 实例，与应用生命周期相同。                 | 整个 Web 应用共享的数据。          |
| `websocket`          | `WebApplicationContext.SCOPE_WEBSOCKET`      | 每个 WebSocket 会话拥有一个独立的 Bean 实例。                                | WebSocket 通信中会话级的状态。     |
| `globalSession`（已废弃） | `WebApplicationContext.SCOPE_GLOBAL_SESSION` | 仅用于 Portlet 环境，表示全局 Session。在 Servlet 环境中等同于 `session`，已不推荐使用。 | 遗留 Portlet 应用。           |

注：
1. 若是使用点名制度，指定一个`Bean ID`,若是没有对应的`Bean`,报错

## 4.4Value注入

---

- `Atuowired注解`是靠主动查找`IOC容器`,若是没有或是`int等类型`如何进行
- `@Value`:
	- 赋值方法：
		- 直接赋值:`("xxx")`
		- 通过引入配置文件赋值:`("${}")`
	- 注解为其赋值：
		- 普通参数：直接赋值即可`@Value("xxx")`
		- 特殊参数：配置`web/jdbc`
			- 进行`jdbc.properties`
			- `xml文件`导入配置文件位置和命令域
			- 对特殊参数赋值

```java
//通过配置文件获得
package com.atguigu.maven.ioc_04;

public class JavaBean {
    @Value("${url}")
    private String url;
    @Value("${driver}")
    private String dirverclass;
    @Value("${user}")
    private String username;
    @Value("${password}")
    private String password;
    @Value("${person.name}, ${person.age}")  // ❌ 不能放在构造器上
    
	public MyBean(@Value("小明") String name,@Value("19") int age) { ... }
}


```

```xml
<!--导入配置文件-->
<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xmlns:context="http://www.springframework.org/schema/context"
       xsi:schemaLocation="http://www.springframework.org/schema/beans http://www.springframework.org/schema/beans/spring-beans.xsd http://www.springframework.org/schema/context https://www.springframework.org/schema/context/spring-context.xsd">

    <context:component-scan base-package="com.atguigu.maven.ioc_04"></context:component-scan>
    <context:property-placeholder location="classpath:jdbc.properties"></context:property-placeholder>

```

- 可能会有没有值的情况：
	- 使用默认值：
		- `@Value("${user:admin"})`:<mark style="background: #FFB86CA6;">使用默认值</mark>，在原基础上加上值

注：
1. `@Value("")`必须是`String`的参数输入，即使是不符合注解的参数，也要是`String`，因为注解会自动适配数据类型
2. `Spring的属性占位符`只要是`${}`都可以指定默认值
3. 本质：<mark style="background: #FFB86CA6;">对一个参数赋值，一定要写在参数旁边</mark>

## 5.2注解Bean

---

- 已解决问题：
	- 扫描
	- 引入第三方配置文件

- 将第三方类放入配置类中：
	- 包装成一个方法：
		- 返回值：`BeanClass`
			- 常使用接口做为返回值——》`getBean实现类的话找不到——》面向接口编程`
			- <mark style="background: #D2B3FFA6;">实际返回值可以用实现类</mark>
		- 方法名：`BeanID`，<mark style="background: #BBFABBA6;">默认</mark>，可以修改——》使用`Nmae/Value属性`
		- 使用`@Bean注解将此类放入IOC容器中`,可以使用`Name/Value属性更改类的BeanID`
	- 周期方法：
		- 原来：`书写对应的方法加上PostConstruct和ProDestory`
		- `Bean属性指定：initMethod和detoryMethod`，<mark style="background: #FFF3A3A6;">第三方类的源码无法修改，这里指定的是第三方类的方法那些是周期方法</mark>
	- 作用域：
		- `ScopeName注解指定，普通注解直接赋值的值和ScopeName代表意义一样`
	- 注入`Bean`:
		- 方案1：使用`BeanID()获得Bean`
		- 方案2(推荐)：将一个类型放到形参列表中，主动获取或者使用参数，然后使用注解
			- 若是有<mark style="background: #FF5582A6;">多个类型</mark>的`Bean`，将<mark style="background: #ABF7F7A6;">形参名称</mark>做为`BeanId`适配
			- `@Qualifier可以显示指定BeanID，默认形参名为BeanID`

```java
package com.atguigu.maven.config;

        return new JdbcTemplate(dataSource);
```

## 5.6工厂类实现

---

- 工厂类：
	- 静态工厂
		- 使用`@Bean`注解进行第三方类进入`IOC容器`,在返回类型时直接调用静态方法
	- 非静态工厂
		- 将工厂类做为`Bean进入IOC容器中`,然后将工厂类进行注入到第三方类的参数或者其他方式`BeanId()`获得工厂类，调用方法返回想要的类

```java
// 工厂类（不用注册进容器）
public class ProductFactory {
    public static Product create(String type) {
        return "A".equals(type) ? new ProductA() : new ProductB();
    }
}

@Configuration
public class MyConfig {
    @Bean("productA")
    public Product productA() {
        return ProductFactory.create("A");   // ← 调用静态工厂
    }

    @Bean("productB")
    public Product productB() {
        return ProductFactory.create("B");
    }
}
```

```java
// 工厂类本身要进容器
@Component
public class ProductFactory {
    public Product create(String type) {
        return "A".equals(type) ? new ProductA() : new ProductB();
    }
}

@Configuration
public class MyConfig {
    private final ProductFactory factory;

    public MyConfig(ProductFactory factory) {   // 注入工厂 Bean
        this.factory = factory;
    }

    @Bean("productA")
    public Product productA() {
        return factory.create("A");              // ← 调实例工厂方法
    }
}
```
