# 二.工作原理

## 2.1工作流程

---

- `servlet匹配对应流程`:
	1. **精确匹配** —— `/user/list`
	2. **最长路径前缀匹配** —— `/user/*`
	3. **扩展名匹配** —— `*.do`
	4. **默认匹配** —— `/`（DefaultServlet 兜底）

- 执行流程：
  ![[Excalidraw/后端/SSM框架/四.SpringMVC/4.1简介/二.工作原理/2.1工作流程/工作流程|工作流程]]
	- `DispatcherServelt`:
		- `SpringMVC`提供
		- 处理核心，将所有的路径匹配到放到这里来
		- 路径处理:`/*`,优先匹配
	- `HandlerServlet`:
		- `SpringMVC`提供
		- 缓存了`handler和处理路径间的关系`,等待调用
	- `HandlerAdapter`:
		- `SpirngMVC提供`
		- 处理请求和响应
	- `Handler`:
		- 自己定义，写对应的业务
		- 接收参数和调用参数
	- `ViewResovler`:
		- 简化视图处理

# 三.原理讲解

## 3.1web容器初始化

---

- `webApplicationInitializer`:
	- 接口
	- `web项目已启动就会自动调用这个接口的重写方法`:
	- 这里面可以写ioc容器创建等操作

```java
package com.atguigu;

import jakarta.servlet.ServletContext;
import jakarta.servlet.ServletException;
import org.springframework.web.*;

public class main implements WebApplicationInitializer{
    @Override
    public void onStartup(ServletContext servletContext) throws ServletException {
        System.out.println("onStartup");
    }
}

```

- `AbstractAnnotationConfigDispatcherServletInitializer`:
	- 抽象类
	- 其父类中有实现接口`webApplicationInitializer`的类
	- 可以直接将ioc容器创建，通过方法的返回类型指定`class`
	- 本身会被扫描到

```java
package com.atguigu.config;

import org.springframework.web.servlet.support.AbstractAnnotationConfigDispatcherServletInitializer;

//可以被web项目加载，会自动初始化ioc容器，会设置dispatcher地址
//使用一个注解类来代替xml配置web的方式，必须对AbstractAnnotationConfigDispatcherServletInitializer继承
//固定写一个类继承对应的类，只要继承对应的类即可
//自动创建对应的ioc容器
public class SpringMvc  extends AbstractAnnotationConfigDispatcherServletInitializer {
    /*
    * onstartup调用自己重写的方法，获得信息
    * */

    //创建webioc容器时使用此方法获得对应的class类
    //AnnotationConfigWebApplicationContext容器
    @Override
    protected Class<?>[] getRootConfigClasses() {
        return new Class[0];
    }

    //设置我们项目对应的配置
    //返回配置类信息
    //创建ioc容器时调用此方法，获得配置类
    //AnnotationConfigWebApplicationContext容器
    @Override
    protected Class<?>[] getServletConfigClasses() {
        return new Class[]{MvcConfig.class};
    }

    //设置dispatcherhandler的拦截路径
    //配置springmvc内部的servlet的访问地址
    //设置servlet时调用此方法，获得对应的字符串对应的地址
    @Override
    protected String[] getServletMappings() {
        //处理所有的地址
        return new String[]{"/"};
    }
}

```

- 大体流程：
	- 启动后立即调用`onstart`
		- 方法已经被重写好了，但是想要调用一些方法获得信息`getServeltMappings,getserveltconfigclasses,getrootconfigclasses`
		- 配置拦截路径：
			- 创建`dispatcherservlet`
				- 创建对应的`ioc容器`，独属于`dispatcherservlet`内部 
					- `getservletconfigclasses`
						- `专门为servlet使用，拦截器等`
			- `getservetlmappings`
		- 创建对应的`root ioc容器`
			- 一些处理器，逻辑调用的`service`，一些`dao`等组件信息

- `servlet VS controller`:
	- 两者不是一个层次的
		- `servlet`:
			- 与前端交互
		- `controller`:
			- 供`servlet`调用
	- 使用方式不同
		- `servlet`:
			- 请求来自动匹配对应的`servlet`
		- `controller`:
			- 有`servlet`进行分配
