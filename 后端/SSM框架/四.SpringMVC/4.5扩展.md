# 一.异常处理

## 1.1异常处理机制

---

- 编程式异常处理：
	- 代码中显示处理异常逻辑，`try ... catch`
	- 针对一个问题，特定处理机制
- 声明式异常处理：
	- 将异常处理机制和逻辑代码分开，通过配置方式进行统一管理和处理
	- 统一处理项目异常，项目问题清晰
	- <mark style="background: #FFB86CA6;">底层是通过AOP机制来处理</mark>
- 
  ![[Excalidraw/后端/SSM框架/四.SpringMVC/4.5扩展/一.异常处理/1.1异常处理机制/异常处理|异常处理]]

```java
package com.atguigu.Handler;

import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

/*
* @ContrllerAdvice :当前类来处理异常 ——》 走视图解析器 ——》混合的项目可以返回一个字符串，转到对应的html中
* @RestControllerAdvice:@Response + @ControllerAdvice ——》 注解返回json字符串
* */
//最重要的问题是此类被扫描到
@RestControllerAdvice
public class GlobalExceptionHandler {
    /*
    * 标签指明处理异常的类型，只要是此类异常就有这个方法来处理
    * 底层是AOP机制
    * 发生异常 ——》 Controller注解类型 ——》 @ExceptionHandler(指定的异常) 注解的方法
    * 指定的异常可以精准查找，若是没有精准查找也可以找父异常
    * */
    @ExceptionHandler(Exception.class)
    //形参接收异常信息
    public Object exception(Exception e) {
        //自定义处理异常
        e.printStackTrace();
        return e.getMessage();
    }
}

```

# 二.拦截器

## 2.1基本概念

---

- 拦截器：
  ![[Excalidraw/后端/SSM框架/四.SpringMVC/4.5扩展/二.拦截器/2.1基本概念/拦截器的使用|拦截器的使用]]
	- 使用位置：
		- 调用`controller`和使用完`controller`后返回时
		  ![[Excalidraw/后端/SSM框架/四.SpringMVC/4.5扩展/二.拦截器/2.1基本概念/具体示例|具体示例]]
		- 返回视图资源/响应信息时
	- 作用：
		- 为`springmvc`内部环节进行操作，拦截

-  `Springmvc拦截器 VS javaweb的过滤器`
	- 范围不同：
		- 拦截器：
			- `spring内部环节进行拦截`
		- 过滤器:
			- 拦截范围最大时整个`SpringMvc`的请求，范围自己设置
	- 工作平台不同:
		- 拦截器:
			- `Spring支持`，可以直接获得`IOC`容器中的组件或`IOC`容器
		- 过滤器：
			- `javaweb支持`，本身不处于`IOC`容器，简介获取`IOC容器`
- 能使用拦截器尽量使用拦截器



## 2.2拦截器的使用

---

- 实现一个类，实现接口`handlerIntercetor`
- 加入`IOC容器`,使用`WebMvcConfigurer`的`addIntercetors`的接口

- 定义拦截器
```java
package com.atguigu.Intercetors;

import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.springframework.web.servlet.HandlerInterceptor;
import org.springframework.web.servlet.ModelAndView;

/*
* 实现接口HandlerInterceptor，通过实现对应的方法，来设置其功能
* */
public class MyIntercetor implements HandlerInterceptor {
    /*
    * @Param request 请求对象
    * @Param response 响应对象
    * @Param handler 链条中controller
    * @param ex 若是handler报错，异常对象
    * @throws Exception
    * */
    //一般记录响应次数
    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response, Object handler, Exception ex) throws Exception {
        System.out.println("After Completion");
    }

    //当handler执行完毕以后，触发的方法，一般没有拦截机制了，都操作完了
    //只用当prehandle return true后才会执行
    /*
    * @param request 请求
    * @param response 响应
    * @param handler 链条中的controller
    * @param modelAndView 执行完写入/共享域的数据(默认request)和视图名称都放入到里面
    *@throws Exception
    * */
    //对结果处理，例如检查敏感词汇，做最后的处理
    @Override
    public void postHandle(HttpServletRequest request, HttpServletResponse response, Object handler, ModelAndView modelAndView) throws Exception {
        System.out.println("Post Handle");
    }

    //前置处理方法再所有controller执行前执行的方法，可以设置编辑格式，权限处理等
    /*
    * @Param request 请求对象
    * @Param response 响应对象
    * @param handler handler是我们要调用的方法对象
    * @return true 放行 false拦截
    * @throws Exception
    * */
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {
        System.out.println("preHandle");
        return true;
    }
}

```
- 配置拦截器
```java
package com.atguigu.config;  
  
import com.atguigu.Intercetors.MyIntercetor;  
import org.springframework.context.annotation.ComponentScan;  
import org.springframework.context.annotation.Configuration;  
import org.springframework.web.servlet.config.annotation.*;  
  
@Configuration  
@EnableWebMvc  
@ComponentScan("com.atguigu")  
public class MvcConfig implements WebMvcConfigurer {  
    @Override  
    public void configureViewResolvers(ViewResolverRegistry registry) {  
        registry.jsp("/WEB-INF/views/", ".jsp");  
    }  
    @Override  
    public void configureDefaultServletHandling(DefaultServletHandlerConfigurer configurer) {  
        configurer.enable();  
    }  
    @Override  
    public void addInterceptors(InterceptorRegistry registry) {  
        //将拦截器放入实体类  
        //默认拦截一切请求  
        //1.全部拦截  
        registry.addInterceptor(new MyIntercetor());  
        //指定路径拦截  
        /*  
        2.精准拦截  
        addpath精准拦截  
        *  *  此路径任意一个路径，一层任意路径  
        *  ** 此路径下所有路径，多层任意路径  
        * */        registry.addInterceptor(new MyIntercetor()).addPathPatterns("/**");  
        /*  
        * 3.排除拦截，排除对应地址应在拦截器内部  
        * 先添加拦截的地址，再从这地址里面排除一部分  
        * */        registry.addInterceptor(new MyIntercetor()).addPathPatterns("/**").excludePathPatterns("/user");  
        }  
  
}
```

- 若是多个拦截器匹配成功：
	- 都执行
	- 先执行先声明的拦截器的前置方法`pre`，按递归方式执行`post,after`
	- 洋葱圈式执行
	- 本质：执行完`pre`后立即判断是否执行后面的，执行调用，不执行`return`

## 2.3补充知识点

---

- 补充知识：
	- `javaweb`的整体流程中，`response/request`只有一个,所有的流程都是对找一个进行操作，通过不断的处理执行
	- `response`不一定是执行完所有流程后才提交，可以手动提交，可以默认提交
		- 手动提交：手动显示的调用方法提交
		- 默认提交：缓冲区已经满了或者执行完了`dispatcherservlet`的服务，到达`after`时基本已经提交了
	- 一旦提交`response`，其就已经被锁定了，无法修改，但是可以看，有`http`协议一点一点的发
	- 内部`springmvc执行流程`
		- `dispatcher找到对应的contorller，匹配对应的拦截器,将其封装成为一个链条，按执行顺序执行，同一个链条中的形参的对象一致`

- 多个匹配：
	- 拦截器：
		- 按链条挨个执行
	- 过滤器：
		- 按链条挨个执行
- 单个匹配：
	- `servlet`可能匹配进入`springmvc`中，可能进入其他的`servlet

- `servlet`匹配原则：

| 优先级 | 类型 | 写法示例 | 说明 |
| :---: | :--- | :--- | :--- |
| 1 | 精确匹配 | `/user/list` | 完全相等才匹配 |
| 2 | 最长路径匹配 | `/user/*` | 前缀匹配，选最长的那个 |
| 3 | 扩展名匹配 | `*.jsp`、`*.action` | 按后缀匹配 |
| 4 | 默认匹配 | `/` | 兜底，匹配所有未被前面匹配的请求 |

- `handler`匹配原则：

| 维度       | 对应注解                            | 说明            |
| :------- | :------------------------------ | :------------ |
| 路径       | `@GetMapping("/user")`          | URL 模式        |
| 请求方式     | `@GetMapping`、`@PostMapping`    | HTTP Method   |
| 请求参数     | `params = "keyword"`            | 请求必须包含或排除某些参数 |
| 请求头      | `headers = "X-Token"`           | 请求必须包含某些头     |
| Consumes | `consumes = "application/json"` | 请求体类型         |
| Produces | `produces = "application/json"` | 响应体类型         |

# 三.参数校验

## 3.1引入

---

- 对于前端传过来的数据，可以进行接收，然后调用`service`方法进行校验，但是太过繁琐
	- 使用`java提供的前端校验` ——》 `jsr-303`
		- 具体实现由`hibernate框架提供`,但是`springmvc`依然支持这一套注解
	- 使用一个实体类来接收前端数据，实体类中使用标签标记，传过来校验若是不符合，报错

- 常使用的注解：

| 注解                           | 说明                 | 适用类型                     |
| :--------------------------- | :----------------- | :----------------------- |
| `@NotNull`                   | 不能为 null           | 任意                       |

| `@NotBlank`                  | 非 null 且去空格后长度 > 0 | String                   |
| `@Size(min, max)`            | 长度范围               | String、Collection、Map、数组 |

| `@Min(value)`                | >= value           | 数值                       |

| `@Digits(integer, fraction)` | 整数位和小数位限制          | 数值、BigDecimal            |

- 类定义上定义数据格式内容：
```java
package com.atguigu.pojo;

import jakarta.validation.constraints.Email;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Past;
import org.hibernate.validator.constraints.Length;

import java.util.Date;

public class User {

    /*
    * 1.name 不为空和空字符串
    * 2.password长度大于6
    * 3.age >= 6
    * 4.email为邮件格式的字符串
    * 5.birthday过去时间
    * */

    private int id;
    /*
    * NotNull:包装类
    * NotBalnk：字符串类型
    * NotEmpty：集合类型
    * */
    @NotBlank
    private String name;
    @Length(min = 6, max = 20)
    private String password;
    @Min(1)
    private int age;
    @Email
    private String email;
    @Past
    private Date birthday;

    @Override
    public String toString() {
        return "User{" +
                "age=" + age +
                ", id=" + id +
                ", name='" + name + '\'' +
                '}';
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        this.age = age;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public int getId() {
        return id;
    }

    public void setId(int id) {
        this.id = id;
    }
}

```

- 接收实体类时，使用注解标记`@Validated`
	- 细节：
		- `param`:注解接收
		- `json`:为形参写一个注解`@RequestBody`，接收请求体内容
```java
@RequestMapping("register")
    public User register(@Validated @RequestBody User user) {
        System.out.println(user);
        return user;
    }
```

- 约定参数错误的处理机制 ——》 返回自定义返回结果
	- 错误信息绑定：
		- 1.`handler(校验对象,BindingRequest request)`
			- `bindignrequest 必须紧挨着校验对象`
		- 2.`bindingrequest`对象获取绑定错误
```java
 @RequestMapping("register")
    public Object register(@Validated @RequestBody User user, BindingResult bindingResult) {
        if(bindingResult.hasErrors()) {
            //若是有错误，不直接返回，自定义
            Map data=new HashMap();
            data.put ("code",400);
            data.put("msg","参数检验异常了！！！");
            return data;
        }
        System.out.println(user);
        return user;
    }
```
