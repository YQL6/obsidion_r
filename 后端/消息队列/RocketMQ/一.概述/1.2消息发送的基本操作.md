# 一.基本样例

## 1.1基本消息类型

---

- 消息发送:
	- 同步消息
	- 异步消息
	- 单向发送消息

- 消费消息:
	- 负载均衡模式消费消息
	- 广播模式消费消息

- 消息类型:
	- 顺序消息
	- 延时消息
	- 批量消息
	- 过滤消息
	- 事务消息

## 1.2准备工作

----

- 添加依赖:
	- `rocketmq的客户端`
		- 接收消息进行处理
- 通信流程:
	- 消息发送者:
		- 创建消息生产者`producer`，并指定生产者组名
		- 指定`nameserver`地址
		- 启动`producer`
			- 若是`broker`没有对应`topic`
				- 配置中开启了自动创建功能
				- 报错
		- 创建消息对象，指定消息整体`topic`,`tag`,`消息体`
		- 发送消息
		- 关闭发送者
	- 消息消费者:
		- `创建消费者consumer`,指定消费者组名 ——》 <mark style="background: #FFB8EBA6;">消费者组名决定消费者的分组</mark>
		- 指定`namerserver`地址
		- 订阅`topic和tag`
		- 设置回调函数，处理消息
		- 启动消费者`consumer`
```pom
	 <dependency>
            <groupId>org.apache.rocketmq</groupId>
            <artifactId>rocketmq-client</artifactId>
            <version>4.4.0</version>
        </dependency>
```

# 二.基本样例实操

## 2.1同步消息

---

- 大体流程
	- 消息发送者发送消息，进入阻塞状态
	- `broker`接收消息后，发送一个确认信息
	- 发送者收到确认信息，进入就绪状态
- 特点：
	- 可靠性较高

- 依赖:
```pom
     <dependency>
            <groupId>org.apache.rocketmq</groupId>
            <artifactId>rocketmq-client</artifactId>
            <version>4.4.0</version>
        </dependency>
        <dependency>
            <!--解决版本依赖的问题-->
            <groupId>io.netty</groupId>
            <artifactId>netty-all</artifactId>
            <version>4.1.97.Final</version> <!-- 或更高版本 -->
        </dependency>
```
- 主体代码:
```java
package com.atguigu.base.producer;

import org.apache.rocketmq.client.producer.DefaultMQProducer;
import org.apache.rocketmq.client.producer.SendResult;
import org.apache.rocketmq.client.producer.SendStatus;
import org.apache.rocketmq.common.message.Message;

import java.util.concurrent.TimeUnit;

/*
* 消费者使用同步的方式发送消息
* */
public class SyncProducer {
    public static void main(String[] args) throws Exception {
        //1.创建消息生产者对象，并指定生产者组名
        //使用默认的生产者类
        DefaultMQProducer producer = new DefaultMQProducer("syncProducer_group1");
        //2.指定Namerserver地址
        producer.setNamesrvAddr("192.168.179.101:9876;192.168.179.100:9876");
        //3.启动producer
        producer.start();
        //4.创建消息对象
        for(int i = 0 ; i < 10 ; i++){
            //具体创建消息对象
            /*
            * 创建时的具体参数:
            *   参数1：消息整体topic
            *   参数2：消息Tag
            *   消息3：消息内容
            * */
            Message message = new Message("base","TagA",("hell word" + i).getBytes());
            //5.发送消息，只有结果返回时才能继续向下执行
            //使用SendResult接收消息结果
            SendResult sendResult = producer.send(message);
            //消息发送结果的状态
            SendStatus sendStatus = sendResult.getSendStatus();
            //消息发送结果的消息id号
            String msgId = sendResult.getMsgId();
            //消息发送结果的队列的队列号
            //默认一个topic在一个broker上建立4个queue，每个broker上都是叫0,1,2,3,要配合broker_name显示
            int queueId = sendResult.getMessageQueue().getQueueId();

            System.out.println("状态为" + sendStatus);
            System.out.println( "消息id为" + msgId);
            System.out.println("接收消息的队列号为" + queueId);

            //每一次都睡一会，虚拟机性能较差
            TimeUnit.SECONDS.sleep(1);
        }
        //6.关闭生产者，释放资源
        producer.shutdown();
    }
}

```

## 2.2异步消息

---

- 大体流程:
	- 发送者发送，继续向下执行
	- 留一个回调函数，执行当收到发送消息的结果/回应时处理流程
- 特点:
	- 不阻塞，处理时间要求高

- 主体代码:
```java
package com.atguigu.base.producer;

import org.apache.rocketmq.client.producer.DefaultMQProducer;
import org.apache.rocketmq.client.producer.SendCallback;
import org.apache.rocketmq.client.producer.SendResult;
import org.apache.rocketmq.client.producer.SendStatus;
import org.apache.rocketmq.common.message.Message;

import java.util.concurrent.TimeUnit;

/*
 * 消费者使用同步的方式发送消息
 * */
public class AsyncProducer {
    public static void main(String[] args) throws Exception {
        //1.创建消息生产者对象，并指定生产者组名
        //使用默认的生产者类
        DefaultMQProducer producer = new DefaultMQProducer("syncProducer_group1");
        //2.指定Namerserver地址
        producer.setNamesrvAddr("192.168.179.101:9876;192.168.179.100:9876");
        //3.启动producer
        producer.start();
        //4.创建消息对象
        for(int i = 0 ; i < 10 ; i++){
            //具体创建消息对象
            /*
             * 创建时的具体参数:
             *   参数1：消息整体topic
             *   参数2：消息Tag
             *   消息3：消息内容
             * */
            Message message = new Message("base","TagA",("hell word" + i).getBytes());
            //5.发送消息，只有结果返回时才能继续向下执行
            //修改为异步发送消息,使用回调函数来进行处理结果，不能使用结果来进行接收了
            //使用SendResult接收消息结果
            producer.send(message, new SendCallback(){
                //使用匿名内部类来进行回调函数的功能重写

                /*
                * 结果异常:
                *   发送完，等待超时
                *   返回结果非OK
                * 异常执行函数
                * */
                public void onException(Throwable throwable) {
                    System.out.println(throwable.getMessage());
                }

                public void onSuccess(SendResult sendResult) {

                    System.out.println(sendResult);
                    //消息发送结果的状态
                    SendStatus sendStatus = sendResult.getSendStatus();
                    //消息发送结果的消息id号
                    String msgId = sendResult.getMsgId();
                    //消息发送结果的队列的队列号
                    //默认一个topic在一个broker上建立4个queue，每个broker上都是叫0,1,2,3,要配合broker_name显示
                    int queueId = sendResult.getMessageQueue().getQueueId();

                    System.out.println("状态为" + sendStatus);
                    System.out.println( "消息id为" + msgId);
                    System.out.println("接收消息的队列号为" + queueId);
                }
            });


            //每一次都睡一会，虚拟机性能较差
            TimeUnit.SECONDS.sleep(1);
        }
        //6.关闭生产者，释放资源
        //主线程可能执行过快，还没有发完就关闭了
        producer.shutdown();
    }
}

```

## 3.2广播和负载均衡模式

---

- 消费的形式:
	- 广播模式
		- 多个消费者组成一个消费者组，<mark style="background: #FFB86CA6;">由组内开启广播模式</mark>，一个线程执行对应的代码以后执行到开启广播，执行广播开启
		- <mark style="background: #FFF3A3A6;">同一个消费者组的处理程序相同</mark>
		- 各个消费者间<mark style="background: #FFB86CA6;">相互独立</mark>，<mark style="background: #FFF3A3A6;">各自的进度由自己保存`offset`</mark>
		- 若是失败，跳过执行
	- 负载均衡模式
		- 消费者可以启动多个，都可以消费消息，针对同一个`topic,top`，可以组成一个消费者组进行<mark style="background: #BBFABBA6;">均衡消费</mark>
		- 为了防止一个消息在同一个消费者<mark style="background: #BBFABBA6;">组内重复消费</mark>：
			- <mark style="background: #FFB86CA6;">同一个消费者组的同一个时刻</mark>，一个消费者只能消费一个消息
		- 通过`brower`进行均衡进度，<mark style="background: #FFF3A3A6;">`offset`保存在`brower`中</mark>
- 配置消息处理模式:
	- `consumer.setMessageModel(MessageModel.CLUSTERING)`:
		- 负载均衡模式
	- `consumer.setMessageModel(MessageModel.BROADCASTING):`
		- 广播模式
- <mark style="background: #ABF7F7A6;">默认使用的是负载均衡模式</mark>

- 主体代码:
```java
package com.atguigu.base.consumers;

import org.apache.rocketmq.client.consumer.DefaultMQPushConsumer;
import org.apache.rocketmq.client.consumer.listener.ConsumeConcurrentlyContext;
import org.apache.rocketmq.client.consumer.listener.ConsumeConcurrentlyStatus;
import org.apache.rocketmq.client.consumer.listener.MessageListenerConcurrently;
import org.apache.rocketmq.common.message.MessageExt;
import org.apache.rocketmq.common.protocol.heartbeat.MessageModel;

import java.beans.beancontext.BeanContextChild;
import java.util.List;
import java.util.concurrent.TimeUnit;

public class Consumer {
    //消费者
    public static void main(String[] args) throws Exception {
        //1.创建消费者，绑定消费者组 ——》 消费者组使用组名绑定
        //同一个消费者组下必须使用相同的订阅
        DefaultMQPushConsumer consumer = new DefaultMQPushConsumer("group1");
        //2.绑定消费者组的nameserver
        consumer.setNamesrvAddr("192.168.179.100:9876;192.168.179.101:9876");
        //3.订阅主体topic和tag
        consumer.subscribe("base", "TagA");

        //设置消费模式
        consumer.setMessageModel(MessageModel.BROADCASTING);
        consumer.setMessageModel(MessageModel.CLUSTERING);
        //4.设置回调函数，处理消息
        consumer.registerMessageListener(new MessageListenerConcurrently() {
            @Override
            /*
             * @Param list 拿到消息暂存的位置,直接从brower中批量拉取
             * @Param context 这一批消费过程中的环境
             *   从那个队伍中拉出来的
             *   消费失败的重试策略
             * */
            public ConsumeConcurrentlyStatus consumeMessage(List<MessageExt> list, ConsumeConcurrentlyContext consumeConcurrentlyContext) {
                //直接获得是消息体对应的byte数组
                System.out.println(list);
                for(MessageExt messageExt : list) {
                    System.out.println(new String(messageExt.getBody()));
                }
                //返回值：消费完以后返回的结果
                //
                return ConsumeConcurrentlyStatus.CONSUME_SUCCESS;
            }
        });
        //5.启动消费者
        consumer.start();
        // 🔥 6. 关键一步：让主线程一直活着！
        // 只要主线程不死，后台的消费线程就能一直拉取消息
        while (true) {
            TimeUnit.SECONDS.sleep(1);
        }
    }
}

```

## 3.3顺序消息

---

- 消费者消费消息和发送者发送顺序一致
	- `broker`:
	  ![[图片/Pasted image 20261101230309.png]]
		- 消费队列:先进先出
			- 消费者:
				- 从最先进入的消费
			- 生产者:
				- 消息放到队列中
		- <mark style="background: #ADCCFFA6;">消费队列多个</mark>，可能消息按<mark style="background: #D2B3FFA6;">不同顺序被放入不同的队列</mark>中，一个`broker`中的一个`topic`默认4个队列，通过轮询方式放入
	- 消费顺序:
		- 全局顺序的顺序一致，所有的消息都同步
			- 没必要
		- 局部模式:
			- 一个主体的消息保证序一致
			- 例如:一个订单信息的一致顺序
				- 张三:创建，付款，推送，完成      顺序
			- 解决:
				- 生产者:
					- 将一个主体的消息放到一个队列中 ——》 天生的先进先出
					- <mark style="background: #BBFABBA6;">手动指定消息放到一个`broker的一个队列中`</mark>
					- 必须要有<mark style="background: #BBFABBA6;">业务`id`</mark>,<mark style="background: #ADCCFFA6;">通过业务`id`知道那些是一个业务</mark>，是一个整体
				- 消费者:
					- 消费者天然的进行多线程消费，主线程不干活，开启多线程来对拉取的消息处理
					- 强制一个消费者拉队列到本地以后，强制让并发的线程针对队列单线程

- 消费者主体代码:
```java
import org.apache.rocketmq.client.producer.DefaultMQProducer;
import org.apache.rocketmq.client.producer.MessageQueueSelector;
import org.apache.rocketmq.client.producer.SendResult;
import org.apache.rocketmq.common.message.Message;
import org.apache.rocketmq.common.message.MessageQueue;

import java.util.List;

public class OrderProducer {
    public static void main(String[] args) throws Exception {
        DefaultMQProducer producer = new DefaultMQProducer("order_producer_group");
        producer.setNamesrvAddr("192.168.179.100:9876");
        producer.start();

        String orderId = "ORDER_999"; // 共同的业务标识
        String[] tags = {"Create", "Pay", "Deliver"};

        for (int i = 0; i < 3; i++) {
            Message msg = new Message("OrderTopic", tags[i], ("订单:" + orderId + " 状态:" + tags[i]).getBytes());

            SendResult sendResult = producer.send(
                /* [参数1] msg: 当前要发送的消息本体 */
                msg, 
                
                /* [参数2] selector: 路由选择器接口的匿名实现类 */
                new MessageQueueSelector() {
                    /**
                     * 核心方法：决定这条消息丢到哪个 Queue
                     * @param mqs  (系统提供) 当前 Topic 下所有可用的队列集合（比如包含 Q0, Q1, Q2, Q3）
                     * @param msg  (系统提供) 当前正在发送的消息本体
                     * @param arg  (你提供)  就是 send 方法的第三个参数，这里传的是 orderId,业务ID
                     * @return 返回选中的那一个 Queue 对象
                     */
                    @Override
                    public MessageQueue select(List<MessageQueue> mqs, Message msg, Object arg) {
                        String id = (String) arg; 
                        // 用订单ID哈希取模，保证同一个订单每次算出来的 index 永远一样
                        int index = Math.abs(id.hashCode()) % mqs.size();
                        return mqs.get(index); 
                    }
                }, 
                
                /* [参数3] arg: 业务参数（塞给上面 select 方法的 arg） */
                orderId 
            );

            System.out.println("发送成功落入: Q" + sendResult.getMessageQueue().getQueueId());
        }
        producer.shutdown();
    }
}
```

import org.apache.rocketmq.client.consumer.listener.ConsumeOrderlyContext;
import org.apache.rocketmq.client.consumer.listener.ConsumeOrderlyStatus;
import org.apache.rocketmq.client.consumer.listener.MessageListenerOrderly;
import org.apache.rocketmq.common.message.MessageExt;

import java.util.List;
import java.util.concurrent.TimeUnit;

public class OrderConsumer {
    public static void main(String[] args) throws Exception {
        // 1. 创建消费者，绑定消费者组
        DefaultMQPushConsumer consumer = new DefaultMQPushConsumer("order_consumer_group");
        // 2. 绑定 NameServer 地址
        consumer.setNamesrvAddr("192.168.179.100:9876;192.168.179.101:9876");
        // 3. 订阅 Topic（与生产者保持一致）
        consumer.subscribe("OrderTopic", "*");

        // 4. 注册【顺序】消息监听器 (注意这里不是Concurrently)
        consumer.registerMessageListener(new MessageListenerOrderly() {
            
            /**
             * @param msgs 拉取到的消息列表（同一批拉取下来的一定属于同一个 Queue）
             * @param context 上下文，包含当前队列的信息
             */
            @Override
            public ConsumeOrderlyStatus consumeMessage(List<MessageExt> msgs, ConsumeOrderlyContext context) {
                
                // 遍历处理这一批消息
                for (MessageExt msg : msgs) {
                    String body = new String(msg.getBody());
                    
                    // 打印当前线程名，验证是否是一个线程在按顺序处理同一个队列
                    System.out.println(Thread.currentThread().getName() + " 顺序消费: " + body);
                    
                    try {
                        // 模拟业务耗时（比如查库、写库）
                        TimeUnit.MILLISECONDS.sleep(100);
                    } catch (InterruptedException e) {
                        e.printStackTrace();
                    }
                }
                
                // 5. 返回消费状态
                // SUCCESS：处理成功，Broker会更新消费进度
                return ConsumeOrderlyStatus.SUCCESS; 
                
                // 如果业务抛出异常，需要返回：SUSPEND_CURRENT_QUEUE_A_MOMENT
                // 意思是：挂起当前队列，过一会儿再重试这批消息
            }
        });

        // 6. 启动消费者
        consumer.start();
        System.out.println("顺序消费者启动成功，正在等待消息...");

        // 7. 阻塞主线程，防止程序退出
        while (true) {
            TimeUnit.SECONDS.sleep(1);
        }
    }
}

	- `MessageListenerConcurrently`:

		- 并发的处理消息，异步的拉取消息

package com.atguigu.base.until;  
  
import org.apache.rocketmq.common.message.Message;  
  
import java.util.ArrayList;  
import java.util.Iterator;  
import java.util.List;  
import java.util.Map;  
  
/*  
* 工具类:  
*   进行消息的集合的切割的工具类，提供遍历切割方法  
*   一般消息不能大于4MB，所以对于集合发送消息要先进行切割消息的集合为几个小消息  
*   使用迭代器的接口来对集合遍历，切割为小消息  
* */  
  
public class MessageSplitter implements Iterator<List<Message>> {  
    //接收消息集合  
    private final List<Message> message;  
    //设置最大消息集合为多少  
    private final int MESSAGE_SIZE = 1024 * 1024 * 4;  
  
    //记录到底切割到哪里了  
    private int currentIndex = 0;  
  
    //构造器方法，对外接收消息集合  
    public MessageSplitter(List<Message> message){  
        this.message = message;  
    }  
  
    //切割方法独立为一个方法  
    public List<Message> Split(List<Message> message,int start, int end){  
        List<Message> newMessage = new ArrayList<Message>(message.subList(start, end));  
        return newMessage;  
    }  
  
    //重写haseNext  
    @Override  
    public boolean hasNext() {  
        return currentIndex < message.size();  
    }  
  
    ////重写next方法  
    @Override  
    public List<Message> next() {  
        int nextIndex = currentIndex;  
        int totalSize = 0;  
  
        List<Message> end_msg = null;  
  
        //针对集合进行遍历  
        for(;nextIndex < message.size(); nextIndex++){  
            Message msg = message.get(nextIndex);  
            //估算消息大小  
            Map<String,String> map = msg.getProperties();   
int size = message.get(nextIndex).getBody().length + 20;  
            for(Map.Entry<String,String> entry : map.entrySet()){  
                size = entry.getKey().length() + entry.getValue().length();  
            }  
            //若是单挑消息就超过了上线，直接报错无法进行发送  
            if(size >= MESSAGE_SIZE){  
                throw new RuntimeException("这条消息太大了");  
            }  
            //若是加上这个消息超过了上线，从这个开始进行切割  
            if(size + totalSize > MESSAGE_SIZE){  
  
                break;  
            }else{  
                //统计大小  
                totalSize += size;  
            }  
  
        }  
        //进行按位置切割  
        end_msg = Split(message,currentIndex,nextIndex);  
        //更新遍历的位置  
        currentIndex = nextIndex;  
        return end_msg;  
    }  
}

## 3.7事务消息

---

- 生产者发送给`broker`后，若是生产者不进行消息提交，生产者不进行提交，消费者无法进行消费
	- 发送的消息:
		- 未提交以前:
			- 半消息
			- 消费者不可见
		- 回调:
			- 服务器查询生产者的组名然后发送到对应事务监听中调用对应的方法进行处理
	- 生产者:
		- 发送消息以后继续执行这个事务，事务执行以后再进行提交操作
			- `commit`:
				- 消息进行消费
			- `rollbake`:
				- 消息删除
			- 超时:
				- 会查，去回调方法，检查消息状态，到达消费者进行调用方法回查，进行恢复消息状态
	- 消息状态:
		- 提交状态
		- 回滚状态
		- 不知道：
			- 过一段时间再回调
		- 中间状态:进行回调操作：
			- 进行回调

- 消费者的主体代码:

            /*
            * 传入事务监听器，为提交事务提供入口
            * 当消息发送以后进行本地事务的操作，具体操作都放到这里面
            * 事务执行完以后是否进行提交看返回值

            /*

             *   消息3：消息内容

            Message message = new Message("TransactionTopic","TagA",("hell word" + i).getBytes());
            //5.发送消息，只有结果返回时才能继续向下执行

            SendResult sendResult = producer.send(message);

            TransactionSendResult transaction_r = producer.sendMessageInTransaction(message,"Order1");

            //消息发送结果的消息id号

            //消息发送结果的队列的队列号
